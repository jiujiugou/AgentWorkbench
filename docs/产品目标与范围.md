## 1. 是什么

**面向企业私有化部署的受控动作执行底座**：把「模型想做什么」变成「系统真的做了什么」，保证不越权、不重复执行、办错了能追回。对外交付「底座 + 一个动作域」的完整系统；制造业 ERP 是第一版装进去的域，不是产品本身。**底座不单独交付。**

方向收拢成一句，用于所有范围取舍：

> **不做「会聊 ERP 的 AI」，做「能让 AI 安全碰 ERP 的那一层」。**

两层必须同时说清：只说底座会读成卖框架，只说 ERP 动作会读成一套工单逻辑。

- **底座**（业务无关）：Runtime/Harness、编排、知识、记忆与状态、工程保障五层，加工具层的「管辖」半边。完全不认识业务。
- **动作域**（可替换）：企业应用层（身份、唯一 PDP、权限策略、字段映射、业务 API）+ 工具层「适配器」半边。承载全部业务语义。

底座**问，但不理解**，只有三个注入口：`PermissionQuery`（PDP 返回 allow/deny，底座不知道金额上限）、`ActionSpec`（参数对底座是**不透明 JSON**，只按 Schema 校验、原样透传）、`TraceEvent`（结构在底座，判据与题库由动作域注入）。

> **AC-01**：换一个动作域，底座五层 diff 为空。这是「底座是主体」唯一可验证的含义。

**模型只负责把自然语言翻成参数；难点全部在模型之外。** 入口是任务，不是聊天框。

## 2. 怎么知道没跑偏

三条方向判据：

1. 换一个动作域，底座五层 **diff 为空**（AC-01）。做不到 = 做的是 ERP 定制项目。
2. 任一动作能答：**谁让做的、什么时候、看到了什么、依据哪条规则、ERP 里变成了什么**。做不到 = 审计只是日志，不是证据。
3. **拿掉模型，系统还能安全地拒绝。** 做不到 = 安全性依赖模型行为，等于没有安全性。

四条边界：**不做平台、不做 RPA、不做第二个真实动作域、不做通用连接器**。

## 3. 第一版成功目标

> 在一个由外部设计的单据模型上，可靠执行 1 个只读动作 + 1 个带人工审批的写动作，不越权、不重复、能追回；同时证明这些保证没有被写死在底座里。

六句可检验的话（每条都能写出反例）：

1. 用 ERPNext 真实 API 查到单据状态，返回带 ERP 状态码与时间戳；查不到时明确说查不到（不是 mock）。
2. 建一张草稿采购单，**未审批时零外部调用**；拒绝与超时过期都不执行。
3. 同一 `request_id` 连打两次，ERP 侧只有一张单，第二次返回首次结果。
4. 模拟超时，系统记「执行中」并发起状态查询，**不重放调用**；查不到转人工。
5. 任取一笔执行，五个字段齐全，能回答「谁在什么时候让系统做了什么」。
6. 用字段、策略、题库都不同的**假第二动作集**跑通同一套运行时，底座五层 diff 为空（AC-01 演练）。

**不证明什么（比上面更重要）**：不证明有客户要、不证明业务口径对、不证明能对接任意 ERP、不证明底座能单独交付、不证明模型 tool calling 稳定、不证明平台化成立。**功能数量、测试覆盖率、绿灯数量、文档篇数一律不是成功标准。**

**反馈源**：v1 的教训是唯一稳定可得的反馈是绿灯，闭环退化成自己写需求、自己实现、自己验收。v3 换成「外部设计的单据模型不迁就我们」——堵得住绿灯自证，**堵不住「有没有人要」**。后者如实挂着，不因转正确认而消失。

第一版验证对象是 ERPNext 自托管实例的默认单据模型 + 一套可替换适配器，**没有真实客户**；开源 ERP 跑通 ≠ 真实客户可用。

## 4. 范围与路线

必须实现：动作契约三类型（`ActionSpec` / `ActionRequest` / `ActionResult`）；四道 fail-closed 网关按序 **schema 校验 → 权限判定 → 业务规则 → 审计留痕**，默认实现全部拒绝；四原语 `Query/Draft/Submit/Cancel`（Draft 与 Submit 拆开）；唯一 PDP + 权限四维；审计五字段（意图、参数、审批人、结果、外部单号）；幂等与去重；1 只读 + 1 写（强制人工审批，最小闭环 = 待办列表 + 同意/拒绝两个按钮，不做管理后台）；假 ERP 兼作 AC-01 验收装置。

红线：**底座五层不得出现业务概念（AC-02）**；写动作默认 `Ask` + fail-closed；**禁止自动重放带副作用的工具调用**；放弃 ≠ 容忍 fail-open 类缺陷。
