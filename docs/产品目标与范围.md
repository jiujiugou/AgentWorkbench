## 1. 是什么

**面向企业私有化部署的受控动作层**：让模型能安全地接入**任何一家企业已经在跑的业务体系**——把「模型想做什么」变成「他们的系统里真的做了什么」，保证不越权、不重复执行、办错了能追回。对外交付「底座 + 一个业务体系的接入」。**底座不单独交付。**

接入对象是**别人已经建好、正在运行、不会为我们改动的业务系统**，不是我们设计的数据模型，**也不限定是哪一家**。方向收拢成一句，用于所有范围取舍：

> **不做「会聊某个系统的 AI」，做「能让 AI 安全碰他们的系统的那一层」。**

**「接入」不是调通 API。** 要接的是四样东西，缺一样就只是脚本：

- **身份**：他们的账号体系，谁在操作由谁说了算
- **权限**：他们的角色、审批链、金额档位，唯一的判定点在接入层
- **数据模型**：他们的字段、编码、状态机，我们不改也不翻译成自己的
- **业务流程**：他们的单据规则与前置条件，规则变了我们跟着变

两层必须同时说清：只说底座会读成卖框架，只说接入会读成一套定制脚本。

- **底座**（业务无关）：Runtime/Harness、编排、知识、记忆与状态、工程保障五层，加工具层的「管辖」半边。完全不认识被接入的系统。
- **接入层**（可替换）：企业应用层（身份、唯一 PDP、权限策略、字段映射、业务 API）+ 工具层「适配器」半边。承载全部被接入系统的语义。

底座**问，但不理解**，只有三个注入口：`PermissionQuery`（PDP 返回 allow/deny，底座不知道金额上限）、`ActionSpec`（参数对底座是**不透明 JSON**，只按 Schema 校验、原样透传）、`TraceEvent`（结构在底座，判据与题库由接入层注入）。

上面那四样在底座侧只变现成这三个口：权限 → `PermissionQuery`；数据模型 → `ActionSpec`；业务流程与判据 → `TraceEvent`；身份由接入层供给，底座只当不透明字符串。**四样进来，三个口出去——这就是「底座问，但不理解」的具体形态。**

> **AC-01**：换一个被接入的系统，底座五层 diff 为空。这是「底座是主体」唯一可验证的含义。
>
> **AC-03**：被接入的系统**一行不改**。如果需要对方加字段、加接口、加幂等键，那不是接入，是改造，出范围。

**模型只负责把自然语言翻成参数；难点全部在模型之外。** 入口是任务，不是聊天框。

## 2. 怎么知道没跑偏

三条方向判据：

1. 换一个被接入的系统，底座五层 **diff 为空**（AC-01），且对方系统 **零改动**（AC-03）。做不到 = 做的是某套系统的定制项目。
2. 任一动作能答：**谁让做的、什么时候、看到了什么、依据哪条规则、那个系统里变成了什么**。做不到 = 审计只是日志，不是证据。
3. **拿掉模型，系统还能安全地拒绝。** 做不到 = 安全性依赖模型行为，等于没有安全性。

四条边界：**不做平台、不做 RPA、不做通用连接器、不改被接入的系统**。

**「不做通用连接器」必须说准，否则与「接任何业务体系」自相矛盾**：不提供「配置一下就能接」的免代码适配（那是 Zapier 那一类）。每接一个业务体系，都要写一套接入层——PDP、业务规则、字段映射、适配器。**这份成本不能省，省掉的就是业务语义。** 允许的是「换业务体系时底座 diff 为空」（AC-01），不是「换业务体系时什么都不用写」。通用连接器只能接 API 那一样；接不了权限、接不了流程、接不了审批链。

## 3. 第一版成功目标

> 在**任何一个**真实存在、不由我们设计、也不为我们改动的业务体系上，可靠执行 1 个只读动作 + 1 个带人工审批的写动作，不越权、不重复、能追回；同时证明这些保证没有被写死在底座里。

六句可检验的话（每条都能写出反例）：

1. 用该系统的**真实 API** 查到一条记录的状态，返回它自己的状态码与时间戳；查不到时明确说查不到（不是 mock）。
2. 建一条记录，**未审批时零外部调用**；拒绝与超时过期都不执行。
3. 同一 `request_id` 连打两次，对方系统侧只有一条记录，第二次返回首次结果。**不假设对方支持幂等键**——对方明确忽略时，靠「提交前本地领取 + 提交后按业务键查证」兜住，不重放。
4. 模拟超时，系统记「执行中」并发起状态查询，**不重放调用**；查不到转人工。
5. 任取一笔执行，五个字段齐全，能回答「谁在什么时候让系统做了什么」。
6. 换一个字段、策略、题库都不同的**第二个业务体系**（不是同一家的第二套接口）跑通同一套运行时，底座五层 diff 为空（AC-01 演练），且该系统同样一行没改。**这条是「任何」的唯一证据**——只有一家跑通，证明的是定制项目。

**不证明什么（比上面更重要）**：不证明有客户要、不证明业务口径对、**不证明任意一个业务体系都能接成**（只验证过一两个载体，真实代价要等第二个域才看得见）、不证明底座能单独交付、不证明模型 tool calling 稳定、不证明平台化成立。**功能数量、测试覆盖率、绿灯数量、文档篇数一律不是成功标准。**

**反馈源**：v1 的教训是唯一稳定可得的反馈是绿灯，闭环退化成自己写需求、自己实现、自己验收。v4 换成「**别人的系统不迁就我们**」——它不会为了配合我们而变得工整。这不是假设，已经实测到（2026-11-08，gitea.com 真实 HTTPS）：它**完全忽略 `Idempotency-Key`**（同一 payload 连发三次得到 #1/#2/#3 三张单）、`PATCH` 返回 **201** 而非 200、`DELETE` 返回 **204 且无 body**、时间戳是 RFC3339+`Z` 而 Frappe 返回无时区的站点本地串。这些约束外部给定，不能商量，也不能靠改对方来绕开。它堵得住绿灯自证，**堵不住「有没有人要」**；后者如实挂着，不因转正确认而消失。

第一版验证载体**没有真实客户**：把它跑通 ≠ 有客户能用。**放弃 ≠ 容忍 fail-open 类缺陷。**

## 4. 范围与路线

必须实现：动作契约三类型（`ActionSpec` / `ActionRequest` / `ActionResult`）；四道 fail-closed 网关按序 **schema 校验 → 权限判定 → 业务规则 → 审计留痕**，默认实现全部拒绝；四原语 `Query/Draft/Submit/Cancel`（Draft 与 Submit 拆开）；唯一 PDP + 权限四维；审计五字段（意图、参数、审批人、结果、外部单号）；**幂等与去重（不假设对方提供幂等能力）**；1 只读 + 1 写（强制人工审批，最小闭环 = 待办列表 + 同意/拒绝两个按钮，不做管理后台）；假系统兼作 AC-01 验收装置。

红线：**底座五层不得出现被接入系统的概念（AC-02）**；写动作默认 `Ask` + fail-closed；**禁止自动重放带副作用的工具调用**；**禁止要求被接入的系统为我们改动**；放弃 ≠ 容忍 fail-open 类缺陷。

已确认（2026-11-07）：**私有化部署 / 审批最小闭环 / M1–M3 不碰 Python 仓**。
已确认（2026-11-14）：**接入对象为任意既有业务体系，且不得要求对方改动**。

M2/M3 需要一个**验证载体**：一个真实存在、能立刻跑起来的外部系统，用来证明「接一个业务体系时底座不动」。当前选 **Gitea**——唯一做过真实行为采集并真连过的；ERPNext 是第二候选（有只读适配器但**从未真连**）。**载体不是产品边界**：换成任何别的业务体系，走的都是同一条路——写一套 PDP + 规则 + 字段映射 + 适配器，底座一行不改。**跑不起来的真连等于没有真连**，这是选载体唯一的硬标准。

前提剩余：分页形态、字段漂移方式、超时表现待实测（均属 M2/M3，不阻塞 M1）。
部署：私有化、C# 主服务是唯一对外入口 / 状态持有者 / PDP，Python 侧为无状态能力进程（ADR 0013）。
