# 运行期完整流程（主干十步）

- **适用侧**：公共 ｜ **寿命**：现状 ｜ **最后校准**：2026-11-09
- **回答**：一次 run 的主干顺序与失败走向；每一步做什么、留下什么、出错时怎样
- **不回答**：实现细节（模块 README）、当前完成度（测试红绿）、执行计划（`plans/`）

**这份流程是契约坐标，不是任务清单，也不是完成度清单。** 每一步按**自上而下**四段读：
`步骤` → `步骤功能` → `阶段产物` → `异常处理`。四段写的是「这一步必须成立的条件」，
不是「现在已经做到了什么」——是否满足由测试红绿证明，本文不维护状态、不列缺口、不排顺序。
它存在的意义是给产品侧一个立足点：新问题来了有格子可归，底座与应用有位置可补。

## 怎么用这份流程

- 每步一个**稳定 key**（`S01`–`S10`）。测试注释、其它文档、讨论一律指 key，不指「第几步」、
  不指章节号、不指代码行号。改一步等于改一个决策，改完只动文件头那一行「最后校准」。
- **归属写在「步骤功能」开头**：`**Host**` / `**Core**` / `**域**`。换动作域时逐格看这一项，
  标 `Core` 的步骤，`src/Core` 与 `docs/core/` 的 diff 必须为空
  （AC-01 / [README.md](README.md) §2 的 AC-01-doc）；标 `域` 的才允许变。
- 新发现的问题，先判**它属于哪一步的哪一段**。归得进去 → 补那一段的契约或补实现，
  不单独开新文档；归不进去 → 说明流程本身漏了一步，那才改本文。
- **缺口状态不进本文**：红的测试就是缺口，修好自然转绿。补不了、需要记录过程的，
  进 `docs/plans/` 只追加，不在这里开「连锁问题」小节。
- 文档写法只在 [README.md](README.md) §6 定义一次。链怎么跑见
  [core/runtime.md](core/runtime.md)（v1 知识问答）与 [core/tools.md](core/tools.md)（v3 受控动作链）。

## 主干十步

### S01 · 你输入一句话

- **步骤功能**：**Host**（前端 `ChatView`）把一次输入（文本 + 会话 + 本次输入编号）送进 SignalR
  `Send` / `Ask`；`clientMessageId` 在点击时生成，一次输入内不变。
- **阶段产物**：一条进入入口契约的 `ChatRequest`，编号必带。**引入重放的前置条件**：调用方必须
  复用同一次输入的编号，且 Hub 必须先建输入级去重（键只能取认证主体 + 编号——此刻
  `conversationId` 尚未确定）；否则同一输入会跑两次 run：`action_idempotency` 只护动作，不护 run。
  条件不成立时不得开启重放。
- **异常处理**：输入为空 / 本连接正在生成 / 连接调用失败 → **不进后续**（本地可见，不产生终态）；
  缺编号属协议违规，由 S02 拒。

### S02 · Hub：验身份、取会话

- **步骤功能**：**Host**（`AgentHub`）。本步起于一次 `Send` / `Ask` 调用，止于 `StreamAsync` 之前；
  探活与界面 user 消息写入也归本格。四件事各有可观察结果：
  ① 认证主体——归属 `(tenantId, userId)` **只取认证声明**，不取请求体；未认证不得进入本步；
  ② 取/建会话——以归属为条件复用或新建，`sessionId` 必须属于当前主体；
  ③ 连接级防抖——同一连接已有 run 时**拒绝且不排队**；
  ④ 输入身份必填——缺 `clientMessageId` 即拒绝。
  会话互斥的不变量由 **Core** 的 `ISessionRunGate` 强制（落点在 Harness 两入口，**不在 Hub**）。
- **阶段产物**（三项都必须可观察）：
  ① `sessionId` = 经归属校验后的真实会话 id，且作为后续 `HarnessRunRequest` 的会话键；
  ② `subject` = 认证声明里的主体名（`Identity.Name`），非空；
  ③ 身份作用域**覆盖整段 run**：起点在会话确定之后（`conversationId` 是派生请求号的输入、
     不能用客户端传来的那个），终点在 run 结束之后；作用域内 `IActionOriginProvider` 三元组
     恒非空，结束后还原。
- **异常处理**（按时间点分三类，**后果不共用**）：
  - **入口前拒绝**（未登录 / 缺输入编号 / 同连接已有生成）→ **不进后续**，零副作用：
    不探活、不建会话、不落消息、不建作用域、不起 run。
  - **探活失败**（模型未配置）→ **不进后续**，但**探活本身已发生**；此后零副作用。
  - **连接中途断开** → **明确终态** `cancelled`：已发生的会话、user 消息与轨迹保留，
    补发终态、保存已有部分答复；撤销已发生的副作用不是本步行为。

### S03 · Harness 组上下文

- **步骤功能**：**Core**（Harness 编排 / Session 历史 / Context 注入）抢会话闸、装配模型端点、
  工具白名单、历史 provider、指令注入。
- **阶段产物**：一次带完整历史与能力清单的模型调用；**同一 `sessionId` 同时最多一个 run**。
- **异常处理**：本步无独立拒绝路径；探活失败发生在 S02，不进本步、不落轨迹。进入本步后
  模型不可用则由 Harness 落明确终态，轨迹照落。

### S04 · 模型决策

- **步骤功能**：**Core**（工具环 `Runtime.Tools`）接模型输出，回普通文本或发 Tool Call；
  模型服务由组合根解析。
- **阶段产物**：一个落在白名单内的工具调用，或直接到 S10 的纯文本。
- **异常处理**：本步无独立拒绝路径；工具不在白名单时，模型既看不到也调不动。

### S05 · `propose_action` 填成一张单子

- **步骤功能**：**Host** 提供输入身份；**Core**（`Tools.Builtin`）把动作名 + 参数变成
  `ActionRequest`：校验 `subject`、参数必须是合法 JSON 对象、派生 `requestId`；参数对底座不透明。
- **阶段产物**：一个身份与请求号都齐全的结构化请求，交给网关。
- **异常处理**：无身份 / 非法 JSON → `rejected`，**不进网关**。

### S06 · 四道闸门

- **步骤功能**：**Core**（`ActionGateway`）按 Schema → Permission → BusinessRule → Audit 严格按序判定；
  规则与权限的**内容**由 **域** 注入，`RiskLevel` 不参与决策。
- **阶段产物**：判定通过、且**每道判定都成功落痕**的请求。
- **异常处理**：任一道 deny → `Rejected`（HTTP 422），**executor 零调用**；审计写失败同样拒绝。

### S07 · 审批：挂起 or 直接放行

- **步骤功能**：**Core**（`ActionRunService`）按 **域** 的 `ActionSpec.RequiresApproval` 分流；
  需审批则挂起 checkpoint 并返回 `Pending`。
- **阶段产物**：可执行的请求快照 + **审批当时仍然有效**的判定。
- **异常处理**：人工拒绝 → 明确终态且零外部调用；审批超时 → 终态或保持挂起。

### S08 · 执行：幂等 → 连接器 → 外部

- **步骤功能**：**Core** 编排幂等领取 → **域** 的连接器执行 → 写回结果。
- **阶段产物**：一个确定的终态结果（含外部单号），供模型回传与审计回放。
- **异常处理**：超时 / 状态未知 / 重复 → **只查证，不重放**；已有结果直接回放。

### S09 · 结果回传模型

- **步骤功能**：**Core**（`Runtime.Loop` + `Runtime.Tools`）在工具环内回灌工具结果；
  迭代上限 6、连续同调用 3 次判循环。
- **阶段产物**：模型的最终文本答复，或一个明确终态。
- **异常处理**：迭代超限 / 重复调用 / 预算耗尽 → 强制收口，状态带归类码。

### S10 · 流式输出 + 落库

- **步骤功能**：**Host** 增量推回前端、写界面正文；**Core** 分别落模型历史、模型轨迹、动作审计。
- **阶段产物**：一次可回放的 run：终态 + 归类码 + 轨迹。
- **异常处理**：审计写失败 → **不算成功**，fail-closed。

## 跨步约束

主干十步能跑，出问题的一直是**交接处**。两条不专属任何一步、但每一步都要守的：

- **身份贯穿**：`clientMessageId`（S01 生成）→ `sessionId` + `subject`（S02 确定）→ `requestId`
  （S05 派生）→ 幂等键（S08 领取）。任何一步把身份做成可缺省，下游判重就失效。
- **零调用优先于办成**：S05 / S06 / S07 的拒绝路径都必须保持「外部系统什么都没发生」，
  这与 S08 的「只查证不重放」是同一条承诺的两端。
