# 2026-11-18 · 三条主线的落地概念

- **适用侧**：公共
- **要证明什么**：Agents / Workflows / Harness 能在 AgentWorkbench 里各自指到具体落点、说出边界、并用负控证明；三条不是并列模块，而是一次 run 的三种决定权
- **不做哪些**：不引入 MAF 的图工作流运行时；不引入 Harness 的待办/压缩/文件访问/后台代理；不改四道闸顺序、不改 MCP 直调边界、不动 `Domains/*`；不碰工作区里已有的未提交改动
- **步骤**：
  1. 用归位三问定概念与边界（产物：`docs/三条主线落地概念.md`）
  2. 按代码核实每条主线的落点与空缺，写成本记录
  3. 在 `docs/README.md` 登记新文档
  4. 跑文档门禁与引用校验，把结果回填本记录
- **决策日志**：
  - 2026-11-18 · 三条主线按「决定权」而不是「模块」切：Agents 决定模型能看见/能选什么，Workflows 决定什么条件走到下一步，Harness 决定谁装配谁收口。理由：正本的三条判据（拿掉模型还能拒绝 / 五字段可回答 / 换域底座 diff 为空）分别落在三种决定权上，按模块切会把它切碎。
  - 2026-11-18 · Workflows **不照抄 MAF 的图运行时**。理由：本项目的跨步不变量（身份链、四道闸顺序、审批快照、禁止重放）不是节点内部约束；图引擎的超步检查点也不落在「审批挂起」「外部结果未决」这两个真正需要活过重启的位置。工作流的定义用现成的 `S01`–`S10` 十步契约，不另造 DSL。
  - 2026-11-18 · 仓内 `Workflow*Record` 是台账不是运行时：grep 只命中记录定义与 EF 映射，没有任何运行时服务引用。它不能当起点；先有状态机，再让表跟着状态机长。
  - 2026-11-18 · Harness 只保留「单次 run 的组合根 + 收口器」。MAF Harness 的规划/压缩/文件访问/后台代理不引入：扩大副作用面，且压缩与自动记忆注入走上下文提供程序管道会绕过工具环守卫（`docs/core/状态与记忆.md` 已记录冲突）。
  - 2026-11-18 · 归位冲突时的优先级：三问都命中 → 放 Workflows。因为「装得更好」不能替「该不该走」做决定。
  - 2026-11-18 · 文档分两份：`docs/` 下那份只写判断/边界/为什么；本文件放代码落点、实施顺序与验证命令。理由：`AGENTS.md` §4 要求正式文档不写类名与调用链。
