# 2026-11-09 · 翻译管道、身份委托与审计落库

- **适用侧**：底座
- **要证明什么**：模型只能填单不能执行；拔掉模型照样拒绝；审计与终态重启不丢；并发同请求号只一次副作用
- **不做哪些**：不接 MCP、不改四道顺序与失败默认、不动 `Domains/*`、不做前端审批页、不重建已删的正本
- **步骤**：
  1. `Core.Ports` 加只读身份端口，Host 用 AsyncLocal 作用域实现，Hub 与 Controller 共用
  2. `Tools.Builtin` 加一个 `propose_action` 工具；组合根注册、白名单加名
  3. `Foundation/Persistence` 加 SQLite 的 run / 终态 / 幂等 / 轨迹实现，DDL 与迁移共用一份
  4. 组合根按 `Actions:Store` 切换存储；默认落库
  5. 补验收测试 + 负控变异自证
- **决策日志**：
  - 2026-11-09 · 翻译机制放 Core（`Tools.Builtin`），**存储介质实现放 `Foundation/Persistence`**：那里已有 `IDbConnectionFactory` 与 Dapper，且不新增 NuGet 包（本会话 restore 坏）。机制与介质是两回事，换项目不用重写机制。
  - 2026-11-09 · 身份不放进工具参数，也不做成工具参数默认值：只从端口读，读不到就拒绝，避免「模型在单子上写申请人=老板」。
  - 2026-11-09 · 并发同 `requestId` 的领取失败分支保留既有语义（返回已落库结果），不改 `ActionRunService`；是否加回放标记单独裁决。
- **验证命令与结果**：
  - `dotnet build AgentWorkbench.slnx --no-restore` → 0 错误
  - `dotnet test ... --no-restore` → 140 条 / 130 绿 / 10 红（10 红全是 M0 既有预期红，一条未变）
  - 负控 5 项（身份仿冒、畸形 JSON 放行、幂等恒真、审计失败放行、清单不来自注入）→ 全部变红，已还原
  - 短时启动宿主（临时库）→ `Application started`、M030 执行、四张 `action_*` 表建成、端口无残留
- **结论**：达成。遗留见 [`docs/core/tools.md`](../core/tools.md) §7。
