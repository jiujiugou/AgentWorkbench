# 阶段 2 · 审批轴正交化

> **状态：未开始**
> **依赖：阶段 1 完成**（Hub 已是 harness 流，审批事件才有管道可走）

## 目标

补上 Codex 正交两维里的**第二维**：工具审批（auto / ask / deny）。

能力边界（能不能用）× 审批级别（什么时候问人）**必须是两个独立维度**，
Codex 官方明确说这两层不能混。

## 现状证据

- `grep -i "approval|Approve|审批|ask.*human|HumanInLoop"` 在 `src/` **零命中**。
- `src/AgentWorkbench.Safety/ToolPolicy.cs` 只是**能力白名单**（第一维）。
- `src/AgentWorkbench.AgentLoop/AgentRunGuard.cs` 是**预算/循环控制**，不是审批。
- 结论：第二维**不是没做好，是从来没建**。

## 为什么排第三（在并路之后、砍伐之前）

- 排在阶段 1 之后：审批需要一条能向前端「要一次确认」的流式管道，`AgentHub` 已接 harness 才有。
- 排在阶段 3/4 之前：审批是**安全语义**，必须在砍伐大动作前定型，否则砍完再补等于重写。
- 阶段 0 已把 `ToolPolicy` 改成 `IOptionsMonitor` 热重载——审批配置**天然复用这条链路**，
  改配置下个 run 生效，这条是本阶段几乎白拿的收益。

## 改动清单

### 1. `src/AgentWorkbench.Safety`（新增契约）

```
IToolApprovalPolicy
  ApprovalMode Decision(string toolName)   // Auto | Ask | Deny
ToolApprovalPolicy : IToolApprovalPolicy
ToolApprovalOptions                          // 配置模型
  Default: Auto
  Overrides: { "shell": Deny, "search_knowledge": Auto, ... }
```

- 契约与 `IToolPolicy` **并列，不合并**——合并就等于把两个维度又揉回一个。
- 住进 `appsettings.json` 的 `Harness:Tools` 节旁边（复用 `IOptionsMonitor`）。

### 2. `src/AgentWorkbench.ToolExecution/ToolExecutionPipeline.cs`

- 工具执行前过审批：`Auto` 直行、`Deny` 直接返回拒绝结果、`Ask` 挂起等人工。
- `Ask` 的实现：通过流式事件向前端发 `ApprovalRequested`，等 `ApprovalResponse`（带超时，超时即拒绝）。
- **负控语义要明确**：超时 / 连接断开 / 无应答 → 一律 **Deny**（fail-closed，不是 fail-open）。

### 3. Webapi / 前端

- `AgentHub` 增加 `ApprovalRequested` / `ApprovalResponse` 两个事件。
- 前端确认对话框：**可以后置**——阶段 2 先落服务端，前端默认全 `Auto`，等有了真实 `Ask` 工具再接 UI。

## 验证判据（全部为单测正负控成对）

| 模式 | 正例 | 负控 |
|---|---|---|
| `Auto` | 直接执行，轨迹有一条 | —— |
| `Deny` | 返回拒绝，工具**未真正执行** | 若仍执行必须红 |
| `Ask` + 批准 | 批准后执行，轨迹有审批记录 | —— |
| `Ask` + 拒绝 | 未执行 | 若执行必须红 |
| `Ask` + 无应答/超时 | 未执行（fail-closed） | 若执行必须红 |

## 回退方式

- 新增文件直接删；`ToolExecutionPipeline` 的审批分支用开关（`ApprovalOptions.Enabled=false`）短路回现状。

## 预算收紧（阶段收尾时执行）

- 若 `Safety` 项目因此膨胀，考虑把审批契约并入 `ToolExecution`（与阶段 4 的 Safety 瘦身合并做）。
- 其余预算不动。

## 设计红线

- **绝不**把审批塞进 `ToolPolicy` 或 `AgentRunGuard`——那是把刚拆开的两个维度又粘回去。
- **绝不**默认 `Ask`。默认 `Auto`，逐个工具显式提升。否则用户第一次用就被弹窗淹没。
