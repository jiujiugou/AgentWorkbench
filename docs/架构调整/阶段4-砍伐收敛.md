## 二、未执行项（按原文无法安全执行，附证据）

### 未执行 1：`Workflow`「删掉整个后台执行模型」

原文前置条件：**「确认前端没有工作流页面在真实使用」**。

实测：**该条件为假**，因此这一刀不改。

- `web/src/router/index.ts` 有 `/workflow` 与 `/workflow/:id` 两条路由；
  `web/src/App.vue` 顶部导航有「工作流」一项（与对话/文档/知识库并列）。
- `web/src/views/WorkflowDetailView.vue` 在用**取消**（L117）、**恢复**（L124）、**重跑步骤**（L110），
  并挂了 SignalR 进度通道 + 轮询兜底（L94）。
- 取消语义**只**能靠那个后台队列实现：`WorkflowService._cancellations` 字典的作用，
  就是让「另一个 HTTP 请求」能取消「正在后台跑的 run」。改成请求内同步执行后：
  - 创建接口会阻塞到整个工作流跑完（步骤超时上限 120s）→ 客户端/代理超时即 UI 显示失败而库里是成功；
  - `Cancel` 变成永远返回 false → 详情页「取消」按钮失效；
  - 刷新页面 = 取消这次 run（请求 token 就是工作流 token）。

**结论：这不是「砍掉冗余」，是砍掉一个正在用的功能。** 且该模块零测试覆盖，砍坏了没有红绿灯兜底。
需要先补测试再谈。

### 未执行 2：`Memory`「内存实现移测试」

原文判据：**「进程内实现若只有测试在用 → 移进 tests 做 test double」**。

实测：**它不是「只有测试在用」。**

- `SessionStore`（内存版）由 `AddNitroMemory` **正式注册**为 `ISessionStore`，
  随后被 `AddNitroMemoryPersistence` 用 `services.Replace(...)` 换成 SQLite 版。
  也就是说它是**「不装落库模块时的默认实现」**，不是死代码 —— 是配置驱动的模块组合的正常形态。
- 它有真实测试：`tests/AgentWorkbench.UnitTests/Memory/SessionStoreTests.cs`（TTL / LRU 淘汰）。
- 移进 `tests/` 的代价：`SessionStore` 同时被 **UnitTests 与 EvaluationTests 两个工程**消费
  （`HarnessUnderTest` 直接 `new SessionStore(...)`），要移动就必须在两个测试工程里各复制一份，
  或为此新增一个共享测试工程 —— **净增复杂度**，与「简单高效」相反。

**结论：这一条省的是 ~110 行，赔的是跨工程重复或一个新增工程。** 不做。

### 关于 `ChatService` / `RagService`（死代码清理项的收尾）

- `RagService` → `KnowledgeController` 的 `/api/knowledge/retrieve`（**前端在用**）与 `/ask`。
- `ChatService` → `RagService.StreamAnswerAsync` + `HealthController` 的模型就绪探活。

### 为什么到不了 15 / 7000

1. **文档的账本身不平。** 它的「起点盘点」只列了 9 个模块（实际 20 个），
   而它给出的唯一项目删除项只有 `Context` 与 `Safety` 两个 → 得到的是 **18**，不是 15。
2. **再往下砍，砍到的是承重墙。** 剩下的可减项只有三类：
   - 契约模块与实现模块的分体（`Knowledge.Abstractions` ↔ `Knowledge.Local`、
     `Memory` ↔ `Memory.Persistence`、`Observability` 与 `Domain/Observability` 记录）——
     合并会把「编排层只依赖契约、不依赖数据层」这条**刻意保留的边界**拆掉；
   - 有真实前端消费者的 `Workflow`（999+ 行）与 `Knowledge.Local`（1000+ 行）；
   - `Documents` / `Webapi` 的 HTTP 面（前端在读）。
3. **7000 行这个数，只有砍掉 `Knowledge.Local` 或 `Workflow` 才够。** 两个都不能砍（见上）。
   剩下的差距不是「还有肥肉没发现」，是**目标值与起点盘点的口径不一致**。

> 结论：本阶段把「能砍的都砍了」，并用预算棘轮锁住；差额需要产品决策，不是工程决策。
