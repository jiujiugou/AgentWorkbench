# 三条主线的落地概念

- **适用侧**：公共 ｜ **寿命**：长期（方向或架构红线变时才改） ｜ **最后校准**：2026-11-18
- **回答**：Agents / Workflows / Harness 在本项目各是一种什么决定权、边界在哪、怎么算落实
- **不回答**：有哪些模块、哪个类在哪、谁调用谁（查代码）；MAF 原文讲了什么（查官方文档）；逐格判据（查 `Sxx` 测试）

## 1. 一句话定义：三种决定权

三条主线不是三个模块，是**一次 run 里的三种决定权**。

| 主线 | 决定什么 | 不决定什么 | 落实的证据形态 |
| --- | --- | --- | --- |
| Agents | 模型能看见什么、能选什么；输出只是**提案** | 不执行动作、不取身份、不决定审批 | 换模型/provider 不动业务代码；白名单外工具不出现在清单里；模型既无文本也无调用时不算成功 |
| Workflows | 什么条件下走进下一步、谁能推进、挂起后怎么续 | 不由模型决定迁移；不自动重放带副作用的调用 | 未审批零外部调用；同一请求号只一次外部效果；超时只查证；断开有明确终态 |
| Harness | 谁来装配一次 run、谁来收口、结束时留什么证据 | 不承载业务语义；不做规划/文件访问/后台委派 | 同一会话同时只有一个 run；四态归类分得开；换域时底座 diff 为空；终态与轨迹齐全 |

这个切分从正本的三条判据直接推出：
「拿掉模型还能安全拒绝」→ Agents 只能处在提案位；
「任一动作能回答谁/何时/看到什么/依据哪条规则/变成什么」→ Workflows 必须把审批与审计做成路径上的必经节点；
「换域底座 diff 为空」→ Harness 只能是装配器，不能长业务语义。

## 2. 归位三问：新需求往哪条线放

按顺序问，第一句命中即归位：

1. 它改变的是**模型能看见或能选择的东西**吗（工具清单、指令、历史、输出解析）？→ Agents。
2. 它改变的是**什么条件进入下一步、下一步是谁、挂起怎么续**吗？→ Workflows。
3. 它改变的是**谁把这些装起来、跑完留下什么**吗？→ Harness。

三句都不命中 → 业务语义，属接入层/域，不进底座（AC-01、AC-02）。
三句都命中 → **优先放 Workflows**，因为它必须能独立拦住 Agents 的提案；让「装得更好」去替「该不该走」做决定，就是把安全塞进模型行为。

## 3. 与 MAF 原文的三处刻意分歧

照抄 MAF 会把本项目已有的约束拆掉，这三处必须显式记住：

**Agents：不停在「调用工具」，停在「提出动作」。**
MAF 把函数工具、MCP 工具、托管工具都放在 Agent 一侧，模型直调是常态。本项目的工具目录和调用机制在这一侧，但动作的判定、审批、幂等在 Workflows 一侧。分界不可移动：工具能被模型看见 ≠ 工具能被模型执行。

**Workflows：不引入通用图引擎，用主干十步当工作流定义。**
MAF 的工作流是执行器/边/事件/超步检查点的图运行时。本项目真正要管的是跨步不变量——身份链、四道闸顺序、审批快照、禁止重放——它们都不是节点内部的事；通用图的节点边界和超步检查点不落在审批挂起、外部结果未决这些真正需要「停住并活过重启」的位置上。因此工作流的定义就是 [运行期流程](host/运行期流程.md) 的 `S01`–`S10`：把每一步的交接对象写实，把三种失败走向（不进后续 / 明确终态 / 只查证不重放）做成一等状态，只在审批挂起与外部结果未决两处设检查点。
仓里已有的工作流台账表**不是**工作流的起点：它只是持久化载体，字段是否与十步的交接对象对齐还没证明。先有状态机，再让表跟着状态机长，反过来会做出一张永远没人写的表。

**Harness：是单次 run 的组合根，不是长任务代理。**
MAF 的 Harness 带规划、待办、压缩、文件访问、后台代理。本项目不要这包能力：它扩大副作用面，且压缩/自动记忆注入落在上下文提供程序管道里，会绕过工具环的守卫与轨迹——[状态与记忆](core/状态与记忆.md) 已记录这条冲突。要引入任一项，先改正本与架构红线，再谈实现。

## 4. 推广的判据：概念落实不等于功能存在

每条主线只有同时满足三件事才算落实：**有边界句**（上面表格的「不决定什么」）、**有落点**（能指到具体装配位置）、**有能变红的负控**。缺第一件的会膨胀，缺第二件的仍是口号，缺第三件的绿灯是自证。

归位三问和这三处分歧本身也要能变红：出现「模型侧做了权限判定」「工作流节点自己决定重放」「Harness 里出现某个业务系统的字段」，都应当有测试或门禁点名被违反的那条边，而不是只在文档里写禁止。

## 5. 这份概念不覆盖什么

不重新定义产品定位、六部件骨架、`S01`–`S10` 的编号，也不替代任何判据。它只回答一个此前没有答案的问题：**当一条新能力出现时，它属于哪条主线、由谁拦住、拿什么证明**。逐文件的落点、实施顺序与验证命令只在配套的[执行记录](plans/2026-11-18-三条主线落地概念.md)里维护，不在这里复制。
