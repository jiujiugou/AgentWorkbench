# 轨迹与观测（内核侧 · 六部件之⑥）

- **适用侧**：底座 ｜ **寿命**：现状（就近维护） ｜ **最后校准**：2026-11-23

> **类型**：Architecture（解释型）。本文解释「内核为什么必须自己产出这条记录、它长什么样、哪一步会丢」，不是事实源、不是参考手册。
> **范围**：边界归属、一条轨迹的生命周期形状、设计取舍、失败语义、验收判断、未决问题。
> **非范围**：表结构与迁移、落库实现、回放界面、保留期与报表——全属应用层。
> **可枚举部分不写在这里**：文件与符号定位、结局与归类码词表、表名列名、依赖版本、测试规模都在 `docs/kb/documents/trace.toml` 的 `evidence` / `fact` 段，由 `scripts/kb_check.py` 对账；本文只写机器判不了的判断。

一句话：**内核产出「事后无法从别处重建」的事实**——一次执行是什么结局、为什么、做了哪些动作、花了多少。
拿掉它，内核就说不清自己为什么停：提前终止被框架正常返回，从返回值和异常里都看不出来。

## 一、负责什么 / 不负责什么

判据只有一条：**事后能不能从别处重建？重建不了的，内核必须产出；重建得了的，应用层自己算。**

| 事 | 归属 |
|---|---|
| 一次 run 的终态 + 归类码（枚举值，不是人话） | 本格 |
| 停因的结构化依据：哪一类 / 观测到的值 / 阈值 / 对象 | 本格（判定归 ③，本格只搬） |
| 本次执行的用量：输入与输出两侧 token 数（不是进程累计） | 本格 |
| 步骤序列：迭代号 / 工具 / 参数 / 结果 / 异常 / 是否被截断 | 本格（采集归 ④，本格只存） |
| 每条结局都产出，并能声明「这条记录写没写全」 | 本格 |
| 终态怎么判、什么算停 | 外部（② / ③） |
| 每一步怎么采集 | 外部（④） |
| 模型这一轮看到了什么（指令 / 片段） | 外部（①，现为未闭合缺口） |
| 界面上的对话 | 应用层 |
| 落库：表结构、迁移、仓储实现 | 应用层 |
| 按 run 标识回放、按会话 / 终态检索 | 应用层 |
| 展示：执行过程面板、回放界面 | 应用层 |
| 保留期、归档、配额 | 应用层 |
| 报表：成功率、P95、工具失败率 | 应用层 |
| 业务审计：谁批的、外部系统里变成什么 | 应用层（动作域另记一套账） |

一个容易混的点：**内核「产出」记录，应用层「保存」记录。** 这两件事的边界不是文件位置，而是「谁定义字段」。

依赖断了谁兜着：② / ③ 不交终态，本格只能按异常兜底归类，「为什么」退化成猜；④ 不交采集结果，步骤序列整段缺失，只剩一条没有过程的结局；① 不交「模型看到了什么」，记录里有动作、没有依据；落库端口不在或写失败，记录根本不会进库，只留下一条 Warning。

## 二、机制形状

内核不产生终态，终态是 ② 判完交给它的——循环与预算由守卫判，异常归类由编排层判。一条轨迹从产生到写入是四段：

```
判定（终态 / 归类码 / 停因依据）
  → 组装（步骤序列 + 最终答复步 + 时长 + 用量 + 完整性）
  → 出口（唯一一次写，返回 run 标识）
  → 消费（应用层回放 / 检索；内核不再碰）
```

结局与归类码是两列，分工不能合并：**结局说「以什么状态结束」，归类码说「为什么」。** 同为超时，整轮超预算与单次模型请求超时的处理方式不同；同为失败，工具异常与模型不可用的重试价值也不同。稳定标识与词表见 `docs/kb/documents/trace.toml`，本文只写形状。

内核的观测该做到什么，只有三条要求：

**1. 一个数据形状，且每个字段都必须是「重建不了」的。** 能算出来的（工具调用次数、平均耗时、成功率）一个都不许进来——它们属于报表，进来就是双写。

**2. 完整性：每条结局都产出，并且能声明「完整 / 不完整」。** 「写了一半」比「没写」更危险：run 有了、步骤丢了，回放看到的是一半的真相却以为是全部。

**3. 内核只拿写口。** 出口只有 `写(记录) → 返回标识`，内核从不读自己的记录做决策。写口与读口已拆成两个接口：内核的构造只拿得到写口，读口只出现在宿主的只读端点——「内核不读」因此是编译期事实，不是注释约定。读到哪、怎么查、留多久，全在出口外面。

内核这一格做完没做完，不看功能列表，只问三句：

| 问题 | 现在能答吗 |
|---|---|
| 这次 run 是什么结局，**为什么**？ | **能**——结局 + 归类码；「为什么」带结构化依据（类别 / 观测值 / 阈值 / 对象），不解析中文 |
| 它做了哪些动作，分别结果如何？ | **能**——步骤序列有迭代号 / 工具 / 参数 / 结果 / 异常 / 是否被截断，且「失败」与「返回空」分得开 |
| **花了多少**？ | **能**——本次 run 的输入 / 输出 token 数进记录；供应商没上报记 null（不是 0） |

三问都答得了，只剩一处**答不全**：失败路径没有响应对象，取不到用量，记 null。想补只能在函数调用环外再包一层只读装饰器——那会绕过守卫与轨迹采集，所以宁可空着，也不拿进程累计冒充。

## 三、为什么这么定

只有这里几条是测试答不了的取舍；判据与负控在测试里，本文不复述。

**只存不算。** 判定分散到两处，同一件事会有两个结论；而且判定要读守卫与环的内部状态，本格拿不到。真要让本格参与判定，先把判定收成一份（现在在 ②）。

**失败 / 取消 / 超时也留痕，且不跟随调用方的取消。** 只在成功时留记录的系统，出事时恰恰什么都没有——最需要回放的那次正好是失败那次。取消是「按用户意愿停下」，不是「这件事没发生」，丢掉它就丢掉了用户主动停止的证据。

**超长必须截断；空答复不落成最终答复步。** 参数与结果都是外部输入，长度不可控，不截断会把表撑爆，也把无关文本拖进排障视野；完整答复另有出处（应用层的会话历史），上限可调、截断不可去掉。提前终止（循环 / 预算 / 拒答）时模型往往没有最终文本，落一条空的就分不清「答了个空」和「根本没答」；将来真要记「模型确实产出空串」，得另加字段，不能复用空值。

**不依赖存储与领域记录。** 观测模块只许引共享词表；引存储 / 领域 / 持久化框架一律不允许——否则内核为写一条记录，就把整个存储栈拖进编译期依赖。方向是持久化层实现本模块的契约，反过来就错了。

**加字段必须同时进记录结构、迁移与出口。** 只加结构不交出，等于内核产出了应用层收不到的事实；几处要在同一次提交里改完，就是为了不出现「字段有了、读回来是空」。另有一条反向边界：不把「模型看到了什么」塞进轨迹或会话历史——一轮 run 可能有多模型调用，塞进历史会把两个口径搅在一起，那是 ① 的字段。

**框架没有「一次 run 的记录」这个实体。** 框架给的是管道上的横切层（agent 级 / chat 级 / 工具级各有插入点）、span，以及挂在响应对象上的用量 / 结束原因 / 响应标识；导出走遥测或结构化日志。它的 "trace" 指分布式追踪，不是「一次执行的历史」——两个词在中文里都叫「轨迹」，这是混淆源头。于是分工断成两截：事实产生在响应对象上，观测导出在 span 与日志里，中间那截「把事实变成一条可重建的记录」没人管——这正是 ⑥ 存在的理由。框架版本与语义约定以 TOML 的 fact 段对账为准，升级后需重核（语义约定仍在演进）。

**没有一个成熟库能直接提供这个部件，可参照结构的也不建议引入。** 它不是通用设施，是领域模型：「什么算一次 run」「什么算停」「步骤怎么归属」「哪些字段必须留」都是领域判断，库只提供管道和零件，不定义语义。手边的持久化、结构化日志、重试、遥测解决的都是「怎么传、怎么写」，最关键的错配是形态——**一次 run 是个实体，日志是条流**，流表达不了终态，也答不了「这个 run 现在什么状态」（那在账本里是一列）。后台任务调度器、工作流引擎、事件溯源库、消息 saga 各有「一次执行」的账，但那是给调度器 / 编排器自己用的：schema 固定，没有会话、工具步骤、停因枚举这些维度。最接近的那一类要额外跑一个服务、并把整个编排换成它的执行模型——那不是补一个部件，是换掉运行时；事件库那条则要先换数据库。结论：结构参照「一次执行」这本账的形状，实现用自己的表，不引依赖。

**遥测替代不了账本，只补得上账本缺的那一角。** span 回答「系统健康吗、哪一步慢、钱花在哪」，读者是运维；记录回答「这一次执行是什么结局、为什么、做过哪些动作」，读者是排障、验收、追责。span 是树不是实体，按标识取不回一次完整执行，也没有「终态」这个概念，生命周期还是采样且短期。反过来它有一件账本补不上的事：单次工具调用耗时——记录里只有整条 run 的墙钟。接入遥测是加法，但有两条前提：它是装饰器形态（agent 级 / chat 级各一层），不触发 ① 那条「工具环外再包一层」的红线；本仓**未接入、未实测**，真接时要补「接入后循环判定与工具失败归类仍照常成立」的负控，并且遥测要落在工具环**内侧**，才既能发 chat span、又拿得到单步耗时。没验过就接，等于拿形态推断当结论——那正是 ① 当初付代价学到的教训。

## 四、配置口径

本格没有独立配置节：轨迹的形状是代码里的约定，不是可调参数。实际值不抄在这里——`docs/kb/documents/trace.toml` 登记依赖与规模，`scripts/kb_check.py` 对账；仓库是权威。

三条判断：

1. **步骤文本的上界不归本格。** 参数与结果的上界由 ④ 的工具执行配置给，本格把 ④ 的截断版和「是否截断」标志原样搬进记录——回放看到的是截断版，那是 ④ 的口径，不在这里再截一次。
2. **最终答复的上界是内核常量，不是配置项。** 它随写轨迹的代码走，改它是代码改动，不是部署改动——也就不会有某次部署悄悄去掉截断。
3. **不新增旋钮。** 留多久、归档到哪、一次查多少条，都在出口外面（应用层）；在这里再加一项，同一件事就有两个口径。

## 五、失败与恢复语义

本格的失败不在「判错」——本格不判；只在「没记」「记了半截」「记了但读不回」。

| 形态 | 记在哪 | 回填什么 | 谁能继续 |
|---|---|---|---|
| 没抢到会话票 | 这一次根本没有 run，没有记录 | 明说「未开始执行」 | 调用方；回放查不到是预期，不是丢账 |
| 准备阶段抛异常 | 已收进 `try`，落一条失败记录 | 归类码跟着分 | 调用方 |
| 中断（取消 / 超时） | 正在执行的那次调用没进步骤，标「不完整」 | 不假装全 | 应用层按「不完整」处理 |
| 落库本身失败 | 只有一条 Warning 日志，没有记录 | — | 没人；这条轨迹彻底没有 |
| 先写 run 再写步骤、两步不同事务 | 有 run 没步骤，看起来还正常 | 「完整」标志（还没接） | **未兜住**，见第六节 |

两条硬要求写在表外：

- 失败 / 取消 / 超时这几条路径**落库不跟随调用方的取消令牌**——调用方取消了，不代表这次 run 可以不记账。
- 写库失败**只记 Warning，不掩盖原始异常**，也不重试。

准备阶段曾经在 `try` 之外：只有「模型未配置」自己落了轨迹，其余路径直接冒泡、库里什么都没有——「无论成败都留一条轨迹」这句话，在准备阶段失败时曾经不成立。已修，并有用例钉住；配套代价是原来那段「自己落轨迹」必须删掉，否则准备失败会写两条。

## 六、怎么算验收通过

判定型用例必须**正例能绿、负控能红**；能脚本判定的禁止用 AI 判。测试文件名与条数会漂，本文不列，元数据里对账。

内核该验的三件事，按重要性排：

| 主张 | 守它的那一组 | 强度 |
|---|---|---|
| 停因能被机器读：同一个「判循环」能分别读出观测值与阈值，不靠解析中文 | 停因判据组 | 负控实测：把观测值写死成常量、或让观测值恰好等于阈值，必须红 |
| 用量能进记录：等于该次调用上报的用量，不是进程累计 | 用量判据组 | 负控实测：换成进程累计值，必须红 |
| 完整性可声明：中断能被识别为「不完整」 | 完整性判据组 | 负控实测：把中断态报成完整，必须红；步骤写失败那半未兜住 |
| 加字段必须同时进记录结构、迁移与出口 | 落库迁移对照 | 单条例外，不是存储实现的证明 |

**本格现在的强度**：判据验的是「交给存储的那条记录字段对不对」，**不是**「存储写对了」——落库往返属应用层，别读成「轨迹已端到端验证」。

**证据强度打折的地方，别当完整证明：**

- 有几条用例单独看恒真（例如「供应商没报用量记 null」——不实现读取路径时字段本来就是 null），必须与相邻那条一起读。
- 两条边界用例读的是源码字符串（「决策路径上没有出现读轨迹的调用」「观测模块只引了共享词表」），证明的是「没写出来」，不是运行期行为。
- 落库往返只有一条：它验的正是第三节那条「加字段必须同时进记录结构与出口」，属例外，不是存储实现的证明。

**落库侧的缺口（不在内核，但必须记）**：落库实现先插 run 再插步骤，两步不在一个事务；步骤写失败会留下「有 run 没步骤」且看起来正常。「完整」字段真正的用武之地在这里，还没接。

**明确不在本文范围的**（属应用层）：检索面有没有消费者、保留期、报表、表结构怎么设计。

## 七、未决问题

1. **「模型当时看到了什么」怎么进记录？** 一轮 run 可能有多模型调用；是每次调用一条，还是只留一份合成后的指令与片段快照？这是 ① 的字段，加进来要动记录形状与出口。
2. **「完整」标志在应用层怎么用？** 回放遇到不完整的记录，是拒绝展示、还是展示并标注？落库还不是原子的，这个标志的用法得与事务一起定。
3. **接入遥测后，判定还准吗？** 循环 / 工具失败的判定必须补负控，且遥测要落在工具环内侧，才拿得到单步耗时。

## 八、与其他五个部件

① 讲「模型每轮看到什么」——本格缺的正是这一维度，一轮 run 可能有多模型调用，那是 ① 的字段；② 讲「怎么从一轮走到下一轮」；③ 讲「允许走几轮、什么时候停」，并把终态与归类交给本格；④ 讲「一轮里的工具怎么执行」，采集在那里、落成步骤在这里；⑤ 讲「跨轮保住什么」，界面会话历史也在它那边，本格不重复存。一句话划界：判定在 ② / ③，采集在 ④，装配在 ①，保存、检索、呈现、保留期都在应用层，本格只做「产出那条不可重建的记录」。
