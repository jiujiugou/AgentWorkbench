# 测试分层职责（AgentWorkbench）

本文件定义各测试层与工程**唯一的职责**。判据不是「用哪个库」，而是**「隔离掉了什么」**。

---

## 一、五类职责

| 层 / 轨 | 承载工程 | 隔离掉什么 | 红了告诉你 |
|---|---|---|---|
| **单元** | `UnitTests` 主体（Agent / Conversation / Embedding / Memory / ModelRuntime / Tools / Workflow / Loop） | 外部依赖**全替身** | **哪个类或算法**错了 |
| **集成** | `UnitTests/Harness` + `Evaluation.AgentTask` | 只隔离**模型与网络**，其余全真（真链路、真账本） | **哪个接缝**断了 |
| **端到端** | *（待建）* | **不隔离**，从真实 HTTP 入口到底层 | **用户功能**坏没坏 |
| **质量**（度量轨） | `Evaluation.ModelQuality`　*（封存）* | 不跑流程，只量响应本身 | **分数 / 等级**（非门禁） |
| **横切约束** | `ArchitectureTests` | 不跑行为，反射 + 文本扫描 | **架构是否倒退** |

并发安全与架构约束是**横切属性**，不是层：并发是集成层的时序属性，但须**专设用例组**且每条配「降级为串行→必红」的负控。

---

## 二、工程 ≠ 层（两条必须钉死的事实）

1. **`UnitTests` 工程不等于「单元测试」**：它内含 `Harness/`（集成层）。判断某个用例属哪层，只看它装配了什么，不看它住在哪个工程。
2. **`AgentTask` 不是独立层**，它是**集成层的承载工程**。它与 `UnitTests/Harness` 同层（两处 `Build()` 逐参数比对：11 项 9 项逐字相同）。

---

## 三、职责边界：同层靠「用途」区分

| 工程 | 唯一职责 | 不负责 |
|---|---|---|
| `UnitTests/Harness` | **单条 + 深断言 + 快反馈** → 集成回归 | 批量驱动、轨迹回放 |
| `Evaluation.AgentTask` | **批量 + 汇总 + 失败路径入容器 + 回放不重跑** | 单条不变量（已由 UnitTests/Harness 覆盖） |
| `Evaluation.ModelQuality` | **确定性质量指标**（F1 / BLEU / GLEU + 分数等级） | 任何门禁（《标准》§1.1） |

---

## 四、重叠的唯一判据

> **同层 + 同判据 = 冗余，删。**
> **不同层 + 同判据 = 金字塔，保留**（价值 = 失败定位的粒度不同）。
> **同层 + 异关注点 = 互补，保留。**

---
