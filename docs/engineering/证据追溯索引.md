## 一、用途

本文件把重要工程主张连成证据链：需求/约束 → 架构决策 → 组件职责与接口 → 实现 → 用例 → 验证报告。规则见 [documentation-policy.md](documentation-policy.md) §6。

每条记录五要素：**来源 / 具体位置 / 能证明什么 / 不能证明什么 / 状态**。没有证据写 `UNKNOWN`，不伪造。

ID 沿用项目既有编号：六句用「第 N 句」、`AC-01/02`、`S01`–`S10`、`F38`、`P01`–`P15`；新增 `IMPL-`/`TEST-`/`EVID-`/`UNKNOWN-` 只作追溯定位。

## 二、六句成功判据的追溯

六句原文以 `docs/产品目标与范围.md` §3 为准；现状观察点见 `docs/验收映射.md`。

### 第 1 句 · 真实 API 查状态

- **需求**：`REQ-1` = 「能查到对方系统里的真实状态」，判定权在对方系统。
- **架构决策**：见正本 §3；传输经 MCP 工具 `frappe_get_doc`，绑定声明 `ErpMcpBindings.Query()`。
- **实现定位 `IMPL-Q1`**：`src/Domains/Erp/ErpMcpBindings.cs`（`Query` 工厂）；执行体 `src/Core/Tools/AgentWorkbench.Tools.Mcp/McpActionExecutor.cs`。
- **用例 `TEST-Q1`**：真跑探针 `scripts/verify-erpquery-http.mjs`（HTTP 入口）；未纳入 `dotnet test`。
- **证据 `EVID-Q1`**：2026-11-20 / 11-22 真跑，`status=succeeded` / `code=mcp_ok` / `externalId=PUR-ORD-2026-00001`，返回真单据 `docstatus` / 供应商 / 金额 / `modified`。
- **能证明**：经我方链路能读到对方真实单据字段；判定权在 ERPNext。
- **不能证明**：不证明写动作、审批、幂等；不证明模型聊天入口（当时 tool call 写成文本，未进闸）。
- **状态**：Verified（有对方系统实证）。

### 第 2 句 · 未审批零外部调用

- **需求**：`REQ-2` = 未审批不得在对方系统产生任何变化。
- **架构决策**：审批按 `ActionSpec.RequiresApproval` 配置，`Ask` 无应答 fail-closed（见 AGENTS.md §5 与 `ToolExecutionPipeline.InspectApprovalAsync`）。
- **实现定位 `IMPL-Q2`**：`src/Core/Runtime/AgentWorkbench.ActionGateway/ActionRunService.cs`（挂起/恢复）；审批闸门 `src/Core/Runtime/AgentWorkbench.Runtime.Tools/ToolExecutionPipeline.cs`。
- **用例 `TEST-Q2`**：`tests/AgentWorkbench.ApplicationTests/ActionGateway/TimeoutReconciliationTests.cs`（离网，写动作只调 1 次）；真跑见验收映射第 2 句。
- **证据 `EVID-Q2`**：2026-11-22 真跑，`erp.cancel` 提交返回 HTTP 202 / `pending` / `approval_required`；此刻**独立只读回查** `PUR-ORD-2026-00001` 仍 `docstatus=1`，对方未动。
- **能证明**：该动作在挂起态未触碰对方。
- **不能证明**：不证明"真人拒绝"（审批人仍是操作者本人，见 `P05`）；不证明所有写动作都需审批。
- **状态**：Verified（该动作、该时点）。

### 第 3 句 · 同 request_id 只一条

- **需求**：`REQ-3` = 同一请求重复提交只在对方留一条效果，**不假设对方有幂等键**。
- **架构决策**：`requestId = Derive(userId, clientMessageId, actionKey, arguments)` 由服务端确定性派生；终态命中返回 `replayed_from_idempotency`。
- **实现定位 `IMPL-Q3`**：`src/Host/AgentWorkbench.Webapi/Controllers/ActionsController.cs`；`src/Core/Runtime/AgentWorkbench.ActionGateway/ActionRunService.cs`（`GateAsync`）。
- **用例 `TEST-Q3`**：真跑重放，见验收映射第 3 句；未见独立单测文件专门覆盖派生函数。
- **证据 `EVID-Q3`**：2026-11-22 真跑，`PUR-ORD-2026-00002` 完整 cancel 后用同一请求体重放 → `code=replayed_from_idempotency`；审计 `execute` 段仅 1 个；独立回查 `docstatus=2`、`modified` 只变一次。
- **能证明**：ERP 侧该动作、该请求的重放被挡住，外部只留一次写。
- **不能证明**：不证明 Gitea 侧同等边界（`P03`）；不证明并发同时提交（本次是串行重放）。
- **状态**：Verified（ERP 侧）。

### 第 4 句 · 超时只查证不重放

- **需求**：`REQ-4` = 真实超时、不知道成没成时，只读查证，不重放调用（正本 v4.1 §3 已去掉"模拟超时"措辞，与"不造故障"决定对齐）。
- **架构决策**：`ADR 0019`（超时归 `Unknown` 而非 `Failed`；不靠人工造故障验收）。**注意归属未决**：该 ADR 现写在 Py 仓，本仓正本对 ADR 范围的声明待人类裁决，见 `P10` 与 [文档改造报告](文档改造报告.md)。
- **实现定位 `IMPL-Q4`**：`src/Core/Tools/AgentWorkbench.Tools.Mcp/ToolFailureClassifier.cs`；`McpToolInvoker.cs`（调用超时）；`McpActionExecutor.cs`（`Unavailable → Unknown`）；`ActionRunService.cs`（查证分支）。
- **用例 `TEST-Q4`**：`tests/AgentWorkbench.ApplicationTests/ActionGateway/TimeoutClassificationTests.cs`；`TimeoutReconciliationTests.cs`（端到端：写 1 次 + 查证 1 次 + `verified_by_query`）；`ToolCallTimeoutTests.cs`（超时/外部取消区分）。三条均做变异自证。
- **证据 `EVID-Q4`**：**UNKNOWN-4**。机制与判据已绿（20 条）；真站点"真实超时 + 对方只留一次写"的外部闭环未取得。两次人工注入均失败：第一次同步 `time.sleep` 堵死 server 事件循环，查证被饿死；第二次 8 秒超时把正常查证也打超时。按 ADR 0019 不再造故障。
- **能证明**：代码层可达、行为正确（离网判据 + 变异自证）。
- **不能证明**：不证明真实生产超时下的外部结果；不证明"对方只留一次写"的外部事实。
- **状态**：Partial（机制 Verified / 外部 UNKNOWN）。
