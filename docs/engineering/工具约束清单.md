# 工具约束清单

- **适用侧**：公共 ｜ **寿命**：常驻 ｜ **最后校准**：2026-11-23

## 范围与非范围

本文回答：本仓用**哪些机器检查**约束文档、每条**能证明什么 / 不能证明什么**、改完代码**该核对哪份文档**。

本文不回答：文档怎么写（见 `AGENTS.md` §4）、某条事实当前取值（跑 §1/§2 的命令）、六句验收到哪（见 `docs/验收映射.md`）。

**定位**：explanation，不是事实源，不是新门禁。约束的真身在脚本、测试和 `docs/kb/*.toml`；本文只解释它们的语义边界，改约束不必改本文。

## 1. 三类检查：各管什么、能证明什么

| 检查 | 谁执行 | 能证明 | **不能证明** | 退出语义 |
|---|---|---|---|---|
| 格式卫生 D1–D4 | `DocsHygieneTests`（dotnet 测试） | 状态位存在、相对链接目标在、局部不重复定义写法、正文纯文本路径存在 | 文档说的和代码做的是否一致；链接目标内容是否正确 | FAIL 即红 |
| 引用漂移 | `scripts/check_doc_refs.py` | 文档点名的 Sxx_NN 方法、`.cs` 文件**还在不在** | 符号存在不等于断言有效；防不了"判据根本没测试" | FAIL 即红 |
| 口径漂移 | `scripts/doc_consistency_check.py` | 同一事实（正本旧路径、旧章节号、ADR 范围）在多份文档里说法是否一致 | 不对齐谁对；不判语义真假（如终态词表是否矛盾） | WARN，恒 0 |

**共同盲区**：三者都查不了**语义真伪**——"文档描述的控制流与代码实际是否一致"。实证：`docs/core/工具执行.md` 旧版写了代码中零命中的 `gateway.Handles` 分支，三类检查全绿、文档却是错的。这类错只能靠 §2 的改动映射触发人工核对。

**自检**：`check_doc_refs.py` 的命中、`doc_consistency_check.py --self-test`、`DocsHygieneTests.D0`、`kb_check.py --self-test` 都在证明"检测器能认出伪造的违规"，不是空壳。

## 2. 元数据层：改了什么该核对哪份文档

两份 TOML，都**不存 status**——验证结果是跑出来的，写进文件就会变成第二种假绿。

- `docs/kb/documents/*.toml`（一份文档一个文件）：`watch`（代码路径 glob → 哪份文档需重新核对）+ `evidence`（结论从哪核对，`symbols` 校验被点名的类型/方法仍在）+ `fact`（文档声称的可枚举事实：配置值 / 版本 / 测试条数，带 `check` 与 `expect`）。
- `docs/kb/contracts/*.toml`（同样一份文档一个文件）：架构契约，带**稳定 ID**（`TOOL-ADMISSION-001` 这类）。ID 不随实现文件、测试名、方法名变化，跨文件查重；`section` 必须能在文档里定位到；**有用例写 `[[contract.evidence]] kind="test"`，没有就写 `kind="gap"` 带 reason**——留空或空 reason 都会被判 FAIL。

`scripts/kb_check.py`（零依赖，标准库 `tomllib` / `json` / `ElementTree`）：

```
python scripts/kb_check.py                  # 全量对账：文档/证据/符号/事实是否都对得上仓库
python scripts/kb_check.py --impact <路径>  # 改了这个文件：该核对哪份文档、关联哪些契约（含缺口）、哪些事实要复核
python scripts/kb_check.py --list           # 列出文档、证据、事实、契约
python scripts/kb_check.py --self-test      # 自检 glob / 过滤器 / 事实对账不是恒真
```

`fact` 支持三种 check：`json`（读 appsettings，按冒号路径取值，列表按 `Name` 挑项）、`csproj`（读 PackageReference 版本）、`test-count`（数 `[Fact]`/`[Theory]`）。**它是"声明 + 对账"，不是把值抄进 TOML**：事实变了而 `expect` 没改，脚本就红。

它**不重跑 §1 的三类检查**，也不跑测试，只做静态对账。它由 `scripts/ci.sh` 调用，所以会被真的执行；单独跑时它仍是提醒——不接 `dotnet test`、不产分数、不落 JSON 报告（没人读的文件比不写更糟）。未命中映射时会显式说"可能确实不涉及，也可能是映射缺项"，并给补 `watch` 的方法，不静默放过。

三条刻意的"不做"：

- 不判语义漂移。PASS 只说明索引没坏，不说明文档还对。
- 不自动改文档。AI 可以提议，不能改权威规则。
- 不给契约打分。`statement` 写得多好都不算证据；能不能站住只看 `test` / `gap`。

## 3. 错误信息格式：WHAT / FIX / REF

借鉴 OpenAI harness engineering 的做法（证据等级 P；公开资料只有自述，无源码，见 R3）：**把约束编码成检查，并把修复指令直接写进错误信息**。每条提示三段，缺一段即为不合格：

- **WHAT**：发现了什么、违反哪条约束。反例："文档可能有问题"。
- **FIX**：具体怎么改。反例："请检查文档"。
- **REF**：去哪里核对权威事实（命令 / 代码路径）。反例：指向另一份会漂的文档。

关键在 REF：**权威在代码和测试，不在任何 Markdown**（与 `AGENTS.md` §0 一致）。方法借鉴自 OpenAI 不等于本仓符合其标准，也不等于有等价实现。

## 4. 判定权归属

| 事项 | 判定权 | 机器的角色 |
|---|---|---|
| 链接/符号是否存在 | 机器（D2/D4 + 引用漂移） | 直接判红 |
| 同一事实口径是否一致 | 机器只列 WARN | **人裁决以哪份为准** |
| 文档描述是否符合代码语义 | **人** | 只能靠映射提醒，判不了 |
| 六句判据真假 | 对方系统（真跑） | 判不了 |
| ADR 归属 / 正本路径 / 终态词表 | **人** | 不判 |

机器查不出的、或需人类取舍的，进 `docs/plans/` 一问题一文件（`P01`–`P15` 顺延），不在本文替人决定。

## 5. 维护本套工具自身

- 改 `watch`/`evidence` 只改 `docs/kb/*.toml` 一处；文档和脚本里不复制第二份映射。
- 新增契约前先问：有没有能指向真实源码或测试的凭据？没有就写 `gap`，不要只写主张。
- **不要给每条实现细节发 ID**。ID 只给跨部件、安全默认值、或有已知缺口的主张；其余挂小节号就够。
- 新增机器检查前先问现有三类能否扩展；能扩展就不新建。
- 不建 CI、不做自动改文档的 agent：单人项目无 PR 流程，自动改写等于把拍板权交给模型。
