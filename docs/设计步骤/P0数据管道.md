# P0 数据管道 · 设计步骤

> 目的：上传 PDF → 解析 → 清洗 → 按条款切分 → 入库 → 预览可核对。
> 范围：仅 PDF 文本层；测试集用公开合同示范文本。
> 架构原则：解析/清洗/切分自研为**本地知识引擎**；知识/RAG 引擎通过**统一接口**接入，可本地（自研）或远程（AnythingLLM），并可整体替换（RAGFlow / OpenContracts），切换只改配置。

## 1. 成熟开源组件选型

| 用途 | 组件 | 说明 |
| --- | --- | --- |
| PDF 文本抽取 | UglyToad.PdfPig | MIT，纯托管，无需外部依赖 |
| 切分 | Semantic Kernel TextChunker + 自写"标题/条款"前置切分 | SK 已在依赖里 |
| 迁移 | FluentMigrator + Runner.Sqlite | 已在依赖里 |
| 数据访问 | Dapper + Microsoft.Data.Sqlite | 已在依赖里 |
| 后台解析队列 | System.Threading.Channels（BCL）+ BackgroundService | 成熟、无额外依赖 |
| 哈希 | BCL SHA256 | 去重/幂等 |
| 前端上传 | Element Plus el-upload | 已在依赖里 |
| 原始 PDF 预览（可选） | pdf.js / vue-pdf-embed | P0 可后置 |
| **知识/RAG 引擎** | **AnythingLLM** | **MIT，Docker，8GB 可跑；自带 API / 工作区 / 引用 / Agent** |
| **可替换引擎（仅留接口）** | **RAGFlow / OpenContracts** | 本期不接，预留适配器 stub |

## 2. 数据模型（SQLite）

- **documents**：`id, file_name, stored_path, sha256, size_bytes, status(pending/parsing/parsed/failed), page_count, error, created_at, parsed_at`
- **document_pages**：`id, document_id, page_no, raw_text, cleaned_text`
- **chunks**：`id, document_id, seq, page_from, page_to, heading, content, char_count, created_at`

存储：`data/agentworkbench.db`（WAL）+ `data/uploads/{sha256}.pdf`。
说明：本地库只存**管道产物**（页/块）；向量与检索由知识引擎负责（本地自研或 AnythingLLM）。

## 3. 后端结构与管线

```
Persistence/  DbConnectionFactory · Migrations(M001文档/M002页/M003块) · DocumentRepository(Dapper)
Documents/
  DocumentIngestionService   保存文件+SHA256+入库(pending)+入队
  DocumentParseQueue         Channel<Guid>
  DocumentParseWorker        BackgroundService：解析→清洗→切分→入库
  Parsing/PdfTextExtractor   PdfPig 按页取文本
  Parsing/TextCleaner        去页眉页脚/断行合并/空白规范化
  Parsing/Chunker            标题识别 + 递归定长切分(带重叠)
Knowledge/                    ← 可替换知识引擎（防腐层）
  IKnowledgeEngine           统一接口：上传/列表/删除/检索/带引用问答 + 能力位
  KnowledgeEngineRegistry    按配置解析引擎
  LocalKnowledgeEngine       本地自研（P0 的解析/切分即其实现基础）
  AnythingLlmEngine          调 AnythingLLM API（本期接入）
  RagFlowEngine / OpenContractsEngine   预留 stub
Controllers/DocumentsController · KnowledgeController
Options/StorageOptions · KnowledgeOptions(Provider + 各引擎连接)
```

状态机：`pending → parsing → parsed | failed`；失败写 `error`，可 `reparse`。
切换引擎：`Knowledge:Provider = local | anythingllm | ragflow | opencontracts`。

## 4. API

**文档管道（本地）**

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/documents` | 上传（multipart），返回文档记录 |
| GET | `/api/documents` | 列表（含 pageCount/chunkCount/status） |
| GET | `/api/documents/{id}` | 详情 |
| GET | `/api/documents/{id}/pages` | 每页 raw + cleaned |
| GET | `/api/documents/{id}/chunks` | chunk 列表（含页码/标题） |
| POST | `/api/documents/{id}/reparse` | 重新解析 |
| DELETE | `/api/documents/{id}` | 删文件+数据 |
| GET | `/api/documents/{id}/file` | 原始 PDF（供预览） |

**知识引擎（可替换）**

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/knowledge/health` | 当前引擎 + 能力位（决定前端按钮是否可用） |
| POST | `/api/knowledge/documents` | 上传到知识引擎 |
| GET | `/api/knowledge/documents` | 列表 |
| DELETE | `/api/knowledge/documents/{id}` | 删除 |
| POST | `/api/knowledge/retrieve` | 检索（返回片段+来源+分数） |
| POST | `/api/knowledge/ask` | 带引用问答（SignalR 流式） |

## 5. 前端页面

- `views/DocumentsView.vue`：本地管道上传 + 列表（状态、页数、块数、操作）
- `views/DocumentDetailView.vue`：左"页文本（raw/cleaned 切换）"、右"chunk 列表（页码+标题）"
- `views/KnowledgeView.vue`：知识引擎状态/能力位、文档、检索调试
- `views/ChatView.vue`：增加"带知识问答"入口
- `api/documents.ts` + `api/knowledge.ts`；路由 `/documents`、`/documents/:id`、`/knowledge`

## 6. 任务拆解

**主轨（本地数据管道，D1–D5）**

| 天 | 任务 | 验收 |
| --- | --- | --- |
| D1 | 加 PdfPig；Persistence + 三个迁移 + 启动跑迁移；StorageOptions | 启动后 db 三张表存在 |
| D2 | 上传接口 + 落盘 + SHA256 + 入队 + Worker + PdfPig 抽页文本 | 传 PDF→state=parsed，pages 有文本 |
| D3 | TextCleaner + Chunker（SK TextChunker + 标题切分，带重叠）→ chunks | 一份合同切出合理条款块 |
| D4 | Documents/Detail 页面 + 路由 + 原始文件接口 | UI 上传、预览、核对 |
| D5 | 放 3–5 份公开合同示范文本跑通，记录解析/切分问题清单 | 质量报告 + 已知问题 |
