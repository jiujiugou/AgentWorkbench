# P2 要素抽取与比对 · 设计步骤

> 目的：对**已解析的合同**跑「要素抽取 + 模板/规则比对」工作流，产出**结构化要素表**与**不一致/风险清单**；每条结论**带可点击原文出处**（复用 P1 的 `?chunk=<seq>` 高亮）。
> 范围：本地工作流引擎（**规则确定性抽取 + 可选 LLM 增强**）；不做 OCR、不出法律意见、不判输赢。
> 架构原则：新增能力 = **新增模块**；复用 P0 管道产物与 P1 引用；结构化输出对上层透明；不重造轮子。
> 依据：[`法律文件Agent-MVP与实施指南.md`](../法律文件Agent-MVP与实施指南.md) 第 4 节 P2「要素抽取 + 模板比对工作流（结构化输出）」，验收产出「要素表 + 不一致清单」。

## 0. 与实施指南的适配说明

指南是通用法律垂直蓝图，本仓库已有既成事实，需按下列差异落地：

| 指南提到 | 本仓库现状 | P2 采用 |
| --- | --- | --- |
| Semantic Kernel（函数 / Process）编排 | 已去 SK，改用 Microsoft Agent Framework（ADR-0001 / AGENTS） | **MAF + 显式管线**，不再引入 SK |
| bge-m3 / sqlite-vec / FTS5 / rerank | P1 已实现 | **直接复用** |
| DOCX/OCR/表格抽取 | P0 仅 PDF 文本层 | P2 不扩展解析，沿用 P0 产物；OCR/DOCX 记入后续 |
| 权限 / 审计 / 金标评测 / 兜底 | 指南放在 P3 | P2 只**预留**反馈与结构化兜底，完整评测在 P3 |
| 导出 Word/Excel | 指南为「好用」要点 | P2 提供 **Markdown / JSON / CSV**，Word/Excel 后置 |

## 1. 目标与范围

| 做 | 不做 |
| --- | --- |
| 合同**要素抽取**（当事人、金额、期限、质保、违约金比例、标的物…） | 出具法律意见 |
| **模板/规则比对**，标出缺失条款、不一致、风险项 | 判断案件输赢 |
| **结构化输出**（要素表 + 清单，带严重级与证据） | 全自动替人决策 |
| 每条结论**可点回原文**并高亮 | 训练 / 微调模型 |

## 3. 数据模型（SQLite）

复用 P0：`documents` / `document_pages` / `chunks`；复用 P1：`rules`（P2 扩展字段并接入）。新增 3 张表：

**`review_runs`（一次审查任务）** — `M007`

| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PK identity | |
| document_id | TEXT NOT NULL | FK `documents(id)` **ON DELETE CASCADE** |

| template | TEXT NULL | 模板/规则集标识（如 `买卖合同`、rules.category） |

**`review_elements`（要素抽取结果）** — `M008`

| 列 | 类型 | 说明 |

**`rules` 扩展** — `M010`（P1 仅建表，P2 接入）

新增列：`rule_type`（`element_required` / `clause_required` / `clause_forbidden` / `value_rule`）、`severity`、`target_key`（对要素类规则指定 key）、`expected`（表达式/期望值）、`match_hint`（关键词，用于条款定位）、`enabled`。保留 `category/name/body/version/created_at`。

存储：统一 `data/agentworkbench.db`（WAL）；迁移 `M007`–`M010`。启动时幂等种子一批**买卖合同审查清单**（`SeedStarterRulesAsync`，按 `category+name` 去重），schema 与内容分离。

## 4. 后端结构与管线（新模块 `AgentWorkbench.Review`）

```
Review/                                   ← 新增模块（P2 核心）
  IReviewService                        跑审查 / 查询结果
  ReviewService                         编排：取 chunks → 抽取 → 比对 → 汇总
  ReviewRunQueue                        Channel<long>（runId）
  ReviewWorker                          BackgroundService：执行 + 进度推送
  ReviewHub(/hubs/review)               按 runId 分组推送进度（或经 Webapi）
  Extraction/
    IElementExtractor                   要素抽取扩展点
    RuleBasedElementExtractor           确定性：金额/比例/日期/期限/当事人/标的物（正则+关键词）
    LlmElementExtractor                 可选：MAF 结构化 JSON（配置模型后启用）
    ElementSchema / ElementDto          结构化输出契约（JSON Schema + DTO）
  Comparison/
    IRuleChecker                        规则比对扩展点
    RequiredElementChecker              模板要求要素缺失 → finding
    ClausePresenceChecker               应有条款缺失 / 禁止条款出现 → finding
    ValueConsistencyChecker             金额大小写不一致 / 比例合计异常 / 正文附件不符 → finding
  Prompting/ReviewPrompts               提示词（版本化常量）+ 强制 JSON Schema
  Reports/IReviewReportWriter           汇总报告扩展点（Markdown / Json / Csv）
  Models/                               领域记录（ReviewRun/Element/Finding）
  ReviewServiceCollectionExtensions     AddNitroReview
Controllers/ReviewController            /api/review/*
```

依赖方向（单向，无环）：

```
Webapi → Review
Review → Agent(IChatService / IStructuredChatService), Knowledge.Abstractions, Persistence, Domain, Shared
Agent  → Providers, Domain
```

> 架构测试新增切片 `Review`：`slnx`、`TestArchitecture.AssemblyNames`、`ModuleCycleTests.expected`、`LayeringTests`（Domain 不得依赖 Review）、`Webapi.csproj`。

**Agent 模块新增契约（跨模块，见 ADR-0002）**

```
IStructuredChatService.GetJsonAsync<T>(systemPrompt, userPrompt, jsonSchema, ct) → T?
```

内部用 `IChatClient.GetResponseAsync<T>(...)` + `ChatOptions.ResponseFormat = ChatResponseFormat.ForJsonSchema(...)`；解析失败**一次修复重试**（append「仅输出符合 schema 的 JSON」），仍失败则该步失败。**保持 P1 `IChatService.StreamAsync` 不变**，纯增量。

**管线（双轨抽取 + 规则比对）**

```
文档(parsed) → 取 chunks（seq/heading/page/正文）
  ① 要素抽取（mode ∋ extract）
     rule 轨：RuleBasedElementExtractor（确定性、离线可用）
     llm  轨：LlmElementExtractor（配置模型才跑；同 key 覆盖 rule）
     → 归一化 + 证据绑定（chunkId/seq/evidence）→ review_elements
  ② 规则比对（mode ∋ compare）
     载入 rules(template) → RequiredElement / ClausePresence / ValueConsistency
     → review_findings（severity + 证据）
  ③ 汇总：要素表 + 不一致清单 + 统计；落 status/steps/latency
```

**降级原则**（与 P1 embedding 降级一致）：未配置模型时 LLM 轨跳过，仅规则轨 → 审查仍可完成（能力位置 `llmExtract=false`）。规则/比对**永远不依赖 LLM**，保证确定性与可离线。

**兜底**（P2 预留，P3 完善）：低置信度 / 无证据的结论标注 `info` 不下定论；LLM 步失败 → run `failed` 并保留已完成步骤产物（不写脏数据）；超时取消。

## 5. API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/review/health` | 能力位 `{ extract, compare, llmExtract }` |
| POST | `/api/review/runs` | 创建审查 `{ documentId, mode, template? }` → 202 `{ runId }`（入队后台跑） |
| GET | `/api/review/runs` | 历史列表（文档/状态/时间/发现数） |
| GET | `/api/review/runs/{id}` | run 状态 + 步骤进度 |
| POST | `/api/review/runs/{id}/rerun` | 重跑（按 run 重建，幂等） |
| GET | `/api/review/runs/{id}/elements` | 要素表（含 `chunkId`/`seq` 证据） |
| GET | `/api/review/runs/{id}/findings` | 不一致/风险清单（含 `severity`/证据） |
| GET | `/api/review/runs/{id}/report?format=md\|json\|csv` | 汇总报告（可导出） |
| GET/POST/PUT/DELETE | `/api/review/rules[/{id}]` | 规则/模板管理（P1 的 `/api/knowledge/rules` 保留兼容） |
| POST | `/api/review/elements/{id}/feedback` | 反馈「对/错」→ 评测集（P3 前置，预留） |

**进度推送**：`/hubs/review`，按 `runId` 分组；事件 `ReceiveReviewStep`（步骤/百分比）、`ReceiveReviewDone`、`ReceiveReviewError`。前端未连 Hub 时可退化为轮询 `GET /runs/{id}`。

## 6. 前端页面

- `views/ReviewView.vue`（`/review`）：**任务化入口**——选文档 → 按钮「抽要素」/「审合同（要素+比对）」；下方运行历史列表。
- `views/ReviewDetailView.vue`（`/review/:id`）：**证据优先 UI**——左「要素表」（key/label/值/来源/置信度），右「不一致清单」（严重级色标/结论/期望 vs 实际）；每行「查看原文」→ `/documents/{documentId}?chunk={seq}`（复用 P1 高亮）；进度条 + 每步结果；导出按钮（md/csv/json）。
- `views/RulesView.vue`（`/rules`）：规则/模板的增删改查（category/type/severity/expected/match_hint）。
- `api/review.ts` + 路由 `/review`、`/review/:id`、`/rules`。

## 8. 扩展点（新增 = 加类 / 加模块，零改旧代码）

- `IElementExtractor` + `ElementExtractorRegistry`（新要素来源：如表格抽取、第三方 API）
- `IRuleChecker` + `RuleCheckerRegistry`（新检查器：合规校验、跨文档一致性）
- `IReviewReportWriter`（新导出格式，如 Word/Excel）
- 规则/模板即数据（`rules` 表），新模板 = 新增规则行，不改代码
- 复用既有：`IChatClientFactory`（模型网关）、`IAgentToolProvider`（如需把审查做成对话工具）

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| LLM 结构化输出不稳定 | 解析失败/脏数据 | MEAI JSON Schema + 一次修复重试；失败标 `failed` 不落脏数据；规则轨兜底 |
| 要素抽取幻觉 | 结论不可信 | 强制证据绑定（chunkId/seq）；无证据标 `info`；P3 金标评测 |
| P0 切分粒度影响比对 | 漏检/误检 | 复用 P0 块；`match_hint` 关键词定位；必要时按 heading 聚合块 |
| 规则覆盖不足 | 清单不全 | 种子清单 + 人工运营；规则版本化 |
| 大文档耗时 | 体验差 | 后台 worker + SignalR 进度；分步可重跑 |
