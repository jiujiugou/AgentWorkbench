# 工作流（Workflow Loop）· 设计步骤

> 目的：把「一次或多次 Agent 运行」组织为**可编排、可单步重跑、提示词可版本化、可重试/取消/超时/断点续跑**的长任务，并汇总为报告。
> 定位：**Workflow Loop（外层：人定步骤与顺序）** 托管 **Agent Loop（内层：模型驱动、受限）**——`agent` 步骤就是一次 Agent Harness 运行。
> 接口：外层给**预算**（工具白名单 + maxSteps + 每步超时/重试）与**上下文**（文档 + 可选 RAG），内层回**结果 + 轨迹**。
> 范围：不引入可视化拖拽编排器；不做权限/审计、不做评测平台化。
> 依据：`../测试标准/Agent-测试与验收标准.md`（判定型 + 度量型；能脚本判定的禁止用 AI）。

## 1. 目标与范围

| 做 | 不做 |
| --- | --- |
| 工作流**定义**（步骤序列/每步输入输出）与版本 | 可视化拖拽编排器 |
| **单步重跑**（只重算该步，下游标脏） | 任意条件分支/循环控制流（V1 顺序管线） |
| **提示词版本化**（存 DB、选定/切换、步骤引用） | 多租户/权限 |
| **重试 / 取消 / 超时 / 进度 / 检查点 / 断点续跑** | 分布式调度、跨节点（单实例足够） |
| 托管 Agent Harness 为 `agent` 步骤 | 重写 Harness 的内部循环语义 |
| 报告步骤（汇总前序产物为 Markdown） | 评测平台化 |

## 2. 双层 Loop 边界（钉死）

| | **Agent Loop（内层）** | **Workflow Loop（外层）** |
| --- | --- | --- |
| 谁决定控制流 | 模型（调哪个工具、调几次） | 人（预定义步骤与顺序） |
| 状态机 | 自循环，直到收敛/短路/超预算 | 固定步骤序列 + 步骤级状态 |
| 归属 | 单步的取证与下结论 | 步骤定义、重试/取消/超时/进度、检查点、提示词版本、单步重跑 |
| 实现 | `AgentHarness` 模块 | `Workflow` 模块 |

**接口**：步骤执行器调用 `IAgentHarness`，只透传预算与上下文，回收结果与轨迹；Harness 不感知 Workflow 的存在。

## 5. 模块结构与执行模型

```
Workflow/
  IWorkflowService                          创建/查询/取消/单步重跑/恢复
  WorkflowService                           编排：加载定义 → 顺序执行步骤
  WorkflowModels                            步骤定义 / 运行与步骤视图 / WorkflowStepContext / 领域异常
  WorkflowRunQueue / WorkflowWorker         Channel<long> + BackgroundService
  Execution/WorkflowGraphBuilder            定义 → MAF 图（按 order 连边，末节点为输出源）
  Execution/WorkflowStepExecutorNode        步骤执行器节点：重试/超时/取消/落库/进度/放行
  Execution/WorkflowStepMessage             图内传递运行上下文
  Steps/IWorkflowStepExecutor + Registry    步骤扩展点（按 type 解析，未知类型报错）
  Steps/AgentStepExecutor                   `agent`：检索依据（降级不算失败）→ 托管 Agent Harness
  Steps/ReportStepExecutor                  `report`：汇总前序产物为 Markdown
  Prompting/IPromptStore + PromptStore      提示词版本化
  WorkflowSeeder                            幂等种子（document_analysis + workflow.answer@base-0.1）
  WorkflowServiceCollectionExtensions       AddNitroWorkflow
Controllers/WorkflowController              /api/workflow/*
Hubs/WorkflowHub                            /hubs/workflow（进度）
```

依赖方向（单向）：`Webapi → Workflow → { AgentHarness, Knowledge.Abstractions, Persistence, Domain, Shared }`。

**执行模型（顺序管线）**

```
run = create(documentId, workflowKey, promptVersion?)
for step in definition.steps (order):
   if step already succeeded and not stale: skip           # 断点续跑
   attempts = 0
   while attempts < maxAttempts:
       attempts++
       try:
           output = registry[step.type].Execute(context, step, budget)
           步骤状态=succeeded; 落 output; 推送进度
           break
       catch TimeoutException:
           最后一次 → 步骤 failed，run failed（不挂起）
       catch:
           退避后重试；耗尽 → 步骤 failed，run failed
       if cancelled: 步骤 cancelled，run cancelled
```

- **预算**：每步 `timeoutSeconds` + `maxAttempts`（默认 1，重试 2）；`agent` 步复用 Agent Harness 的预算（工具白名单 + maxSteps）。
- **取消**：`CancellationToken`（`POST /cancel`）→ 当前步取消，run 置 `cancelled`。
- **单步重跑**：`POST /runs/{id}/steps/{stepKey}/rerun` → 重置该步为 `pending`，**其后所有步骤标 `stale`**，从该步起重算（产物按 run 重建，幂等）。
- **恢复**：`POST /runs/{id}/resume` → 从首个非 `succeeded` 步骤继续（复用已完成产物）。
- **进度**：每步开始/结束推 `ReceiveWorkflowProgress { runId, stepKey, status, attempts, output }`。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 单步重跑/恢复产物重复 | 数据脏 | 按 run 重建（先删后插）；幂等键 = (run_id, step_key) |
| 步骤失败/超时挂起 | 体验差 | maxAttempts + per-step timeout + 取消；负控覆盖 |
| 提示词版本漂移 | 结论不可复现 | 运行固定 `prompt_version` 落库，可回放 |
| 并发重复触发同一 run | 竞态 | run 级互斥（同 run 只允许一个执行任务） |
| 过度设计（分支/循环） | 复杂度 | V1 只做顺序管线 + stale 标记 |

## 10. 与测试标准的衔接

- **判定型（mock，确定性）**：步骤顺序、步骤状态、单步重跑范围、提示词版本选用、重试次数、超时终止、取消不挂起、检查点/恢复、进度完整、级联删除、整跑幂等。
- **度量型（程序算 + 阈值）**：步骤成功率、恢复正确率、单步重跑下游失效率、幂等（行数稳定）。
- **不引入 LLM-as-judge 门禁**；LLM 步骤用 mock/回放。
