# P4 工作流（Workflow Loop）· 设计步骤

> 目的：把既有能力（P0 解析 → P1 检索 → P2 抽取/比对 → P3 审查结论）组织为**可编排、可单步重跑、提示词可版本化、可重试/取消/超时/断点续跑**的工作流。
> 定位：**P4 = Workflow Loop（外层：人定步骤与顺序）**；**P3 = Agent Loop（内层：模型驱动、受限）**。P4 把 P3 的 Agent Loop 当作一种步骤类型（`agent_step`）托管。
> 接口（沿用 P3 钉死）：外层给**预算**（工具白名单 + maxSteps + 超时）与**上下文**（finding + chunks + 检索入口），内层回**结果 + 轨迹**。
> 范围：不引入可视化拖拽编排器（V1 明确不做）；不做权限/审计（P5）、不做评测平台化（P6）。
> 依据：`../法律文件Agent-MVP与实施指南.md` ④（提示词与工作流：多步、可测、可定位、提示词版本化、单步重跑）；`../测试标准/Agent-测试与验收标准.md`（判定型 + 度量型；能脚本判定的禁止用 AI）。

| 做 | 不做 |

## 2. 双层 Loop 边界（钉死）

| | **Agent Loop（P3，内层）** | **Workflow Loop（P4，外层）** |
| --- | --- | --- |
| 谁决定控制流 | 模型（调哪个工具、调几次） | 人（预定义步骤与顺序） |
| 状态机 | 自循环，直到收敛/短路/超预算 | 固定步骤序列 + 步骤级状态 |
| 归属 | 逐条 finding 的取证与下结论 | 步骤定义、重试/取消/超时/进度、检查点、提示词版本、单步重跑 |

**接口**：P4 步骤执行器调用 P3（`IReviewAdvisorService` / `IAgentHarness`），只透传预算与上下文，回收结果与轨迹；P3 不感知 P4 的存在。

## 5. 模块结构与执行模型

```
Workflow/                                   ← 新增模块（P4）
  IWorkflowService                          创建/查询/取消/单步重跑/恢复
  WorkflowService                           编排：加载定义 → 顺序执行步骤
  WorkflowRunQueue / WorkflowWorker         Channel<long> + BackgroundService
  Steps/WorkflowStepExecutor(+Registry)      步骤执行扩展点
  Steps/ExtractStepExecutor                  → Review 抽取
  Steps/CompareStepExecutor                  → Review 比对
  Steps/AgentStepExecutor                    → P3 ReviewAdvisor（托管）
  Steps/ReportStepExecutor                   → Review 报告
  Prompting/IPromptStore + PromptStore      提示词版本化
  WorkflowServiceCollectionExtensions        AddNitroWorkflow
Controllers/WorkflowController               /api/workflow/*
Hubs/WorkflowHub                             /hubs/workflow（进度）
```

依赖方向（单向）：`Webapi → Workflow → { Review, ReviewAdvisor, AgentHarness, Knowledge.Abstractions, Persistence, Domain, Shared }`。
架构测试需新增切片 `Workflow`（`slnx`、`AssemblyNames`、`ModuleCycleTests.expected`、`LayeringTests`）。

**执行模型（顺序管线）**

```
run = create(documentId, workflowKey, promptVersion?)
for step in definition.steps (order):
   if step already succeeded and not stale: skip           # 断点续跑
   attempts = 0
   while attempts < maxAttempts:
       attempts++
       try:
           output = registry[step.type].Execute(context, step, budget)
           步骤状态=succeeded; 落 output; 推送进度
           break
       catch TimeoutException:
           最后一次 → 步骤 failed，run failed（不挂起）
       catch:
           退避后重试；耗尽 → 步骤 failed，run failed
       if cancelled: 步骤 cancelled，run cancelled
```

- **预算**：每步 `timeoutSeconds` + `maxAttempts`（默认 1/重试 2）；`agent` 步复用 P3 预算（白名单 + maxSteps）。
- **取消**：`CancellationToken`（`POST /cancel`）→ 当前步取消，run 置 `cancelled`。
- **单步重跑**：`POST /runs/{id}/steps/{stepKey}/rerun` → 重置该步为 `pending`，**其后所有步骤标 `stale`**，从该步起重算（产物按 run 重建，幂等）。
- **恢复**：`POST /runs/{id}/resume` → 从首个非 `succeeded` 步骤继续（复用已完成产物）。
- **进度**：每步开始/结束推 `ReceiveWorkflowProgress { runId, stepKey, status, attempts, output }`。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 托管 P3 导致回归 | P3 验收回退 | `agent_step` 仅调用既有 `IReviewAdvisorService`；P3 24/24 作为门禁 |
| 单步重跑/恢复产物重复 | 数据脏 | 按 run 重建（先删后插）；幂等键 = (run_id, step_key) |
| 步骤失败/超时挂起 | 体验差 | maxAttempts + per-step timeout + 取消；负控覆盖 |
| 提示词版本漂移 | 结论不可复现 | 运行固定 `prompt_version` 落库，可回放 |
| 并发重复触发同一 run | 竞态 | run 级互斥（同 run 只允许一个执行任务） |
| 过度设计（分支/循环） | 复杂度 | V1 只做顺序管线 + stale 标记 |

## 11. 与测试标准的衔接

- **判定型（mock，确定性）**：步骤顺序、步骤状态、单步重跑范围、提示词版本选用、重试次数、超时终止、取消不挂起、检查点/恢复、进度完整、级联删除、整跑幂等、P3 回归。
- **度量型（程序算 + 阈值）**：步骤成功率、恢复正确率、单步重跑下游失效率、幂等（行数稳定）。
- 交付 `scripts/acceptance-p4.ps1`（判定 + 负控）与 `scripts/eval-p4.ps1`（指标 + 阈值，小规模金标）。
- **不引入 LLM-as-judge 门禁**；LLM 步骤用 `tests/fixtures/llm/` mock/回放。
