# P1 知识库 · 设计步骤

> 目的：P0 切好的 chunk → 向量化 + 全文索引 → 混合检索 → 带引用问答。
> 范围：本地自研知识引擎（`IKnowledgeEngine` 的 Local 实现）；其他 provider 未实现时由注册表降级为不可用 stub。
> 架构原则：复用 P0 的 `Knowledge/` 防腐层；组件**全部开源成熟，不重造轮子**；向量/检索对上层透明，切换引擎只改配置。

## 1. 成熟开源组件选型

| 用途 | 组件 | 许可 | 说明 |
| --- | --- | --- | --- |
| Embedding | BAAI/bge-m3（Ollama）+ OllamaSharp | Apache-2.0 / MIT | 中文强、可私有化；OllamaSharp 实现 MEAI `IEmbeddingGenerator` |
| 向量库 | `Microsoft.Extensions.VectorData` + `CommunityToolkit.VectorData.SqliteVec`（内含 sqlite-vec） | MIT | 单文件、无独立服务；后续可换 Qdrant |
| 全文检索 | SQLite FTS5（`trigram` 分词） | 公共领域 | SQLite 内置；无分词库依赖；自带 BM25 |
| 混合融合 | RRF（倒数排名融合） | — | 标准算法，约 20 行 |
| 重排（可选） | BAAI/bge-reranker-v2-m3（Ollama / 兼容 API） | Apache-2.0 | P1 默认关闭，接口预留 |
| 抽象 / 编排 | Microsoft.Extensions.AI · Semantic Kernel | MIT | 已在依赖 |
| 迁移 | FluentMigrator | Apache-2.0 | 已在依赖 |
| 前端 | Vue 3 + Element Plus | MIT | 已在依赖 |

> 注：`Microsoft.SemanticKernel.Connectors.SqliteVec` 已废弃，用 `CommunityToolkit.VectorData.SqliteVec`（.NET Foundation，MIT，`1.0.x-preview`）；不满意 preview 可换 **Qdrant**（`Qdrant.Client`，Apache-2.0）+ 容器，接口不变。

## 2. 数据模型（SQLite）

复用 P0：`documents` / `document_pages` / `chunks`（`chunks.id` 为 rowid）。

- **`chunks_vec`**：向量集合，键 `chunk_id`；payload 存 `document_id / seq / heading / page_from / page_to`，正文回查 `chunks`（不重复存）。
- **`chunks_fts`**：FTS5 虚拟表，`content='chunks', content_rowid='id'`，`tokenize='trigram'`；`chunks` 批量替换后 `rebuild`。

存储：统一放 `data/agentworkbench.db`（WAL）；向量表由连接器创建，`chunks_fts` 由迁移建。
迁移：`M004_CreateChunksFts`。

## 3. 后端结构与管线

```
Embedding/
  IEmbeddingProvider            统一接口：EmbedAsync(texts) -> float[][]
  OllamaEmbeddingProvider       OllamaSharp 实现（bge-m3）
  OpenAiEmbeddingProvider       兼容 /embeddings 的供应商（回退）
Knowledge/
  IKnowledgeEngine              统一接口：health/列表/删除/检索/问答 + 能力位
  KnowledgeEngineRegistry       按配置解析引擎（local | 其他 → 不可用 stub）
  LocalKnowledgeEngine          本地实现：FTS5 + 向量 + 混合检索 + 引用
  UnavailableKnowledgeEngine    未接入引擎占位（NotImplemented，能力位全 false）
  Retrieval/HybridRetriever     向量 topK ∪ FTS topK → RRF →（可选 rerank）
  Retrieval/IReranker           重排抽象，P1 默认 Null
  Indexing/ChunkIndexer         向量化 → 写 chunks_vec → rebuild chunks_fts
Application/RagService          检索 → 拼上下文（强制引用）→ ChatService 流式
Controllers/KnowledgeController /api/knowledge/*
Options/KnowledgeOptions        Provider + Embedding + Rerank + 各引擎连接
```

管线：

```
上传 → P0 解析 → chunks 落库 → ChunkIndexer：Embed → chunks_vec → rebuild chunks_fts
问题 → 向量 ∪ FTS(BM25) → RRF →（可选 rerank）→ 拼上下文（带 [文档·片段#]）→ 流式
删除/重解析 → 级联清理 chunks_vec 与 chunks_fts
```

无命中或全部低于阈值 → 返回"资料不足以回答"。能力位 `{ Retrieve, Ask, Upload, Rerank }` 由 `/health` 暴露。

## 4. API

**知识引擎（可替换）**

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/knowledge/health` | 当前引擎 + 能力位 |
| GET | `/api/knowledge/documents` | 已索引文档列表（复用 P0 `documents`，附 `indexed`/`chunkCount`） |
| POST | `/api/knowledge/documents/{id}/index` | 手动/重建索引 |
| POST | `/api/knowledge/retrieve` | 检索：`{ query, topK }` → 片段 + 来源 + 分数 |
| POST | `/api/knowledge/ask` | 带引用问答（SignalR 流式，复用 `/hubs/agent`） |

> 上传/删除仍走 P0 的 `/api/documents`，索引在解析完成后自动建立。

## 5. 前端页面

- `views/KnowledgeView.vue`：引擎状态/能力位、已索引文档列表、**检索调试面板**（问题 → top-k 片段/来源/分数）
- `views/ChatView.vue`：加"带知识问答"开关；引用 `[文档名 · 片段#]` 可点击
- `views/DocumentDetailView.vue`：支持 `?chunk=<seq>` 定位高亮
- `api/knowledge.ts` + 路由 `/knowledge`

## 6. 任务拆解

| 天 | 任务 | 验收 |
| --- | --- | --- |
| D1 | 接入 OllamaSharp + SqliteVec；`KnowledgeOptions`；M004；`/api/knowledge/health` | 启动后 FTS 表存在；health 返回引擎与能力位 |
