# 阶段 1 · F2 知识资料管理

> 一句话：**传进去的文件，之后提问要能当依据用；传不进去要说清为什么。**
>
> 依据 [功能需求.md](功能需求.md) §3（REQ-05 / 06 / 10）。这里只写"用户能做什么、怎么算做到了、现在到哪一步"，不写为什么（→ §3.1）、不写代码在哪（→ [现状](../现状/知识资料管理.md)）。

## 1 用户能做的五件事

| # | 用户做什么 | 系统必须 | 怎么算做到了 |
|---|---|---|---|
| 1 | 传一份文件 | 收下并开始处理；格式不支持、空文件、太大，要说清是哪一种，并且不留任何东西 | 传 PDF → 列表立刻多一行「处理中」；传 DOCX、空文件、超过 30 MB → 一句人话，**库里没记录、磁盘没文件** |
| 2 | 看它处理到哪了 | 三态可见：处理中 / 可检索 / 失败+原因。**只有成功的才能标记为「可检索」** | 列表里每行都带状态；失败那行能读出原因文字 |
| 3 | 看它的原文和片段 | 能按页看原文，能看切成了哪些片段；**文档不存在要和「还没解析完」分得开** | 两个端点返回内容；不存在的 ID 返回 404，而不是空数组 |
| 4 | 失败了再试一次 | 点一下重新排队，回到「处理中」，旧失败原因清掉 | 返回 202，状态变为 `pending`，`error` 为空 |
| 5 | 删掉它 | 列表里消失，**并且以后提问再也搜不到它的任何内容** | 用只有它能答的问题问一次 → 删除 → 再问 → 回答「资料里没有」 |

**第 5 行是本域唯一"错了也看不出来"的一条**：删完列表空了，看起来成功；但向量没删干净时，提问仍能命中已删文档。只有真去问一次才发现。

## 1.1 上传拒收的错误码（对外契约）

第 1 件事里"要说清是哪一种"由响应体的 `code` 承载。**`message` 只给人看，可改可译；`code` 用来分支，一经发布不改名。**

| `code` | 什么时候 | 前端该做什么 |
|---|---|---|
| `NO_FILE` | 请求里没有 `file` 字段 | 提示"没选到文件"（通常是表单构造错误，不是用户操作） |
| `FILE_EMPTY` | `file` 存在但长度为 0 | 提示"选中的文件是空的" |
| `FILE_TYPE_UNSUPPORTED` | 扩展名不在 `.pdf / .txt / .md / .json` 内 | 提示"换格式"，并列出支持的类型 |
| `FILE_TOO_LARGE` | 超过业务上限（默认 30 MB） | 提示具体上限，建议压缩或拆分 |

三条约束：

1. **判定顺序即契约**：先有没有文件 → 再内容为空 → 再格式 → 最后大小。空文件同时也不支持扩展名时，用户该看到的是 `FILE_EMPTY`（先解决更基础的问题）。
2. **只加不改**：删一个码等于让已发布的客户端走进 `default` 分支。
3. **与超限 413 的区别**：请求体超过框架上限（64 MB）时由 Kestrel 直接拒，**没有响应体、也没有码**；`FILE_TOO_LARGE` 只覆盖 30–64 MB 这一段。

> 这四个码由 `tests/AgentWorkbench.ApiContractTests/UploadValidationTests.cs` 守着（同时对状态码、业务码、以及"盘上/库里/队列里什么都没动"三条一起断言）。码的定义在 `Domain/Documents/DocumentErrorCodes.cs`。
>
> **风格说明**：本组是 UPPER_SNAKE 的对外码；`EmbeddingFailureCode` 是 lower_snake 的内部诊断码（只进日志和 `detail`，不承诺稳定）。看到大小写就能判断能不能拿它写分支。

## 2 阶段 1 明确不做

1. Word / Excel / 图片 / 网页 —— 只承诺 PDF，把它做透
2. 文档版本管理（v1 / v2 / 回滚）
3. 在线预览与编辑 —— 只读原文，不做编辑器
4. 文档级权限 —— 属 F1，阶段 1 不做
5. 外部来源连接器（飞书 / 网盘 / ERP）

> 代码实际已能收 `.txt / .md / .json`，属**超出承诺**，不算缺口；但"不支持就要说清"这条不能因此降级。

## 3 一条不能让的判断

> **"处理中"和"处理失败"必须让用户看见，不能让失败看起来像"资料里没有"。**

失败被伪装成可用，用户会拿到"查不到"的回答，然后怀疑是 AI 不行——实际是文档根本没入库。这类问题排查成本极高，因为症状和"检索不准"一模一样。

## 4 现在还差的（读完代码得出的，4 条）

| 差什么 | 后果 |
|---|---|
| **没有文档页**：前端零处调用 `/api/documents` | 1、2 两件事今天只能 `curl` 做，"用户能看见"这个要求还没兑现 |
| **删除顺序反了**，且无事务（先删向量 → 再删记录 → 再删文件） | 删记录失败会留下"列表里有、搜不到"的残废记录；也可能留下搜得到的幽灵内容 |
| **不做去重**：同内容传两次＝两条记录（只是共用同一个磁盘文件） | 列表出现重复行，删一条另一条还在 |
| **`pages` / `chunks` 不判存在**：任意 id 都返回 200 空数组 | 分不清"文档不存在"和"还没解析完"，前端只能猜 |
