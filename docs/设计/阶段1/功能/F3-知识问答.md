# F3 知识问答 · 功能

需求出处：`docs/需求/功能需求.md` 的 REQ-07 / 08 / 09。

一句话：**用户问一个问题，系统在本地资料里找到相关原文，给出带出处的答案。**

本文只写这个功能由什么构成、每个部分管什么。**每项验到哪一步，见《F3-功能验证》。**

## 1 功能成立的条件：三条不变量

这个功能不是三个功能，是一个功能的三条不变量。三条同时成立，功能才算成立。

| 不变量 | 含义 | 缺了会怎样 |
|---|---|---|
| **可用** | 有答案时答得出，且答案来自资料 | 功能没有意义 |
| **可核** | 答了能追溯到原文 | 用户只能选择信或不信 |
| **不编** | 没答案时明确说没有 | 会自信地编，比不答更危险 |

三条互为验收条件：去掉可核，可用的"模型真用了资料"没有任何观测点；去掉不编，前两条不算完成；去掉前两条，不编的阈值定不出来。

**三条都是必要条件，没有"完成三分之二"这种算法。**

**验收顺序只能按证据排：先用、再可核、最后不编。** 这不是排期，是依赖：找不到材料，后两条无从谈起；可核提供不编的证据（无出处句比例）；不编的两个阈值，一个要可用的距离分布，一个要可核的引用台账。

按危害排其实相反——可用做不好，用户不满；**不编做不好，会被信任**。但验收顺序只看证据依赖，不看危害。

## 2 最原始的通路：找、送、答

删掉任何一步就不再是 RAG。

```
问题
 │  找：问题 → 相关的几块原文
 │  送：几块原文 → 上下文里的文字
 │  答：上下文 → 答案
用户看到答案
```

三步是必需的。其余都是在三步上加的：不做分词，全文路等于废掉；不做精排，前五里噪声多；不做判定，库外问题照样答；不做引用，答案无从核。

## 3 九个位置，挂在这条通路上

九段不是一条直线。五个是数据加工步骤（串行），另外四个各在别处。

| 位置 | 类型 | 它做什么 | 挂在 |
|---|---|---|---|
| 入口 | 边界 | 接收问题，开一次运行，注入指令 | 可用 |
| 分词 | 前提 | 全文路怎么把问题变成可比的词 | 可用 |
| 召回 | 加工 | 取出候选块 | 可用 |
| 精排 | 优化 | 候选里谁排前面 | 可用 |
| 装填 | 加工 | 块变成上下文里的文字 | 可用 |
| 判定 | 决策 | 这组命中够不够，不够就别答 | 不编 |
| 引用生成 | 加工 | 模型写答案，句尾标出处编号 | **可用 + 可核** |
| 引用校验 | 核验 | 查编号是否存在、内容是否对得上 | 可核 |
| 回原文 | 界面 | 用户悬停角标，看到原文片段 | 可核 |

三类混排，不能当一条流水线读：**判定只输出结论，不输出数据**；**引用校验的输出直接给界面，不喂下一步**；**回原文根本不在服务端**。

九段覆盖的是「资料怎么变成答案」，不覆盖「上下文整体怎么拼」（系统提示词、历史消息、本轮问题加起来多少）。现在知识问答以单轮为主，这块份额小，所以没有位置。

**评测也不在这九段里。** 它不是一次问答经过的一步，是跑很多遍之后统计——放进链路会让人以为它是最后一道工序。

九段里六段有现成件（分词、重排、解析、页码锚点、检索指标、三档判据），两段是搬砖（入口收敛、引用校验），**只有判定必须自己设计**——没有可抄的。

### 3.1 三条必须始终成立的结构约束

这三条不是某一段的做法，是整条链路的性质。破一条，前面九段各自都做对了，结果仍然是坏的。

| 约束 | 破了会怎样 |
|---|---|
| **证据只取一次**，同一份结果分发给模型、来源面板、引用校验 | 检索两次的排序可能不同，出现"面板显示这批、答案引那批"，而且不报错 |
| **引用候选取自本次证据，编号空间封闭** | 编号能指向本次之外的东西，等于给出一句无担保的担保 |
| **判定必须可见**：已回答 / 依据较弱 / 资料不足 / 未判定 / 失败，五种在界面上长得不一样 | 判了但用户看不出，判定等于没做；最危险的那种"有答案、有引用、但引用全对不上"会混进正常答案 |

多次检索时编号每次从 1 起算，合并必然撞号——取最后一次非空的那批；更早那批的引用判为越界。这是保守方向的错误（判成没出处），不会反过来给出假担保。

## 4 三个不变量各自拆成子问题

拆法只有一条规则：**列出用户能看到的坏结果**。列不出来的，不是子问题，是内部实现细节。

### 4.1 可用：八条

| 序 | 子问题（断了用户看到什么） | 落在哪一步 |
|---|---|---|
| 一 | 搜什么都空；**列表仍显示"可检索"** | 入库与切块（前置，不在九段里） |
| 二 | 答案落在缝里，一句话被切成两半 | 切块 + 分词 |
| 三 | 答非所问 | 召回 |
| 四 | 正确答案排第二，模型用了第一条 | 精排 |
| 五 | 内容被截断，只送到一半 | 装填 |
| 六 | 凭记忆答，没有依据 | 引用生成（可用视角：用了没有） |
| 七 | 读了但读错，数字、型号说错 | 引用生成（质量视角：读对没有） |
| 八 | 同一个问题从两个入口得到两个答案 | 入口 |

第一条的第二个现象比第一个糟：库空且列表也说空，用户知道该去入库；**库空而列表显示"可检索"，用户会以为搜索坏了，去查检索和阈值，方向全错**。它有一个具体成因——列表判"可检索"只看正文块与向量，不看全文表，所以换机器、回滚分支、清库之后没重建索引，就会出现"全文检索全空、列表照旧显示可检索"。

第五条同理：五块全文一起进上下文，最长那块两千多字，一条问题可能喂进去上万字——**条数是上下文预算的一部分，不该写死在检索工具里**。

### 4.2 可核：六条

前两种是不方便，第三种是骗人——**"有出处"本身就是一种担保**，指向错块比没有出处更危险。防住它的唯一办法：引用的候选集只能是本次证据，编号空间封闭。

| 序 | 子问题（断了用户看到什么） | 落在哪一步 |
|---|---|---|
| 一 | 没有角标，整段无从核 | 引用生成（可核视角：标了没有） |
| 二 | 编号不存在，指向一块不存在的原文 | 引用校验·一级（范围） |
| 三 | 编号在范围内，但那一块里找不到对应内容（误挂） | 引用校验·二级（覆盖率） |
| 四 | 不知道哪一句没依据，只看到总数 | 前端无出处句底纹 |
| 五 | 知道有出处，但看不到原文，还得自己去找 | 回原文悬浮卡片 |
| 六 | 当时能核，过几天回来看不到 | 引用记录落库 |

### 4.3 不编：七条

| 序 | 子问题（断了用户看到什么） | 落在哪一步 |
|---|---|---|
| 一 | 库里没有也照答，编得像真的 | 判定（七条规则） |
| 二 | 判定说"不足"，但没拦住，模型照样答完 | 否决（终止生成） |
| 三 | 拦住了，但界面是空白，或半句"我先查一下" | 固定文案兜底 |
| 四 | 拒了，但用户以为是模型自己承认不知道 | 前端拒答态 |
| 五 | 该拒的没拒（阈值太松） | 阈值定标 |
| 六 | 不该拒的却拒了（阈值太紧） | 阈值定标 |
| 七 | 拒了，但统计里记成"已回答" | 拒答状态码 |

一至七里只有第一条在九段上，其余六条挂在**判定的配套**上——否决、文案、前端、阈值、状态码。它们不是数据流，是判定结果的落地形态。

### 4.4 判定输出什么

判定返回四个取值之一，加一个原因。系统失败不在其中——那是运行状态，不是判定结论。

| 取值 | 含义 | 之后发生什么 |
|---|---|---|
| 已回答 | 有明确赢家，且足够近 | 放行，答案必须挂出处 |
| 依据较弱 | 够近但没有赢家，或只有一条参照 | 放行，答案加"建议核对原文" |
| 资料不足 | 判不足 | 交给否决层，终止生成 |
| 未判定 | 系统没有能力判断（缺向量，或阈值没配齐） | 放行，但必须在界面上说出来 |

三个硬约束：**阈值可空**，未测出来时留空、结论落在未判定上，不能用 0 假装配置过；**未判定必须显示**，缺向量时唯一诚实的做法是承认没能力判断；**候选过滤与拒答阈值不能共用一个数**——共用时它同时干两件事，过滤候选加事实上充当隐式阈值，调它的时候两件事一起动，调完说不清是"候选少了"还是"闸严了"。拆法是候选过滤放到很宽（1.0，只防垃圾），拒答阈值另外从数据量出来。

"只有一条参照"判依据较弱，是保守方向的选择：只有一条时不敢拒，放过去让没出处的句子把它暴露出来。拒错了用户无法自救，放过去了至少看得见。

### 4.5 不编要覆盖的是三种问题，不是一种

同样是"资料里没有"，正确行为分三档——混成一档，就只剩一个含糊的"不知道"。

| 档 | 例 | 距离判得出吗 | 正确行为 | 靠谁兜 |
|---|---|---|---|---|
| 完全库外 | 液压系统压力是多少 | 能 | 拒答，来源为空 | 判定 + 否决 |
| 同主题缺答案 | H5U 保修期多久 | **不能** | 不拒，靠没出处的句子把它暴露出来 | 可核的句级报告 |
| 超出检索能力 | 从连不上到读得到的完整排查顺序 | **不能** | 拒答是假通过，资料里其实有答案 | 单独列一栏，不进误拒率分母 |

第二档是这道闸的真实边界：问"H5U 保修期"和问"H5U 的 E2 报什么警"指向同一本手册，在向量空间里几乎挨着，区别只在那一块里有没有那句话。**没有任何绝对阈值能同时做到拒掉保修期、放过报警码**——不是阈值调得准不准，是那个量本身表达不了"有没有那句话"。

第三档更不能拒：那两条题的资料确实在库里，只是前五块装不下。拒在这里会拒得很合理，还会把误拒率压得好看，同时掩盖真缺陷。

所以 4.3 的七条是跨三档列的，不是七条各自独立。分档这件事必须先做，因为误拒率的分母靠它。

**边界要写死，否则会变成假承诺**：引用核实率只证明"每一句都有可核对的出处"，不证明"整段结论是从这些出处推出来的"。模型可以抄两句原文、第三句凭常识补，而那句角标恰好也能对上。用户核验的粒度本来就是句级的，这个缺口不用新机制填，但文档里不能把引用写成"证明答案来自资料"。

## 5 边界

这个功能只管"基于已有资料查资料作答"。

**产品边界：不做**

- 不做通用问答（不检索直接答）——一旦允许，权限与引用同时失效
- 不做内容生成（改写、翻译、扩写）——一做创作，引用就失去意义
- 不做多轮任务编排（"帮我整理一份报告"）
- 不做主动推送与定时摘要
- 不做 GraphRAG、多跳检索——没有基线之前加检索编排，等于同时改两个变量

**技术做法：不做**

| 不做 | 理由 |
|---|---|
| 用模型判"答案够不够"或"引用是否忠实" | 不可复现、不可复算，撞"不得由模型当门禁"这条铁律 |
| 多层未判定 | 未判定只有"缺向量"一种，多一层就多一个说不清的状态 |
| 给模型否决权 | 否决层只读判定，模型不能反过来推翻它；给了申诉权的闸等于没有闸 |
| 查询改写或扩展 | 多一次模型调用；改完"问题就是用户原话"这条前提消失，题库标准答案要跟着重写 |
| 同义词表 | 又一份带版本的隐藏状态，换一版数字就漂——与不用词典分词同一个理由 |
| 引用可信度评分 | 一个 0.87 分只制造新的误读；要么挂上，要么不挂 |
| 原文页面跳转高亮 | 页码精度只到"第 1 页"，撑不起跳转。回原文退到片段卡片 |
| 多路召回的权重调参 | 现在用倒数排名融合，没有可调的权重；改成加权求和要先有基线，而基线取决于其余部分 |

**有条件暂缓**（不是不做，条件到了就做）

- **交叉编码器重排**：会同时改变排序和分数分布，失去"改分词前后差多少"的对照 → 等混合检索的基线数字出来
- **换解析器**（MinerU / docling）：改切块边界，块编号全变，题库标准答案全部作废 → 先有解析失败的显式上报路径

两类不能混：暂缓的等着就能做，上面两张表是无条件的，等多久都不做。

## 6 这份清单怎么保证不漏

两个方向都要走，缺一个都不够。

**从用户看到的结果出发**，生成子问题。用户能看到的坏结果是有限的，列完就没有了；而系统内部细节无穷，从内部找永远找不全。

**从位置反查**，每个位置至少要出现在一个子问题里。没出现的就是"装着但没人验"——装填当时就是这么漏掉的：它在九段里，却没有任何一条问过它。

现在的对账结果：

| 位置 | 被哪几条覆盖 |
|---|---|
| 入口 | 可用八 |
| 分词 | 可用二 |
| 召回 | 可用三、可用四 |
| 精排 | 可用四 |
| 装填 | 可用五 |
| 判定 | 不编一（配套见不编二至七） |
| 引用生成 | 可用六、可用七、可核一 |
| 引用校验 | 可核二、可核三 |
| 回原文 | 可核五 |
| 入库与切块 | 可用一、可用二 |

每一格都有人。这张对账表就是"九段没有空段"的证据，也是以后加新位置时必须过的一关。

## 7 四份文档的分工

- **本文**：这个功能由什么构成，每个子问题落在哪一步。
- **《F3-功能验证》**：每一项验到哪、用什么验、红了算什么；指标怎么定义。
- **《F3-决策记录》**：为什么这么定，放弃了什么，哪些还是赌的。
- **《00-放这里》**：新出现的一条信息该放哪。

界线：本文只写"应该有什么"，不写"现在有没有"；决策记录只写"为什么"，不写"怎么做"。写进本文的东西不会因为代码变动而失效。

## 附录甲 · 中文分词：两字切分

不用词典分词。按字符类分段：连续英文数字型号原样保留成一个词，连续汉字按两字滑窗切。

| 输入 | 输出 |
|---|---|
| `H5U故障代码` | `H5U` `故障` `障代` `代码` |
| `报警怎么处理` | `报警` `警怎` `怎么` `么处` `处理` |
| `Modbus TCP` | `Modbus` `TCP`（不含汉字，原样） |

三个细节：

- **型号与错误码不被切开**：`H5U`、`Modbus`、`E2` 都成一个独立词，正好覆盖工业手册里最需要精确匹配的那类词。
- **单字不成两字**（例如"泵"）：这类查询交回模糊匹配兜底，不为它做单字索引。
- **索引与查询必须调同一个函数**：两边切法不一致，结果是命中零条，而且不报错——实现时踩过一次，所以评测脚本加了索引格式自检，不匹配时直接报错而不是给零分。

**运维约束**：换机器、回滚分支、清库之后都要重跑一次索引。全文表存的不再是原文而是切分后的词串，没重建就是"检索全空、列表仍显示可检索"——覆盖度判定只看正文块与向量，不看全文表。

## 附录乙 · 只留一个入口

作答只有一条路径：对话通道。另一条 HTTP 问答端点连同它下面的流式作答、提示词构造、接口契约一并删除——它前端零调用、不写运行记录、引用格式不同，并且在内部检索两次。

连带一条通则：**任何新配置项必须有消费者。** 没有消费者的配置比没有这个配置更糟，下一个人（或一个 agent）会以为对应的机制还在。
