# F3 知识问答 · 功能验证

只回答两件事：**21 项每一项现在验到哪一步**（项号与子问题见《F3-知识问答》第 4 节），以及**这些数怎么算**（第六节）。

## 读法

状态五态：

| 状态 | 含义 |
|---|---|
| 通 | 有实现，有验证，结论通过。**要标它必须先过反向检查**（见下），否则只能是"未验"。人工目视通过的写"通（人工）"并附失效条件 |
| **不通过** | 有实现，有自动验证，**结论是不合格**——这比"未验"更进一步，它知道问题在哪 |
| 半通 | 有验证，但**只覆盖子问题的一部分**，或判它的条件没满足（阈值空、无线） |
| 未验 | 有实现，但没有任何自动验证 |
| 缺 | 没有实现，或没有任何检查手段 |

**"通"必须带范围，不带范围的一律读成"不知道"。** 五档，按"链条走到哪"分：

| 范围 | 范围里有什么 | 范围外有什么 |
|---|---|---|
| 函数 | 只调到纯函数 | 管道、DI、数据库、前端 |
| 管道 | 经过工具执行管道（否决、终止） | 真模型、真检索 |
| 接口 | 经过 HTTP / SignalR 入口 | 真模型、真前端 |
| 人工 | 人看一次 | **不重跑**——所以必须写失效条件 |
| 端到端 | 真模型 + 真检索 + 前端 | — |

**"通"只证明断言存在且通过，不证明设计生效。** 整条链每格都对得上，运行时仍可能一次都走不到那个分支——现在的拒答就是这样：函数通、否决通、状态码通，两个阈值是 null，`Judge` 第一件事判"没配齐 → 未判定"。看汇总数字时先看范围分布，再看项数。

三条硬规矩。**每写一条验证都必须过第一道，不过的不许标"通"。**

**一、反向问一句：这条断言永远绿，那条坏结果还会发生吗？**

| 回答 | 判定 | 状态能写成什么 |
|---|---|---|
| **会** | 它不是这条子问题的验证 | 最高"未验"，验证方式列注明"这个断言不管它" |
| **不会** | 有牙齿 | "通" |
| **答不上来**（没有通过线 / 脚本没跑 / 人工目测） | 没有判据 | "未验"、"缺"或"人工"，不许写"通" |

判据的意思是：**验证的对象必须和子问题在同一层**。测组件正确 ≠ 测行为正确——分词 46 条能把分词函数锁得死死的，切块把一句话切成两半时它们照样全绿。这类验证不是白写，但它保护的不是这条子问题，不能记在这条名下。

**二、每条"通"必须能说出"改什么会让它变红"。** 说不出的，它不是验证，是装饰。

**三、人工验证项必须写失效条件**（渲染结构、类名、字段被改时会静默失效）。人工项是这份文档里唯一没有见证者的状态。

第一道最省事的执行方式是**改坏法**：故意把功能改坏，看断言红不红。把切块改成"每块只切一句"，分词测试还全绿，就证明了它管不到"答案落在缝里"。10 分钟一次，比争论"这算不算验证"有用——不争论，改坏它看。

**三种观测者。** 每一条的"红了算什么"最终都要有人提供证据，只有三种可能：

| 观测者 | 含义 | 现在的情况 |
|---|---|---|
| 本件自给 | 这一条自己算得出 | 大多数 |
| 借第三件 | 证据来自另一条不变量的产物 | 可用六（模型读没读）借可核的引用台账与无出处句比例 |
| 无人 | 只能真跑才量得出来，现在没有 | 可用五（实际字符数）、可用七（数值比对） |

"借"是正常的：系统只有一条处理链，同一份中间产物被多处消费，观测点必然错位。代价是串行依赖——第三件做不完，这一件后半段无法验收。

验证方式三档：

| 方式 | 含义 |
|---|---|
| 测试 | `dotnet test` 里的一行断言，改代码就重跑 |
| 脚本 | `tests/benchmark/rag/` 下的脚本，手动跑，出数字 |
| 人工 | 看一眼，验收时做一次，之后靠"路径不变"保证 |

## 四、本轮跑出来的结论

### 4.1 可核三：覆盖率分不开同主题邻块

可核第三条**不通过**，而且这不是"没配阈值"的问题。

`CitationCoverageTests` 用 5 组同主题邻块做对照——同一本手册的相邻报警码、相邻功能码、同样提到"SD 卡"的另一段。实测：

| 组 | 句子 | 差距 | 能不能分开 |
|---|---|---|---|
| E2 报警 | E2 报警表示未检测到 SD 卡 | 足够 | 能 |
| COM 端子 | COM 端子接 24V 电源负极 | 足够 | 能 |
| 03 功能码 | 03 功能码用于读保持寄存器 | 0.091 | **不能** |
| 波特率 | 默认通讯波特率是 9600 | 0.125 | **不能** |
| 存储卡容量 | 最大支持 32GB 的存储卡 | 0.000 | **不能**，两块完全相同 |

三组的共同点：**句子短，且关键词与邻块高度重合**。功能码都含"寄存器"，波特率都含"波特率"，存储卡都含"SD 卡"。覆盖率按两字组合算，这些重合全部计入，正确块的优势被摊平。

**后果**：二级校验的唯一职责就是抓"号码对、内容不对"的误挂，而误挂恰恰发生在同主题邻块之间。判别力在这三组上为零或接近零，意味着**即使把阈值定出来，这一级的实际效果也接近于不生效**。

修的方向不是调阈值：

- 覆盖率按 IDF 加权（越少见的词权重越高，"寄存器""波特率"这类在每个块里都出现的词降权）
- 或者改成关键值命中比对（数字、型号、单位逐条对，而不是整句字符重合）

这两条都还没有做。

**表中"不能"的三组已从测试里删除，不再用断言锁定。**它们原来写成 `Assert.True(gap < 0.20)`，是恒真式：覆盖率即便退化到永远返回 0，这条断言也照样绿，抓不到任何退化。缺陷的价值在"曾经测到 0.091 / 0.125 / 0.000"这个事实，而事实写在这里比写成会传染的常量更耐用。

删掉之后测试只剩 5 条：2 组能分开的对照（`right > wrong` 与 `gap >= 0.20`）+ 1 条无关块。**覆盖率一旦变瞎，那 2 组会立刻红**——原先被恒真式盖住的退化，现在能被抓到了。

### 4.2 可用二：7.29% 的块从半句开始

`sample_chunks.py` 扫了 439 块的 376 条接缝，**34 处异常、涉及 32 块，7.29%**（阈值 5%）。

四类（一处可命中多类）：块尾不像句尾 26、标题/表格行被切断 6、块首不像句首 3、相邻块能拼成一个词 1。

三个例子：

| 位置 | 现象 |
|---|---|
| 汇川H5U-故障诊断 seq=114→115 | 块尾 `…配置Comparepluse/time`，块首直接是 `2147483647或者小于-2147483648…`——原句是"换算成脉冲单位后大于 2147483647"，后半截变成一个没有主语的裸数字 |
| samr-03-chujing seq=8→9 | 块尾逗号悬空 `…旅游者提出解除合同的，`，且标题只剩半句 `第十三条 因不可抗力或者已尽合理注意义务仍不能` |
| samr-04-fangwumaimai seq=3→4 | 块尾 `…统一社会信用代码： / 开发企业资质证书号：`，表单字段列表断在半路 |

**根因**：`Chunker` 按行累积、每 800 字 flush、尾部留 120 字重叠。800 字的边界与句子边界无关，重叠区也只是按字数切，不保证落回句首。

**这条为什么重要**：块从半句开始时，模型拿到的是一段没有主语的文字——而引用角标照样能对上（那句话确实在这一块里）。所以这是「可用」里唯一一条**不会触发任何其它告警**的错误：引用全绿、判定说"已回答"，答案却是从半句推出来的。

**修法**：flush 时回退到最近的句末标点（。！？；）再切，重叠区从上一个句首开始算。改完重跑 `sample_chunks.py`，比例必须降到 5% 以下，否则这条仍然是"不通过"。

### 4.3 可用六：三次里有一次，模型根本没查

这是全篇最重要的一条实测，因为它推翻了一个一直没写下来的假设——**"指令说了先检索，模型就会先检索"**。

同一个后端、同一个模型、同一轮次，四次问答：

| run | 题 | iterations | tools | 结果 |
|---|---|---|---|---|
| 16 | q01 Modbus 异常码 | 2 | 1 | 4 句，1 句有出处 |
| 17 | q01 重跑 | 2 | 1 | 5 句，1 句有出处 |
| **18** | **q03 伺服反馈 65535** | **1** | **0** | **10 句，0 句有出处** |
| 19 | q24 H5U 出厂 IP | 2 | 1 | 4 句，2 句有出处 |

run 18 发生了什么：模型一次都没调 `search_knowledge`，直接凭常识列了六条排查建议（信号干扰、接线、参数设置、驱动器故障、电机故障、控制器问题），读起来很像手册里的内容。

系统这边的反应：

- 引用报告：`sentenceCount=10, citedSentenceCount=0, uncitedRatio=1.0, citations=[]`
- 第二层判定：`supportVerdict="unsupported"` —— **触发了**
- 答案：照给

**所以第二层是工作的，但它只标不拦。** 用户看到的是一段很专业的建议，末尾加一句"资料不足以回答该问题"——这比空答案更危险，因为编造被包装过了。

这就是"六条指令裸奔"的实证：只有"不足就说"有代码兜底（否决层），"先检索"没有。补它不能靠更严的 prompt（prompt 已经写了，这次就是它没照做），只能靠**系统预检索**——用户一提问就先检索一次，模型想不想查都有证据在手，`[n]` 也就不再依赖它主动。

## 五、汇总

| 状态 | 项数 | 是哪几项 |
|---|---|---|
| **通（端到端）** | 2 | 可用五、可用七 |
| 通（自动断言） | 5 | 可用一（脚本）、可用八（接口）、可核二（函数）、不编二（管道）、不编七（单测） |
| 通（人工目视） | 3 | 可核四、可核五、不编四 |
| **不通过** | 4 | 可用二（切块）、**可用六（零检索）**、**可核一（零角标）**、可核三（判别力） |
| 半通 | 3 | 可用三（有数字无通过线）、不编一（只覆盖算术）、不编三（只覆盖文案来源） |
| 未验 | 2 | 不编五、不编六 |
| 缺 | 2 | 可用四、可核六 |

**"通"分三类是必须的**：端到端那 2 条跑过真模型、真检索、真前端链路；自动那 5 条改代码会重跑；人工那 3 条只在验收时看一次，之后靠"路径不变"保证，所以各自写了失效条件。

**端到端从 0 变成 2**，但注意这 2 条验的都是"链路跑通没有"，不是"答得对不对"——答得对不对现在有 4 条红的（可用二、六、可核一、可核三）。

## 六、评测集与指标

这一节定"数从哪来、怎么算"。上面表里出现的 0.812、0.588、误拒率、无出处句比例，全以这里为准。

### 6.1 评测集

```
tests/benchmark/rag/questions.json     40 条：问句、标准答案块、题型
tests/benchmark/rag/run_rag_eval.py    输出检索指标，随代码进版本库
```

公开基准替不了自建题集——真正缺的是"哪一块写了答案"这个标准答案，任何框架都给不了。

三条规矩：

- **标准答案写成文件名与片段序号，不写块编号**：块编号自增，重解析一次就全变，而它不会报错，只会让命中率悄悄归零。
- **题型四类**：字面题（用原文术语，会虚高，只当基线）、改写题（禁止使用原文术语，这档才是真实体验）、歧义题（多块都算对）、负控题（库外问题，应当拒答）。
- **题集与代码同版本**，否则数字不可比。

负控必须拆三档：完全库外、同主题缺答案、超出检索能力。三档正确行为不同，混成一个标签，误拒率就没有分母。库外那一档要补到十五条以上，否则定出来的阈值是过拟合。

### 6.2 指标

检索侧两个：

| 指标 | 定义 |
|---|---|
| 命中率（前五条） | 标准答案块出现在前五条的比例 |
| 平均倒数排名（前五条） | 第一个标准答案块的排名取倒数后求均值（第一名 1.0、第五名 0.2、没进 0） |

生成与拒答侧四个：

| 指标 | 定义 |
|---|---|
| 误拒率 | 库内有答案的题里被判"资料不足"的比例（分母不含"超出检索能力"那一档） |
| 引用核实率 | 已挂出的引用里指向标准答案块的比例 |
| 无出处句比例 | 没有挂出处的句子数除以总句数 |
| 间隔分布 | 每道题的第一名距离，以及第二到第五名平均距离减第一名；定阈值前先量，本身不是门禁 |

三档判据映射到五种结果：答对是"已回答且引用命中"；坦白不知道是"资料不足"；**自信答错是"已回答但没有引用或引用全不命中"**。第三档最危险，也最容易在统计里被漏掉——这几个数必须一起看，单看命中率会把自信答错算成命中。

### 6.3 阈值怎么来

不是调出来的，是量出来的：四十条题各跑一次，按档分组看第一名距离与间隔这两条分布有没有重叠。

**测量有一个陷阱必须先处理**：检索器在返回之前就按候选过滤上限把远处的候选滤掉了。直接量，看到的永远是"全部不超过该值"——那不是数据的分布，是被剪掉尾巴的分布，据此定出来的阈值只在那个上限以内打转。**测量时必须先把候选过滤放宽到 1.0。**

| 测量结果 | 第一层怎么办 | 交付什么 |
|---|---|---|
| 库外档的间隔明显低于正例，两段不重叠 | 阈值落进间隔，闸成立 | 三层全套 |
| 两段重叠，没有可分的位置 | 第一层取消 | 只做"记录加未判定可见"，判据改为"库外问题不给出处、答案明确说资料里没有"，由第二层兜底 |

第二种不是失败，是这套 embedding 下的真实能力边界——硬拍的阈值会在真实流量里同时干两件坏事：该答的拒了、该拒的答了，而且没人分得清是哪一件。

扫描留作最后一步：候选值定了之后，用它跑一遍误拒率与自信答错率。两个数一起变坏，说明阈值落在重叠区，不许用。
