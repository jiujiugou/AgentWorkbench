# 阶段 1 · F3 知识问答

> 一句话：**把问题变成带原始出处的答案；没依据时明确说"资料里没有"。**
>
> 依据 [功能需求.md](功能需求.md) §4（REQ-07 / 08 / 09）。这里只写"用户能做什么、怎么算做到了、现在到哪一步"，不写为什么（→ §4.1）、不写代码在哪（→ 各源文件行号，见 §4 表）。

## 1 用户能做的三件事

| # | 用户做什么 | 系统必须 | 怎么算做到了 | 现在 |
|---|---|---|---|---|
| 1 | 问一个资料里有的问题 | 检索资料，基于命中内容作答 | 问"XX 的参数是多少" → 答案来自那份文档，不是模型常识 | 🟢 "知识库问答"模式走检索 + 工具，链路完整 |
| 2 | 看这个答案的依据 | 每条结论标出处：**文档名 + 位置（页/片段）+ 原文片段**，三者缺一不可 | 答案里有 `[1]` 之类的标记；展开来源面板能看到对应片段原文；**标记和面板能对上** | 🟡 面板有、片段有，但**标记没有任何程序校验**（见 §4-2） |
| 3 | 问一个资料里没有的问题 | 只回答"资料不足以回答"，**不掺任何推测、不伪装成资料结论** | 问一个库外问题 → 得到固定拒答文案，且展开来源面板为空 | 🔴 服务端闸几乎不生效，靠模型听指令（见 §4-1） |

**第 3 行是本域唯一"做不好会被信任"的一条**：给引用做错了会被发现；没依据却编造答案，用户会**信**，然后在关键问题上被误导。

## 2 阶段 1 明确不做

1. 通用知识问答（不检索直接答）—— 一旦允许，权限与引用同时失效
2. 多轮复杂任务编排（"帮我整理一份报告"）—— 属 Agent 编排，不是查资料
3. 主动推送 / 定时摘要 —— 第一版是"问—答"模型
4. 生成新内容（改写 / 翻译 / 扩写）—— 只做"基于已有资料作答"，一做创作引用就失去意义

## 3 一条不能让的判断

> **"没依据"比"给引用"更重要。** 引用做不好会被发现；拒答做不好**会被信任**。

所以宁可多拒答（用户损失一次提问），不可少拒答（用户损失信任）。判定"够不够"必须由代码做，不能由模型自己判断——模型判就不可复现、不可测量，"没编造"就永远无法证明。

## 4 现在还差的（读完代码得出的，4 条）

| 差什么 | 证据 | 后果 |
|---|---|---|
| **拒答闸失效**：服务端唯一硬闸是 `hits[0].FusedScore <= 0`，但融合分恒大于 0，且全文检索有 `LIKE` 兜底，中文问句几乎必有候选 | `RagService.cs:58`；`HybridRetriever.cs:180`（LIKE 兜底） | "没编造"完全靠模型听提示词；工具路径连这道闸都没有，指令自己承认是"前移为约束"（`KnowledgeInstructions.cs:9`） |
| **出处零校验**：答案里的 `[1]`、`《文件名》片段#12` 没有任何程序验证它指向本次真实返回的片段 | 全仓无校验代码 | 模型编一个不存在的出处，不会有东西报错；"可核查"三个字目前是自称 |
| **两种引用格式并存**：REST 链路要 `[编号]《文件名》`，harness 链路要 `《文件名》片段#序号` | `RagService.cs:81` vs `KnowledgeInstructions.cs:18` | 校验器要写两套；且 REST `/api/knowledge/ask` **前端零调用**，等于维护一条没人用的链路 |
| **一问两检索**：REST ask 先检索一次拿 sources，流式生成内部又检索一次 | `KnowledgeController.cs:113-119` | 答案依据和返回的 `sources` 可能是**两批不同的片段**——用户对着来源面板核查答案，可能对不上 |

> 第 1 条和第 3 条是同一件事的两面：**判定"够不够"的权利现在在模型手里**，而"用户能不能信这个答案"取决于它。
