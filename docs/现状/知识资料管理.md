## 4 与既定约定不一致的地方（只列事实）

> **约定现在在哪**：`docs/设计/阶段1/阶段1-F2.md`（用户视角的 5 件事 + §1.1 错误码）、7 篇 ADR、需求文档。
> 位置列写方法名不写行号——行号每次重构都会漂。
>
> **已对齐的一项（2026-10-31）**：上传拒收现在带 `code`（`NO_FILE` / `FILE_EMPTY` / `FILE_TYPE_UNSUPPORTED` / `FILE_TOO_LARGE`），
> 且 `NO_FILE` 与 `FILE_EMPTY` 已拆成两个分支。规格见 [阶段1-F2 §1.1](../设计/阶段1/阶段1-F2.md)，由 `ApiContractTests` 守着。

| # | 现状 | 位置 | 依据 |
|---|---|---|---|
| 1 | **不做去重**：从不按 sha256 查已有记录，每次都新 `id` + 恒 202。同内容只复用磁盘文件（路径相同），记录会重复 | `DocumentIngestionService.IngestAsync` | [ADR-0006](../adr/0006-dedup-by-unique-constraint.md) |
| 2 | 删除顺序仍是「**先索引、后记录**」，与 ADR-0005 的 L1→L2 相反；但已加残留核对：清不干净就返回 409 并**保留记录**，不再留幽灵 | `DocumentsController.Delete` | [ADR-0005](../adr/0005-delete-has-three-layers.md) |
| 3 | 列表 **2N 查询**：逐文档 `CountChunksAsync` + `CountVectorsAsync`；且返回裸数组 | `DocumentsController.List` | 无 |
| 4 | 下载 `Content-Type` 硬编码 `application/pdf`，不按扩展名 | `DocumentsController.Download` | 无 |
| 5 | `parsing` 中重处理的行为未定，代码未特判 | `DocumentsController.Reparse` | 无 |
| 6 | `pages` / `chunks` 对任意 id 都返回 200 空数组，分不清「文档不存在」和「还没解析完」 | `DocumentsController.Pages` / `Chunks` | 无 |

第 3–6 条现在**没有任何文档说它们不该这样**——要么重新定，要么就当它是当前行为，别让一条已删的约定继续在记忆里失效。
