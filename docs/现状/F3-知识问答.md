# F3 · 知识问答（现状 + 接口）

- **这份文档只回答两件事**：现在能做什么、代码在哪。不写"应该怎样"，也不写当初为什么这么选。
- **依据**：2026-10-31 读代码 + 读 `appsettings.json` 得出。改代码后以代码为准。
- **不回答**：表结构（→ [表结构.md](../../数据库/表结构.md)）、需求（→ [功能需求.md](../../需求/功能需求.md) §4）、怎么测（暂无）。

## 1. 一句话现状

**能问、能答、能给出处；但"没有答案时说不"目前只在一个条件下触发，而答案里的出处没有任何程序校验。**

## 2. 入口

| 方法 · 路径 | 代码 | 做什么 | 现状 |
|---|---|---|---|
| `GET /api/knowledge/health` | `KnowledgeController.Health:38` | 报引擎配置与索引计数 | 🟢 可用；**不报"最近一次调用是否成功"** |
| `GET /api/knowledge/documents` | `Documents:47` | 文档列表（带 `chunkCount`、`indexed`） | 🟡 与 `GET /api/documents` **重复实现**，两者字段不同 |
| `POST /api/knowledge/documents/{id}/index` | `Reindex:70` | 先删后重建该文档索引 | 🟢 可用；同步执行，不走队列 |
| `POST /api/knowledge/retrieve` | `Retrieve:87` | 只检索，返回命中片段与三路分数 | 🟢 可用（调试用） |
| `POST /api/knowledge/ask` | `Ask:103` | 检索 + 生成答案 | 🔴 **另一条链路**（见 §3），无运行轨迹 |
| Hub `Ask` | `AgentHub.Ask:59` | 知识问答（流式） | 🟢 **主链路**：走 harness，有轨迹 |

## 3. 两条作答链路（本域最重要的一张图）

| | Hub `Ask`（主） | `POST /ask`（遗留） |
|---|---|---|
| 检索怎么发生 | 模型调工具 `search_knowledge` | 服务端**预检索一次**，`RagService` 内部**再检索一次** |
| 提示词 | `KnowledgeInstructions.AnswerWithCitations`（run 级注入） | `RagService.BuildSystemPrompt` 内联拼【资料】 |
| 轨迹 | ✅ 有（工具调用、步骤、状态） | ❌ 无 |
| 出处来源 | 工具结果 JSON → `ReceiveSources` 推送 | 预检索那批 → 响应体 `sources` |
| 状态 | 应保留，遗留链路待 F4 收敛 | 待废 |

**后果**：同一次问答的两批候选各自排序，答案依据的可能不是界面显示的来源列表，且系统内部没有记录这个错位。

## 4. 核心类

| 类 | 位置 | 干什么 |
|---|---|---|
| `KnowledgeController` | `Webapi/Controllers/` | 5 个端点的薄封装；**自己在拼错误体** |
| `LocalKnowledgeEngine` | `Knowledge.Local/` | `IKnowledgeEngine` 唯一实现；转发到检索 / 索引 / RAG |
| `HybridRetriever` | `Knowledge.Local/Retrieval/` | 两路召回（向量 ∪ 全文）→ RRF 融合 → **回查正文，查不到即丢弃** |
| `RagService` | `Knowledge.Local/` | 遗留链路的"检索 + 拼提示词 + 流式生成"；**拒答判定在这里** |
| `SearchKnowledgeTool` | `Knowledge.Local/Tools/` | 工具 `search_knowledge`，返回 `RetrievalHit` 的 JSON 数组 |
| `KnowledgeInstructions` | `Knowledge.Local/` | 主链路的系统指令：先检索、只依据资料、标出处、不足则拒答 |
| `ChunkIndexer` / `VectorIndex` | `Knowledge.Local/Indexing/` | 写 FTS5 与 sqlite-vec；属 F2 的索引通路 |

## 5. 关键参数（`appsettings.json` 的 `Knowledge` 节）

| 参数 | 现值 | 影响 |
|---|---|---|
| `TopK` | 5 | 交给模型 / 返回的片段数 |
| `CandidateK` | 20 | 每路召回候选数，融合后再截断 |
| `MaxVectorDistance` | 0.6 | 语义路候选的**距离上限**（越小越相似），超过即丢 |
| `MinFusedScore` | **0.0** | 融合分下限。**融合分第 1 名恒为 1/61≈0.0164，所以这一项等于永不触发** |
| `Embedding` | ollama / bge-m3 / 1024 | 语义路依赖它；不可用时退化为纯全文 |
| `Rerank.Enabled` | false | 重排关闭，直接按融合分截断 |

## 6. 现状缺口

| 缺口 | 证据 | 后果 |
|---|---|---|
| **拒答几乎不会触发** | `RagService:58` 判 `hits[0].FusedScore <= 0`；而全文路有 `LIKE` 兜底，中文问句基本都有候选 | "资料里没有"这一步实际靠模型听指令，不可测、不可复现 |
| **出处没有程序校验** | 无人解析答案里的引用标记 | 模型编一个不存在的出处，没有任何东西会红 |
| **遗留链路无轨迹** | `KnowledgeController.Ask` 不经 harness | 这次问答查不到 run，属 F4 待补的审计后门 |
| **可用性无观察者** | `GetStatusAsync` 只报配置与计数 | 文档页想显示"语义检索当前不可用"时没有数据源（只有检索会发生语义调用，所以只有本域能产出它） |
| 中文短词靠模糊匹配 | `FtsSearchAsync` 对 1–2 字词走 `LIKE` | 字面碰巧命中的候选会污染融合排序 |
| 引用不落库 | `messages` 无引用列 | 重开会话引用消失（属 F5 / REQ-21） |

## 7. 不属于本域

资料入库与索引（F2）、运行轨迹与停止（F4）、会话与引用持久化（F5）、`curl` 闭环与模型配置（F6）。**本域只产出"这次问答的结果"**：答案、出处、来源列表。
