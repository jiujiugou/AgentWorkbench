# 运行时底座 · 五项功能规格与验收要求

v0.2-draft ｜ 2026-11-07 ｜ 范围：**只含五项**（模型循环 / 工具调用 / 上下文 / 会话 / 任务执行）

判据来源：ADR 0016 §二 R1–R5、§八 RR-1–RR-5；ADR 0017 §三 / §六；正本 §4.1。

> 本文以**功能**为主语：每项先写「这一层负责什么、应该做到什么」，再写「怎么确认它做到了」。
> 跨模块的组合行为不混进单项，单列 §6。
> 每条验收都必须带**负控**——把实现改坏，该测试必须变红。只断言「存在 / 不抛异常」不算通过。

---

## 0. 五项的位置

| 项 | 一句话职责 | 管 | 不管 |
|---|---|---|---|
| **模型循环** | 让一次 run 在预算内结束，并说清为什么结束 | 迭代次数、墙钟、重复调用、token 预算、终态归因 | 循环本体（MAF 承担）、对话质量 |
| **工具调用** | 决定「这次调用能不能发生」，发生了怎么记 | 白名单、审批、结果否决、轨迹、截断 | 工具的业务实现、ERP 适配器 |
| **上下文** | 把历史 / 本轮 / 指令 / 片段变成一次请求的消息形态 | 形态、预算、注入位置 | 检索、读库、业务语义 |
| **会话** | 让 run 之间的状态能存下来、下次接着用 | 存取、TTL、容量、降级 | 长期记忆（停用）、业务状态 |
| **任务执行** | 把「模型想做什么」变成「系统真的做了什么」 | 动作契约、四道校验、原语、幂等、审计 | 报告编排（v1 尾端）、真实 ERP 适配器 |

## 1. 模型循环（`Runtime.Loop`）

### 1.1 它负责什么

一次 run 的**刹车系统**：允许跑多久、跑几轮、什么时候判定跑偏。循环本体是 MAF 的 `FunctionInvokingChatClient`，本层只提供预算和守卫。

### 1.2 应该完成的功能

| 编号 | 功能 | 可观察结果 |
|---|---|---|
| **F1.1** | 迭代预算：限制工具调用轮次，到顶后模型被强制收口 | `status=iteration_limit`、`error_code=iteration_limit`；模型调用轮次 ≤ 上限 + 1；**不得** `succeeded` |
| **F1.2** | run 级墙钟：整轮超时抛 `AgentRunTimeoutException` | `status=timeout`、`error_code=run_timeout`；抛的是 `TimeoutException` 子类 |
| **F1.3** | 重复调用检测：连续「同工具 + 同参数」达上限即终止 | 在第 K 次调用**发出前**停，`status=loop_detected`；工具执行次数 = K−1，不是 K |
| **F1.4** | token 预算：本 run 累计用量越限即终止 | `status=budget_exceeded`；按 run 起点快照计算，不受进程历史用量影响 |
| **F1.5** | 终态可归因：8 个 `AgentRunStatus` × 对应 `AgentRunCode` | 同一 `status` 下不同原因不合并（`run_timeout` ≠ `model_timeout`） |
| **F1.6** | 取消：调用方取消即停 | `status=cancelled`；取消后不再发起新工具调用 |
| **F1.7** | 不自研循环 | Harness 用 `UseProvidedChatClientAsIs`；本层无驱动模型的 `while` 循环 |

### 1.3 怎么确认做到了

| 功能 | 验收方式 | 负控（改坏必须红） | 现状 |
|---|---|---|---|
| F1.1 | 脚本每轮都返回工具调用、上限设 2 → 断言 status / error_code / 轮次 | 删掉 `InspectCompletion` 的截断判断 | 实现有，**0 测试** |
| F1.2 | 每轮响应延迟 > 预算 → 断言 status 与异常类型 | 把超时归类改 `failed` | 实现有，**0 测试** |
| F1.3 | 连续 3 次同参调用 → 断言工具执行次数 | 去掉 `AgentRunGuard` 指纹 | 实现有，**0 测试** |
| F1.4 | 每轮返回固定 usage，累计越限 | 预算不累加（只判单轮） | 实现有，**0 测试** |
| F1.5 | 枚举全部终态，断言 `(status, code)` 两两不重复 | 两个 code 用同一字符串 | 实现有，**0 测试** |
| F1.6 | 第 2 轮前 cancel → 断言 status 与后续调用数 | 忽略 token 继续跑 | 实现有，**0 测试** |
| F1.7 | 结构断言 + F1.3 联动 | Harness 出现 `AIContextProviders` | 实现有，**0 测试** |

> F1.1 / F1.3 / F1.4 的验收需要工具环配合（守卫由环调用），属 §6 的集成验证；但**判据归属本项**，不随工具实现改动而变。

### 1.4 明确不做

自研循环（ADR 0016 §五 A4）、流式断线重连、对话质量优化（引用角标 / 拒答措辞是 v1 指标）。

## 2. 工具调用（`Runtime.Tools`）

### 2.1 它负责什么

模型与真实世界之间的**闸门**：工具在不在白名单、这次要不要问人、结果要不要拦住、每一步留下什么证据。

### 2.2 应该完成的功能

| 编号 | 功能 | 可观察结果 |
|---|---|---|
| **F2.1** | 工具目录：只暴露白名单内工具，按名去重 | 白名单外的工具模型**看不到**（不在 `GetTools()` 里），不是「看得到但调不动」 |
| **F2.2** | 审批三态：`Auto` 直接执行 / `Ask` 问人 / `Deny` 拒绝 | `IToolApprovalPolicy.Decision(tool)` 决定走哪条；`Deny` 不执行 |
| **F2.3** | fail-closed：`Ask` 无审批者、超时、通道故障一律拒绝 | 工具执行 0 次；轨迹 `error=approval_unavailable` |
| **F2.4** | 拒绝回填：被拒作为结果回填模型，模型可换路 | 模型收到结构化拒绝载荷；不重试同一调用；`error=approval_policy_denied` / `approval_user_denied` |
| **F2.5** | 结果否决：回填前可终止本轮 | 模型**只被请求 1 次**；`status=refused`；轨迹保留工具结果 |
| **F2.6** | 轨迹：每次调用记名、参数原文、结果、错误码、轮次 | 轨迹条数 = 调用次数；拒绝与失败在 `error` 上可区分 |
| **F2.7** | 异常归类：工具异常记 `tool_error` 并抛回 | `error` 含异常类型与消息；不静默吞成 `succeeded` |
| **F2.8** | **参数校验：调用前按 schema 校验** | **当前不存在**（`Validate` / `Schema` 零命中）；畸形参数直达执行体 |
| **F2.9** | **进入模型的结果有上界** | **当前不存在**：`MaxResultChars=400` 只截轨迹，模型拿到完整结果 |
| **F2.10** | **幂等键：只透传 / 记录，不生成不解析** | **当前不存在** |

### 2.3 怎么确认做到了

| 功能 | 验收方式 | 负控（改坏必须红） | 现状 |
|---|---|---|---|
| F2.1 | 注入一个白名单外工具 → 断言 `GetToolNames()` 不含它 | 去掉 `Where(IsAllowed)` | 实现有，**0 测试** |
| F2.2 | 三种策略各跑一次 → 断言执行次数 | 把 `Deny` 改 `Auto` | 实现有，**0 测试** |
| F2.3 | `Approver=null` / 超时 → 断言执行次数 + 错误码 | 默认放行（fail-open） | 实现有，**0 测试** |
| F2.4 | 拒绝后断言模型收到载荷、且发生第二次请求 | 拒绝后静默收口、不给模型机会 | 实现有，**0 测试** |
| F2.5 | 已有 3 条 Veto 用例 | 已覆盖 | ✅ **3 条绿** |
| F2.6 | 任一次多工具调用 → 断言轨迹字段齐全 | 不记 `Arguments` 原文 | 实现有，**0 测试** |
| F2.7 | 工具抛异常 → 断言 `error` 与 status | 异常吞掉记 `succeeded` | 实现有，**0 测试** |
| F2.8 | 缺必填 / 类型错 → 断言执行 0 次 | — | ❌ **功能缺失** |
| F2.9 | 工具返回 10 万字符 → 断言进入模型的内容长度 | — | ❌ **功能缺失** |
| F2.10 | 传入带业务含义的键 → 断言原样记录 | — | ❌ **功能缺失** |

### 2.4 明确不做

内置 MCP / ERP / PLC 适配器、通用连接器（正本 §2.3）、模型动态注册工具（ADR 0016 §五 B5）、写动作自动执行（B6）。

## 3. 上下文（`Runtime.Context`）

### 3.1 它负责什么

只做**消息形态与预算**：把调用方给的历史、本轮输入、指令、片段，整理成一次模型请求。不读库、不检索、不认识业务。

### 3.2 应该完成的功能

| 编号 | 功能 | 可观察结果 |
|---|---|---|
| **F3.1** | 组装产物三件：`Messages`（历史 + 本轮，不含 system）/ `Instructions`（指令 + 片段）/ `Fragments`（实际注入） | 三字段语义清晰，`Messages` 里没有 system |
| **F3.2** | 历史预算：取最近 N 条，本轮输入必须在内 | 超长历史被截断；最后一条 = 本轮输入 |
| **F3.3** | 片段预算：总字符 ≤ 上限，按序截断 | 注入内容长度 ≤ `MaxFragmentChars` |
| **F3.4** | 指令注入：system 进请求、**不进历史** | 多轮之后历史里指令 0 次，请求里 1 次 |
| **F3.5** | 关闭态：`Enabled=false` 零注入，且能力位同步 | 请求无 system；`GetCapabilitiesAsync().Context == false` |
| **F3.6** | 无注入时原样返回 | `Wrap` 返回同一实例（`ReferenceEquals`） |
| **F3.7** | 边界：不读库、不检索、无业务词 | `Runtime.Context` 命中 AC-02 禁词零次 |
| **F3.8** | 注入点是 `IChatClient` 装饰器，非 `AIContextProviders` | 源码不出现该属性；挂了会让守卫与轨迹被绕过 |

### 3.3 怎么确认做到了

| 功能 | 验收方式 | 负控（改坏必须红） | 现状 |
|---|---|---|---|
| F3.1 | 给定输入 → 断言三字段内容与边界 | 把 system 塞进 `Messages` | 实现有，**0 测试** |
| F3.2 | 20 条历史、上限 10 → 断言条数与首尾 | 截断保留最旧的 | 实现有，**0 测试** |
| F3.3 | 5000 字片段、预算 1000 → 断言注入长度 | 去掉裁剪 | 实现有，**0 测试** |
| F3.4 | 同 session 连跑 3 轮 → 断言指令出现次数 | 把指令写进 history | 实现有，**0 测试** |
| F3.5 | `Enabled=false` → 断言注入数与能力位 | 能力位固定 `true` | ❌ **当前假绿** |
| F3.6 | 空 bundle → 断言同一实例 | 无条件 new 装饰器 | 实现有，**0 测试** |
| F3.7 | AC-02 扫 `Runtime.Context` | 引入业务字段 | 实现有，**0 测试** |
| F3.8 | 结构断言 + F1.3 联动 | 改挂 provider | 实现有，**0 测试** |

> F3.5 现在就是红的：`GetCapabilitiesAsync` 直接返回 `_contextOptions.Value.Enabled`，默认 `true`，而 Harness 实际只做「本轮输入直接进模型」。

### 3.4 明确不做

RAG / 文档解析 / 权限过滤（知识层挂载）、引用角标与拒答判定（v1 指标）、智能摘要与自动压缩（ADR 0016 §五 B8：固定窗口 + 显式截断）。

## 4. 会话（`Runtime.Session`）

### 4.1 它负责什么

run 之间的**状态传递**：这次结束把状态存下、下次能取回。只做存取，不做理解。

### 4.2 应该完成的功能

| 编号 | 功能 | 可观察结果 |
|---|---|---|
| **F4.1** | get-or-create 幂等：命中返回已有，未命中用 `ISessionFactory` 新建 | 同 id 两次取到同一内容，存储里只有 1 条 |
| **F4.2** | TTL：空闲超 `SessionTtlMinutes` 过期（0 = 不过期） | 过期后再取得到**新**会话，旧内容不可读 |
| **F4.3** | 容量上限：进程内缓存 ≤ `MaxCachedSessions`（0 = 不限） | 超限时淘汰最久未用，总数不越界 |
| **F4.4** | 写回：内存版无副作用；落库版序列化后 UPSERT | 写完能读回，消息顺序与本轮一致 |
| **F4.5** | 降级：快照损坏 / 版本不识别 → 新会话，不抛 | 非法 JSON 不导致调用失败；有降级痕迹 |
| **F4.6** | 两臂同契约：内存版与 SQLite 版行为一致 | 同一套用例两套实现都过 |
| **F4.7** | 长期记忆应与 ADR 一致（停用不删） | `LongTermEnabled` 当前默认 `true`，与 ADR 0016 §五 A5 / B7 相反 |

### 4.3 怎么确认做到了

| 功能 | 验收方式 | 负控（改坏必须红） | 现状 |
|---|---|---|---|
| F4.1 | 同 id 调两次 → 断言内容与存储条数 | 每次 new | 实现有，**0 测试** |
| F4.2 | `FakeTimeProvider` 前进超 TTL | 关掉过期判断 | 实现有，**0 测试** |
| F4.3 | 超过上限 → 断言总数与淘汰对象 | 去掉淘汰 | 实现有，**0 测试** |
| F4.4 | 写后读 → 断言顺序与轮次 | 追加顺序倒置 | 实现有，**0 测试** |
| F4.5 | 落库写入非法 JSON | 去掉降级分支 | 落库版有，**0 测试** |
| F4.6 | 同一套用例跑两臂 | 改坏任一套 | **0 测试** |
| F4.7 | 读配置默认值 + 工具注册表 | 默认值改回 `true` | ❌ **与 ADR 相反** |

### 4.4 明确不做

长期记忆自动召回（A5 / B7）、跨会话画像、`Harness` run 层 checkpoint（属任务执行 F5.4）。

## 5. 任务执行（`Runtime.Orchestration` + 待建 `Core/Ports` / `Domains/Erp`）

### 5.1 它负责什么

在 v3 里「任务」= **动作**，不是「问答 + 报告」。这一层要把模型输出变成受控的外部动作：能拦、能重复提交不出双单、能追回。

> 现状：`Workflow` 里的 `answer → report` 两步编排是 v1 知识工作台的尾端，**不属于本项**。本项所需的三类型、网关、原语在仓内均不存在。

### 5.2 应该完成的功能

| 编号 | 功能 | 可观察结果 |
|---|---|---|
| **F5.1** | 动作契约：`ActionSpec` / `ActionRequest` / `ActionResult` + `SideEffecting` | 参数对底座是不透明 JSON；`Draft` 标可重复，`Submit` 标必登记 |
| **F5.2** | 四道校验：schema → 权限 → 业务规则 → 审计 | 任一道不过即停，外部调用 0 次；默认实现**全部拒绝** |
| **F5.3** | 四原语：Query / Draft / Submit / Cancel | `Draft` 连调两次不产生两张单；`Submit` 幂等 |
| **F5.4** | 挂起 → 人批 → 恢复，`Harness` run 层 checkpoint | 中断后恢复，已完成的写动作不重放 |
| **F5.5** | 幂等：同 `request_id` 只一次副作用 | 外部只发生 1 次；第二次返回首次结果 |
| **F5.6** | 超时只查证：记「执行中」并发起 Query，不重放 | 写调用次数不变；查不到转人工 |
| **F5.7** | 审计五字段：意图 / 参数 / 审批人 / 结果 / 外部单号 | 任取一笔能反查出「谁、何时、看到什么、依据哪条规则、外部变成什么」 |
| **F5.8** | 假 ERP：四原语的内存实现 | 同时是单测装置与换域演练的载体 |

### 5.3 怎么确认做到了

| 功能 | 验收方式 | 负控（改坏必须红） | 现状 |
|---|---|---|---|
| F5.1 | 反射断言类型与标志；AC-02 扫底座 | 在底座类型里写业务字段 | ❌ **不存在** |
| F5.2 | 四道各失败一次 → 断言外部调用数 | 任一道默认改放行 | ❌ **不存在** |
| F5.3 | 四原语各跑一次，Draft 连调两次 | Draft 产生副作用 | ❌ **不存在** |
| F5.4 | checkpoint 后重建 → 断言写动作次数 | 恢复时重跑已完成步骤 | ❌ **不存在**（Workflow 层有，Harness 层无） |
| F5.5 | 同 `request_id` 连打两次 | 去掉去重表 | ❌ **不存在** |
| F5.6 | 适配器先超时后成功 | 自动重放 | ❌ **不存在** |
| F5.7 | 任取一笔反查五字段 | 删任一字段 | ❌ **不存在** |
| F5.8 | 四原语可跑 + 换域演练 | 写死一个字段名 | ❌ **不存在** |

### 5.4 明确不做

真实 ERPNext 适配器（M2/M3）、`answer → report` 报告编排（v1 尾端）、第二个真实动作域（正本 §2.3）、把审批层级 / 金额档位写进底座（ADR 0017 §四）。

## 6. 跨模块验收（不属于任何单项）

## 7. 前置装置（阻断项）
