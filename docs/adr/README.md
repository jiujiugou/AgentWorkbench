# 架构决策记录（ADR）

一个决策一篇，写完不改。改主意就写新的一篇，旧的标 `Superseded by 00NN`。

## 什么时候写

**写**：这个决定重提起来会疼、改了会牵动别处、半年后有人会问"当初为什么这样"。

**不写**：参数级取舍（轮询间隔、请求写法）、一眼能看出来的选择、随时可改的实现细节。这些留在设计文档的「取舍登记」里。

判据一句话：**如果这个决定被推翻时要重写别的文档，它就够格进 ADR。**

## 模板

```markdown
# ADR 00NN · 一句话结论

- **状态**：Proposed / Accepted / Superseded by 00NN
- **日期**：YYYY-MM-DD
- **机制**：见 某设计 §x.y  ← 只给指针，不复制规则

## 背景
当时的约束、要解决的问题。写清"不这样会怎样"。

## 决定
做了什么。一句话能说清最好。

## 后果
好处 / 代价，成对写。只写好处的是宣传，不是 ADR。

## 什么情况下该重开
给出可观测的条件，不是"以后再说"。
```

**15 分钟写不完就是写错了**——说明你在里面写机制，应该挪回设计文档。

## 编号规则

- 全局连续编号，不按域分号。ADR 是时间线，不是目录。
- 编号一旦分配不再复用，即使那篇被取代。
- **不写机制**。任何"怎么实现"的内容属于设计文档，这里只留 `机制见 §x`。

## 与设计文档的分界（谁说了算）

ADR 与设计文档会写同一件事——这是**有意的**，但必须指定谁赢，否则两份"决定"迟早分岔。

| 内容 | 谁写 | 谁说了算 |
|---|---|---|
| 规则本身（怎么实现、状态怎么转换、事务边界） | 设计文档 | **设计文档**。ADR 里的「决定」段是决策的**历史快照**，可能与现状不一致 |
| 为什么这么定、放弃了什么、什么条件下重开 | ADR | **ADR**。设计文档不重复论证，只给结论 |
| 字段、端点、错误码 | 接口契约 | 接口契约 |

**判据**：ADR 的「决定」段允许与设计文档不一致（它记录的是当时），但**不一致就必须二选一修**——要么补一篇新 ADR 说明改主意了，要么说明设计文档写错了。**不允许长期并存两种表述。**

### 改设计正文里的规则，什么时候必须补一篇 ADR

| 情形 | 要写新 ADR 吗 |
|---|---|
| 改了被 ADR 锁住的不变量或决策（设计 §7.1 有映射表） | **必须**。先写新篇说明旧依据为何不成立，旧篇标 `Superseded by 00NN` |
| 改了参数级取舍（轮询间隔、上传写法） | 不用，改设计「取舍登记」即可 |
| 只是把同一决定的表述写得更清楚 | 不用 |
| 发现设计文档本来就写错了、ADR 才是对的 | 不用新 ADR，但要修设计——ADR 是当时决策的记录，它没写错 |

**一句话**：**ADR 锁的是"结论"，不是"文字"。** 换个说法不算改决定；改结论必须留痕。
