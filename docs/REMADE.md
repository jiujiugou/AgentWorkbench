## 4. 改造路线

三个阶段，每个阶段有一个**可验证的完成标志**。没有标志的阶段不算完成。

### 4.0 分界原则：切「归属 / 身份 / 隔离」三件事

原始想法是"先做单用户、再做多用户"。方向对，但**不能按这个字面去切**——因为代码已经走到中途：`ConversationRepository` 的五个方法**已强制带 `tenantId` / `userId`**，`AgentHub` 已在传，`FallbackPolicy` 已默认拒绝。

按"单用户"去切，意味着把这些退成无参签名，将来再改回来 —— **两次白改，中间还会丢掉已写好的越权校验**。

所以要把三件事分开：

| | **归属**（数据属于谁） | **身份**（你是谁） | **隔离**（你能看什么） |
|---|---|---|---|
| **阶段 1** | 有参数，**值由固定回落给出** | **不做** | 不生效、不测试 |
| **阶段 2** | 有参数，值来自真实登录 | **Identity 一次做对** | 生效，且必须有测试 |

**一句话：阶段 1 保留归属的"形"，不建身份的"实"。**

> **阶段 1 的硬规矩**：写查询时继续带 `tenantId` / `userId`（值来自固定回落），**不许图省事删掉**。
> 留着它，阶段 2 只是"把固定值换成登录值"；删掉它，阶段 2 要重走一遍签名改造。
> 这条成本为零，是让阶段 1 不给阶段 2 挖坑的唯一一条设计约束。

**为什么身份整域后移，而不是"先做个简单登录"：**

现有手写认证（`PasswordHasher` + 手工 Cookie）技术上能跑，但它的**每一项在 Identity 进来后都要重写**——密码哈希要升级、Cookie 签发要换成 `SignInManager`、`IsActive` 校验要挪进 `OnValidatePrincipal`、claim 生成要换成 `UserClaimsPrincipalFactory`。

**现在做一遍登录页和 Cookie 契约，等于为还不存在的框架预写一遍，之后改第二遍。** 而身份的全部收益（锁定、停用即时生效、改密失效、成员管理）**只在多用户下才有意义**——单用户时一条都验不出来。

> 所以顺序是：**功能域先做完，身份一次做对。** 这也解释了为什么切分比预想的干净：阶段 1 恰好是 REQ-04~22（全部业务需求），阶段 2 恰好是 REQ-01~03 + AUTH-01~11（全部身份需求）。


### 4.1 三个阶段 × 六个功能域

阶段 1 只做 **F2–F6**；**F1 整域后移到阶段 2**，与 Identity 一起落地。

| 域 | 阶段 1（单用户维度） | 阶段 2（身份 + 隔离） | 阶段 3 |
|---|---|---|---|
| **F1 身份与访问控制** | **不做**（只留一个固定归属的技术前提） | 登录、成员、隔离、账户行为、**Identity 落地** | — |
| **F2 知识资料管理** | 上传 / 状态 / 删除 | 加归属列 + 检索两路过滤 | — |
| **F3 知识问答** | 检索 / 引用 / 拒答 | 按权限检索与作答 | — |
| **F4 Agent 执行（写侧）** | 记录 / 步骤 / 状态 / 停止 / **无后门** | 记录带归属、按权限查 | — |
| **F5 会话与执行记录（读侧）** | 列表 / 续聊 / 轨迹 / **引用落库** | 会话隔离（404 不 403） | — |
| **F6 服务端能力** | curl 闭环 / 断连 / 错误体 / 模型配置 | 错误反馈不泄露跨团队数据 | — |
| **交付面**（不按域） | — | — | 指标 / 备份 / 真实负载 |

**读法**：阶段 1 结束时，**F2–F6 各有一个"单用户下成立且可验收"的版本**；阶段 2 结束时，F1 补齐并给其余五域各加一个"隔离成立"的版本。

> **为什么 F1 整域后移**：Identity 尚未引入，此时打磨登录页、Cookie 契约、账户行为（锁定 / 停用 / 改密失效）都是**为还不存在的框架做准备**。这些能力现在写一遍、引 Identity 后再改一遍，等于白做两次。**功能域先做完，身份一次做对。**

### 阶段 1：单用户把 F2–F6 各走通一遍

**一条闭环判据**（五个域串起来的一句话）：

> 打开系统 → 传一份 PDF → 问一个只有它有答案的问题 → 看到引用 → 展开轨迹 → 关浏览器重开，三样都还在 → 同样的事用 `curl` 也能做完。

| 域 | 阶段 1 要做 | 覆盖 REQ | 完成标志 |
|---|---|---|---|
| **F2** | 上传 PDF；处理状态可见；删除并清理索引与派生内容 | REQ-05、REQ-06、REQ-10 | 传一份真实 PDF，状态从"处理中"变"可检索"；删掉后同一问题**检索不到它** |
| **F3** | 检索；带引用作答（文档名 + 位置 + 原文片段**三者齐全**）；无证据时明确说"资料里没有" | REQ-07、REQ-08、REQ-09 | 问一个只有该 PDF 有答案的问题 → 三要素齐全；问一个库里没有的问题 → **明确拒答，不编** |
| **F4** | 执行记录 / 步骤 / 状态（含取消与终止原因）；停止；**补掉审计后门**——`POST /api/knowledge/ask` 改走 harness | REQ-11、REQ-12、REQ-13、REQ-16 | 每次问答都有 run；故意停一次 → 状态是"已取消"而非"失败"；**三个入口**（同步 REST / Hub 流式 / knowledge ask）都能查到轨迹 |
| **F5** | 会话列表 + 续聊；轨迹可见（`RunTrace` 已有）；**引用与 run 落库** | REQ-04、REQ-14、REQ-15、REQ-21 | 关浏览器重开：答案、引用、轨迹都在，且能说出"这条回答来自哪次 run" |
| **F6** | 用 `curl` 走完整个闭环；按 `runId` 查状态；断连容忍；错误体统一；模型配置可用 | REQ-17、REQ-18、REQ-19、REQ-20（仅前半"明确稳定"）、REQ-22（已有） | 关掉前端，用 `curl` 完成一次问答并拿到 `runId` 与轨迹；发完问题立刻断连，重连能查到结果 |
| — | 空库部署验证 | — | 干净目录起一遍，从上传走到出答案，全程无手工 SQL |

**唯一的技术前提（不是功能，是脚手架）**：

> 现在 `FallbackPolicy = RequireAuthenticatedUser` 已生效，而 `CurrentUser.Owner()` 在缺 Claim 时会抛异常 —— **不做身份，F2–F6 一行都跑不起来**。
>
> 阶段 1 的处理：**不建登录页、不改鉴权逻辑**，只在归属取值处加一个**固定回落**（取不到 Claim 时用配置里的种子归属）。这是 10 行脚手架，不是功能：
>
> - 不写进任何功能域的验收
> - **阶段 2 引 Identity 时必须删掉**，标记为 `// TODO(stage2): 移除匿名回落`
> - 启动日志显式 WARN 一行"鉴权未强制，归属为固定值"——否则半年后会有人以为这是设计

**阶段 1 明确不做**（按域列，避免"顺手做了但没人验收"）：

| 域 | 不做 | 为什么 |
|---|---|---|
| **F1** | **整域**：登录页、Cookie 契约、成员管理、账户行为、隔离、Identity | Identity 未引入，现在做等于为还不存在的框架预写一遍，之后要改第二遍 |
| F2 | 文档级权限 | 已在 P1 之外（见功能需求 §4.0 的范围收窄） |
| F3 | 跨团队检索限制 | 只有一份知识库 |
| F4/F5 | 按权限查记录、列表过滤 | 只有一个归属，过滤结果恒等于全量 |
| F6 | REQ-20 后半句"不得泄露**其他团队**数据" | 没有其他团队 |

> **唯一被拆开的需求是 REQ-20。** 阶段 1 做前半"错误信息明确、稳定"，阶段 2 加后半"不泄露跨团队数据"。**其余需求整条归属某一阶段，不拆开**——拆需求会让"验收通过"变成一句无法判断的话。
>
> **账目（切分比原先更干净）**：阶段 1 = **REQ-04 ~ REQ-22 共 19 条**（全部业务需求）；阶段 2 = **REQ-01、REQ-02、REQ-03 + REQ-AUTH-01 ~ 11 共 14 条**（全部身份需求）。19 + 14 = 33 条全覆盖，无遗漏、无重叠。
>
> 换句话说：**阶段 1 是"业务域的完整版"，阶段 2 是"身份域的完整版 + 业务域加隔离"**。

> ⚠️ **阶段 1 的验收清单里不许出现隔离类判据。**  
> 单账号下它必然通过，那不是"做对了"，是"没有失败的机会"。  
> 这和当初 `HarnessConversation` 自己补 user 消息导致 `NonEmpty` 恒真是同一类错误：**判据存在，但失去区分度。**  
> 隔离类判据统一标注"阶段 2 验收"，**不计入阶段 1 的完成定义**（清单见 [用户管理/验证方式.md](验证与现状/用户管理/验证方式.md) §2.1）。

### 阶段 2：补上 F1（身份）并给 F2–F6 加"隔离"这一维

**这一阶段的入口是 Identity 落地**：登录页、Cookie 契约、`AspNetUsers`、`UserClaimsPrincipalFactory` 全在这里一次做完，不分成两刀。

| 域 | 阶段 2 加什么 | 覆盖 REQ | 完成标志 |
|---|---|---|---|
| **F1** | **身份本身**：登录页 / 路由守卫 / Cookie 契约 / Identity 落地 / 团队与成员管理 / 账户行为；以及四项隔离 | REQ-01、REQ-02、REQ-03、REQ-AUTH-01 ~ 11 | 两个账号能各自登录；管理员能加人；**两个团队各传一份文档，互相检索不到** |
| **F2** | `documents` / `chunks` 补归属列；检索两路（字面 + 向量）都按归属过滤 | REQ-AUTH-04、REQ-07 | 同一问题，A 团队能命中自己的文档，B 团队命中空 |
| **F3** | 检索与作答遵守权限；**不得因模型能推断就绕过** | REQ-AUTH-04、REQ-09 | 用 B 的账号问 A 文档里的内容 → 拒答而不是"猜出来" |
| **F4** | `agent_runs` / `agent_steps` 补归属；按权限查询 | REQ-AUTH-05、REQ-11、REQ-14 | A 查不到 B 的任何 run；含输入、证据、工具参数 |
| **F5** | 会话四路（列表 / 读取 / 删除 / 续聊）按归属校验；跨租户返回 **404 而非 403** | REQ-AUTH-03、REQ-04 | A 拿 B 的会话 id 直取 → **404**，且原数据未被修改 |
| **F6** | 错误反馈不泄露跨团队数据与凭据 | REQ-20 后半句 | 越权请求的错误体里**不含**任何他人数据的痕迹 |
| — | **删掉阶段 1 的匿名回落脚手架** | — | `Owner()` 在缺 Claim 时重新抛异常，且这条有测试守着 |
| — | 存量数据归给种子账号 | — | **983 行**（文档 64 / 页 390 / 片段 438 / 消息 34 / 会话 10 / run 15 / step 23 / session 9）一次迁移完毕 |
| — | 隔离测试 T 组 + 门禁自证 | — | 临时移除归属过滤后，这些测试**必须变红** |

**完成标志**：两个账号各传一份文档，互相检索不到；A 用 B 的会话 id 直取，得到 404 而不是内容。

**为什么存量数据不是障碍**：那 983 行全部属于同一个人，`ALTER TABLE ADD COLUMN ... NOT NULL DEFAULT '<种子租户>'` 一次就能补齐。**不需要产品决策，不需要人工分类。** 之前"先写数据后加隔离会很痛"的警告在单人场景里被高估了。

## 5. 现在卡在哪

**卡在一件很小但绕不开的事：鉴权门是关着的，而阶段 1 不做身份。**

```
任意请求 → FallbackPolicy 要求已登录 → 无 Cookie → 401
                ↓
        CurrentUser.Owner() 取不到 Claim → 抛异常
                ↓
         F2–F6 没有一个域能验收
```

**这不矛盾，是排期顺序带来的必然。** 处理方式**不是**补登录页（那是阶段 2 的事），而是加一个 10 行的**固定归属回落**——取不到 Claim 时用配置里的种子归属，让五个域能跑通。

三条纪律：

1. 标记 `// TODO(stage2): 移除匿名回落`，它是**脚手架不是功能**
2. 启动日志 WARN 一行"鉴权未强制，归属为固定值"——否则半年后有人以为这是设计

## 6. 三条原则

1. **需求是唯一源头。** 设计、接口、验证、运维都只能引用，不能重新定义。
2. **每份文档开头写清"已知的漂移点"。** 主动承认哪里已经不对，是文档能活下去的唯一办法；否则文档只会两极分化——没人看，或者看了被坑。
3. **没有完成标志的阶段不算完成。** "差不多做完了"是判断力最容易失守的地方，所以每个阶段都要有一句能拿出去核对的话。
