# 文档模板：core 部件的重做要求

- **适用侧**：公共 ｜ **寿命**：常驻 ｜ **最后校准**：2026-11-24
- **适用**：`docs/core/` 下的 Architecture（解释型）文档，以及同等粒度的部件文档重做
- **不适用**：`docs/kb/` 的机器事实层、`docs/plans/` 的过程记录、正本与 ADR
- **性质**：协作规范，不是事实源。它规定文档怎么写，不规定系统怎么跑，也不记录任何一篇文档的当前状态

> 这份文件回答一个问题：一篇部件文档重做到什么程度算做完。
>
> 它只写要求与判据。哪篇文档现在多少行、哪一节讲了什么，属于那篇文档自己的事，不进这里。

本文为什么存在：没有它的时候，同样骨架的两篇文档，一篇读完能接手，另一篇读完要查表。差别不在章节齐不齐，在下面这几层。

## 1. 骨架：八节，每节只干一件事

| 节 | 回答什么 | 收口方式 | 什么内容归这里 |
| --- | --- | --- | --- |
| 1 整体模型 | 由哪几块组成、怎么串、谁负责 | 本格不管什么，推给别的部件 | 全景图、职责表、入口与出口 |
| 2 机制展开 | 按真实顺序逐步讲，每步答「为什么在这、不这样会错成什么」 | 本阶段契约 | 在主链上按顺序发生的事 |
| 3 特殊约束 | 不在主链上但必须讲的 | 一句话边界 | 横切的另一层机制、外部依赖、硬边界 |
| 4 故障处理 | 按失败类型，不按子系统重讲 | 缺口登记 | 每种失败后状态变成什么、谁能继续 |
| 5 配置 | 默认值往哪倒、数值各自归谁 | 为什么这么倒 | 只有取值和方向，没有流程 |
| 6 验收 | 契约表 + 证据限制 + 本部件算通过的标准 | 缺口不藏 | 契约、证据强度、人的验收清单 |
| 7 未决 | 现在靠什么假设、将来换不换 | 假设与未决定分开 | 还没定的决定 |
| 8 系统关系 | 与其他部件谁负责什么 | 回扣开篇命题 | 边界表、共用数值归属 |

**节的准入判据只有一句话**：在主链上按顺序发生 → 第 2 节；不在链上但影响主线 → 第 3 节；只是取值 → 第 5 节。

判据比顺序重要。顺序能照抄，判据决定一段内容该放哪——放错节，读者会在两节里读到同一件事，然后开始跳读。

典型的分节错误是把横切机制塞进流程节：它和主链共用同一批动作，但生效范围跨过整条链，混在流程里讲不清「它和主链上那道检查不是同一件事」。这类内容归第 3 节。

**短文档可以合并节，但不能缺第 1 节和第 6 节。** 这两节是承重墙：没有整体模型，读者不知道自己在看哪一块；没有验收，写完不知道算不算完成。

## 2. 节内：每个子节走同一个五步

1. **是什么**——机制形状，一句话说清它在做什么。
2. **为什么定成这样**——不这么定会出什么问题。
3. **反过来做会错成什么**——一个具体画面，不是抽象后果。
4. **边界**——它不负责什么。
5. **证据**——有判据就写结论，没有就登记 gap。

以「先记录、后校验」这类子节为例：建立一条未完成记录（是什么）→ 被拦下也意味着这次请求确实发生过（为什么）→ 只给成功的那次留记录，事后就说不清系统曾经拒绝过什么（画面）→ 记录的是请求意图，不是执行成功事实（边界）。

五步不必分小标题，但缺了第三步就退化成「规则 + 理由」。**没有画面，读者记不住；没有边界，读者会误以为它能管更多。**

## 3. 衔接：每节末把问题交给下一节

判据：读者读完这一节，应该自然产生下一节要回答的那个问题。如果第 N 节的结尾和第 N+1 节的开头之间没有这句话，中间就断了。

交接有两种写法，都合格：

- **把边界推出去**：本节只管到某处，那之外的事归别的部件——下一节接着讲后者。
- **把矛盾留下来**：本节的做法在某个条件下会失效，下一节处理那个条件。

不合格的是第三种：两节之间只靠标题并列，读者要靠自己猜为什么从这里讲到那里。

**反例：换皮。** 节标题齐全、契约齐全、证据齐全，但节与节之间没有承接——读起来是查表，不是读下来。把旧结构的内容重新分栏，标题变了，推导链没变。

## 4. 图与表：按内容形状选，不按版面好看选

| 内容形状 | 用什么 |
| --- | --- |
| 顺序步骤 | 流程图（竖排，每步一行） |
| 分支与出口 | 分支图（成功一路、异常一路） |
| 多方交错 | 并列图（两个主体并排） |
| 纯概念对比 | 表 |
| 都没有 | 可以纯文字，但每条主张必须带失败画面 |

**图必须承载信息。** 判断标准：把图删掉，读者会不会少知道一件事。会，就留；不会，那是装饰。

**顺序、分支、多方交错这三类内容，缺图就是不合格**——不看图文比的数字。反过来，纯概念节也不要为凑比值硬画，那就是装饰图。比值只用来发现「整节都在用文字讲流程」这种失衡，不用来逼人加图。

流程图常见的失效是只画动作不画对象：每一步只有动词，读者知道顺序，但不知道这一碰的是哪份数据、它活多久。补法是每一步旁边标出作用对象及其生命周期——一张图同时回答「什么时候」和「对谁」。

纯概念节允许图文比低。三份并列的数据、三条互斥的边界，没有流程可画，用一张对比表替代即可，不按第 5 节的度量扣分。

## 5. 度量：两个下限，一个不设

| 指标 | 要求 | 为什么 |
| --- | --- | --- |
| 图文比（图行 : 文字行） | ≥ 0.5 | 低于这个值，说明有大量纯文字解释没有落到画面 |
| 中位段长 | ≥ 70 字（排除引导句） | 低于这个值，说明是一句一段堆出来的，读起来碎 |
| 总行 | **不设目标** | 同样八节，内容量差一倍，行数就差一倍 |

**引导句不计入段长。** 以冒号结尾、后面紧跟图 / 表 / 列表的短句（「三条判断：」「本节该验的四件事：」）是结构的一部分，它本来就该短。把它算进段落长度，会系统性拉低中位数，反过来逼着人把引导句和后面的表揉成一句长话——那是为指标服务，不是为阅读服务。

**图文比不是主判据。** 图该不该有，先看第 4 节的形状表。比值只有 0.5 这个下限，是因为「纯文字讲流程」的节通常比值很低；比值正常的节不代表图对，比值低的节也不一定缺图。

**总行不能设目标，一设就会注水。** 行数由内容决定，不由模板决定。

**度量是体检指标，不是 KPI。** 它可以做进检查脚本的提示输出，但不能 FAIL。文档不做功能、不驱动门禁——把可读性做成硬门禁，下一步就是为过门禁拆段落，那正好是反效果。

基线不写进本文。要校准时，取同目录里已经立住的那几篇现算，写完再算一次自己的，横向比。写死数字会让模板跟着文档一起过时。

## 6. 不合格的样子

比正面要求更有用，因为照着要求填也会掉进这几个坑。

**换皮。** 节标题齐了，内容还是旧结构重排。判据：把标题遮住，读者还能不能看出新的推导顺序。

**查表式。** 每一节都是表格和清单，读下来不像话。判据：连续读三节，能不能不回头看。

**注水。** 为了达到行数或图文比，加解释、拆图、重复同一判断。判据：删掉这一段，读者会少知道一件事吗。

**假绿。** 把「有测试」写成「已证明」。判据：这条结论在测试失败时会不会变。不会变，说明它写的是存在性，不是验证结果。

**装饰图。** 图只是把文字又画了一遍，删掉不影响理解。

**引用他篇当前状态。** 正文里写「某篇文档第几节如何」「某处现在是多少行」。这类内容会随那篇文档一起变，写进来的那一刻就开始过时。

## 7. 剔除：事实不进正文

以下内容留在 `docs/kb/documents/*.toml` 与 `docs/kb/contracts/*.toml`，正文一个都不写：

- 文件名、类名、方法名、字段名
- 配置实际值与代码默认
- 依赖版本
- 测试文件路径、用例名、测试数量
- 预设变异点

正文只留两样东西：**判断**，和**判断背后的失败画面**。

这条不能反过来做——正文里写着「某处代码在某个文件某个位置」，改一次代码就要改一次文档，而文档永远改不及时。事实交给能机器对账的地方，正文只解释为什么这么定。

## 8. 流程：先骨架，后正文

重大改写（迁骨架、重排节、换主轴）必须分两步：

1. **先出节标题 + 每节第一句**，给作者看结构。
2. 认可后，再填内容。

理由是代价不对称：写完全文才被否，返工是整篇重写；先看十几行骨架被否，返工只是改标题。

**结构判断归作者，素材核实归写作者。** 穷举代码、测试、配置、TOML 可以自动化；「按什么顺序讲」不能。

## 9. 自检：八问

写完对着这八条问一遍，任何一条答不上就还没做完。

1. 遮住节标题，还能看出这是新的推导顺序吗？
2. 每一节末尾有没有一句话把问题交给下一节？
3. 每条主张有没有配一个具体失败画面，而不只是「否则会有问题」？
4. 每个子节说清了自己不负责什么吗？
5. 图文比和中位段长够吗？总行有没有被当成目标？
6. 有没有把测试存在写成验证通过？
7. 事实、用例名、配置值、他篇当前状态，正文里还有残留吗？
8. 第 6 节的「本部件算通过的标准」，能不能独立于契约表回答「这格做完了吗」？
