# P4 工作流（Workflow Loop）· 验收标准（可执行版）

> 对应设计：`../设计步骤/P4工作流.md`
> 判定原则：每条给出**可复核证据**（脚本结果 / 接口返回）。**全部自动化**，不含人工抽样、不含 LLM-as-judge。
> 依据：`../测试标准/Agent-测试与验收标准.md`（**能由脚本/程序判定的，绝对不用 AI**；LLM 步骤用 **mock 模型 + record-replay** 确定性化）。

## 0. 判定方式说明

| 标记 | 含义 |
| --- | --- |
| **自动** | 由 `scripts/acceptance-p4.ps1` 断言，给出 PASS/FAIL |
| **度量** | 由 `scripts/eval-p4.ps1` 程序计算指标 + 阈值门禁 |

> Workflow 的步骤顺序、状态机、单步重跑范围、重试/超时/取消、检查点/恢复、提示词版本、级联、幂等**全部程序判定**（用 mock 驱动 LLM 步骤）。

## 1. 功能验收（判定型）

| 编号 | 标准 | 判定 | 阈值 / 断言 | 证据 |
| --- | --- | --- | --- | --- |
| W1 | 能力健康 | **自动** | `/api/workflow/health` 返回 `workflow=true` 且 `steps` 含 extract/compare/agent/report | 脚本输出 |
| W0 | 创建并流转 | **自动** | `POST /api/workflow/runs` 返回 202；轮询终态 `succeeded` | 脚本输出 |
| S1 | 步骤定义与顺序 | **自动** | 步骤按定义 `order_index` 执行；每步 `step_type` 与定义一致 | 脚本输出 |
| S2 | 步骤状态落库 | **自动** | 每步有 `status/attempts/started_at/finished_at`；产物摘要非空（成功步） | 脚本输出 |
| SR1 | 单步重跑 | **自动** | `rerun` 后仅该步重算，**其后步骤全部 `stale`** 并重算；之前的步骤状态不变 | 脚本输出 |
| PV1 | 提示词版本化 | **自动** | 版本可持久化/列出/设为 active；运行时固定 `prompt_version` 落库；切换版本后步骤使用新版本 | 脚本输出 |
| RT1 | 失败重试 | **自动（mock）** | mock 令某步前 N-1 次失败 → 按 `maxAttempts` 重试至成功；`attempts` 与轨迹一致 | 脚本输出 |
| TO1 | 步骤超时 | **自动（mock）** | mock 令步骤超时 → 该步 `failed`、run `failed`、`error` 非空、**不挂起** | 脚本输出 |
| CN1 | 取消 | **自动（mock）** | `POST /cancel` → 当前步 `cancelled`、run `cancelled`，不挂起 | 脚本输出 |
| CP1 | 检查点 / 断点续跑 | **自动** | 中途中断后 `POST /resume`：**已成功步骤不重算**，从首个非 `succeeded` 继续至 `succeeded` | 脚本输出 |
| PS1 | 进度完整 | **自动** | 每步至少一条进度事件；事件 `stepKey/status` 与最终步骤状态一致 | 脚本输出 |
| D1 | 删除级联 | **自动** | 删文档后 `workflow_runs` / `workflow_steps` 全消失 | 脚本输出 |
| RR1 | 整跑幂等 | **自动** | 重跑后终态 `succeeded`；步骤行数按 run 重建（不翻倍）；产物行数稳定 | 脚本输出 |
| AG1 | P3 托管不回归 | **自动** | `agent_step` 托管 P3 后 `scripts/acceptance-p3.ps1` 仍 **24/24 PASS** | 脚本输出 |

## 2. 度量验收

| 编号 | 标准 | 判定 | 阈值 | 证据 |
| --- | --- | --- | --- | --- |
| M1 | 步骤成功率 | **度量** | 正常样本步骤成功比例 **= 100%** | `eval-p4` 报告 |
| M2 | 断点恢复正确率 | **度量** | 恢复运行与整跑产物一致比例 **= 100%** | `eval-p4` 报告 |
| M3 | 单步重跑重算范围 | **度量** | 重跑步的下游失效率 **= 100%**，上游失效率 **= 0%** | `eval-p4` 报告 |
| M4 | 幂等稳定性 | **度量** | 重跑前后 `workflow_steps` / 产物行数 **不变** | `eval-p4` 报告 |

> 指标均为**程序计算**（对照 `tests/benchmark/p4/golden/`），不调用模型做判断。

## 3. 负控（红队）——必须存在，且必须"会失败"

| 编号 | 负控输入 | 判定 | 期望结果 |
| --- | --- | --- | --- |
| N1 | 非法 `runId` | **自动** | `GET/POST /runs/{id}/*` 返回 `404` |
| N2 | 文档不存在 / 未解析成功 | **自动** | `POST /runs` 返回 `404` / `400`（documentId 缺失或未就绪） |
| N3 | 未知 `stepKey` | **自动** | `rerun` 返回 `404` |
| N4 | 未知提示词版本 | **自动** | `POST /runs`（带非法 version）返回 `400` |
| N5 | 某步必然失败 | **自动（mock）** | run 终态 `failed`、`error` 非空、**不挂起** |
| N6 | 重试耗尽 | **自动（mock）** | 步骤 `attempts = maxAttempts` 后 `failed`，不再重试 |
| N7 | 同一 run 并发二次触发 | **自动** | 第二次被拒绝/幂等（同一 run 单执行），状态不脏 |
| N8 | 恢复时重复执行已完成步骤 | **自动** | `resume` **不重算** 已 `succeeded` 步骤（`attempts` 不变） |
| N9 | 未配置模型时的 `agent_step` | **自动** | 该步明确失败/降级，run 有终态、`error` 非空，**不挂起** |

## 4. 测试集

- 复用：`tests/corpus/`、`tests/benchmark/p2/negative/`、`tests/benchmark/p3/`、`tests/fixtures/llm/`。
- 新增 `tests/benchmark/p4/`：
  - `golden/`：≥1 份合同的**工作流金标**（步骤顺序 → 期望状态/产物），供 M1/M2/M3。
  - `negative/`：某步必失败 / 超时 / 重试耗尽 / 未知版本。
  - `prompts/`：≥2 个提示词版本，供 PV1 切换。
- 本地 mock：沿用 `src/AgentWorkbench.MockLlm`（如需新增"步骤失败/超时"动作在 `tests/fixtures/llm/` 增场景），**不得调用真模型**。

## 5. 自动化脚本

```powershell
# 判定 + 负控（构建 → 清库 → 起 mock+服务 → 跑 → 停）
powershell -ExecutionPolicy Bypass -File scripts/acceptance-p4.ps1
# 指标（步骤成功率 / 恢复正确率 / 重跑范围 / 幂等）
powershell -ExecutionPolicy Bypass -File scripts/eval-p4.ps1
```

- 断言：W1/W0/S1/S2/SR1/PV1/RT1/TO1/CN1/CP1/PS1/D1/RR1/AG1 + N1–N9。
- 全部用 **mock** 确定性判定，不依赖真模型。
- 退出码：全过 `0`；有 FAIL `1`；环境/前置失败 `2`。
- 输出：每个断言 PASS/FAIL 与明细；`eval-p4` 输出 `tests/benchmark/p4/report.json`。

## 6. 放行判定

- **自动**：W1/W0/S1/S2/SR1/PV1/RT1/TO1/CN1/CP1/PS1/D1/RR1/AG1 全 PASS + N1–N9 全 PASS。
- **度量**：M1/M2/M3/M4 达标。
- **回归**：`scripts/acceptance-p3.ps1` 仍 24/24（AG1）。
- 同时满足 → **P4 通过**。
