# 工作流（Workflow Loop）· 验收标准（可执行版）

> 对应设计：`../设计步骤/P4工作流.md`
> 判定原则：每条给出**可复核证据**（接口返回 / 源码位置）。**全部程序判定，不含人工抽样、不含 LLM-as-judge。**
> 依据：`../测试标准/Agent-测试与验收标准.md`（**能由脚本/程序判定的，绝对不用 AI**；LLM 步骤用 **mock 模型 + record-replay** 确定性化）。

## 0. 判定方式说明

| 标记 | 含义 |
| --- | --- |
| **自动** | 设计上由验收脚本断言，给出 PASS/FAIL |
| **接口** | 当尚无脚本时，用 HTTP 请求 + 期望状态码/字段作证据 |
| **源码** | `文件:行号` + 源码特征（标注「仅源码检查」） |

> ⚠️ **验收脚本尚未落地**：本文件原引用的 `scripts/acceptance-p4.ps1` / `scripts/eval-p4.ps1` **在仓库中不存在**（`scripts/` 目录从未进入版本库）。下表是**待实现**的判定集合：`判定` 列标 **自动** 的条目在脚本落地前只能用 **接口/源码** 证据人工复核。**能变红的负控是先决条件，缺负控不得判 PASS。**

## 1. 功能验收（判定型）

| 编号 | 标准 | 判定 | 阈值 / 断言 | 证据 |
| --- | --- | --- | --- | --- |
| W1 | 能力健康 | 接口 / 自动 | `/api/workflow/health` 返回 `workflow=true` 且 `steps` 含 `agent`/`report` | 脚本输出 |
| W0 | 创建并流转 | 接口 / 自动 | `POST /api/workflow/runs` 返回 202；轮询终态 `succeeded` | 脚本输出 |
| S1 | 步骤定义与顺序 | 接口 / 自动 | 步骤按定义 `order_index` 执行；每步 `step_type` 与定义一致 | 脚本输出 |
| S2 | 步骤状态落库 | 接口 / 自动 | 每步有 `status/attempts/started_at/finished_at`；成功步产物摘要非空 | 脚本输出 |
| SR1 | 单步重跑 | 接口 / 自动 | `rerun` 后仅该步重算，**其后步骤全部 `stale`** 并重算；之前的步骤状态不变 | 脚本输出 |
| PV1 | 提示词版本化 | 接口 / 自动 | 版本可持久化/列出/设为 active；运行时固定 `prompt_version` 落库；切换版本后步骤使用新版本 | 脚本输出 |
| RT1 | 失败重试 | 自动（mock） | mock 令某步前 N-1 次失败 → 按 `maxAttempts` 重试至成功；`attempts` 与轨迹一致 | 脚本输出 |
| TO1 | 步骤超时 | 自动（mock） | mock 令步骤超时 → 该步 `failed`、run `failed`、`error` 非空、**不挂起** | 脚本输出 |
| CN1 | 取消 | 接口 / 自动 | `POST /cancel` → 当前步 `cancelled`、run `cancelled`，不挂起 | 脚本输出 |
| CP1 | 检查点 / 断点续跑 | 接口 / 自动 | 中断后 `POST /resume`：**已成功步骤不重算**，从首个非 `succeeded` 继续至 `succeeded` | 脚本输出 |
| PS1 | 进度完整 | 自动 | 每步至少一条进度事件；事件 `stepKey/status` 与最终步骤状态一致 | 脚本输出 |
| D1 | 删除级联 | 接口 / 自动 | 删文档后 `workflow_runs` / `workflow_steps` 全消失 | 脚本输出 |
| RR1 | 整跑幂等 | 接口 / 自动 | 重跑后终态 `succeeded`；步骤行数按 run 重建（不翻倍）；产物行数稳定 | 脚本输出 |

> 证据补充（源码）：`src/AgentWorkbench.Workflow/WorkflowService.cs`（运行生命周期）、`Execution/WorkflowStepExecutorNode.cs`（重试/超时/取消/放行）、`Steps/`（步骤类型）。

## 2. 度量验收

| 编号 | 标准 | 判定 | 阈值 | 证据 |
| --- | --- | --- | --- | --- |
| M1 | 步骤成功率 | 度量 | 正常样本步骤成功比例 **= 100%** | `eval-p4` 报告（**未实现**） |
| M2 | 断点恢复正确率 | 度量 | 恢复运行与整跑产物一致比例 **= 100%** | `eval-p4` 报告（**未实现**） |
| M3 | 单步重跑重算范围 | 度量 | 重跑步的下游失效率 **= 100%**，上游失效率 **= 0%** | `eval-p4` 报告（**未实现**） |
| M4 | 幂等稳定性 | 度量 | 重跑前后 `workflow_steps` / 产物行数 **不变** | `eval-p4` 报告（**未实现**） |

> 指标设计上均为**程序计算**（对照 `tests/benchmark/p4/golden/`，**未建**），不调用模型做判断。

## 3. 负控（红队）——必须存在，且必须“会失败”

| 编号 | 负控输入 | 判定 | 期望结果 | 源码证据 |
| --- | --- | --- | --- | --- |
| N1 | 非法 `runId` | 接口 / 自动 | `GET/POST /runs/{id}/*` 返回 `404` | `WorkflowController` |
| N2 | 文档不存在 / 未解析成功 | 接口 / 自动 | `POST /runs` 返回 `404`（缺失）/ `400`（未就绪） | `WorkflowController` |
| N3 | 未知 `stepKey` | 接口 / 自动 | `rerun` 返回 `404` | `WorkflowController` |
| N4 | 未知提示词版本 | 接口 / 自动 | `POST /runs`（带非法 version）返回 `400` | `WorkflowController` |
| N5 | 某步必然失败 | 自动（mock） | run 终态 `failed`、`error` 非空、**不挂起** | 脚本 |
| N6 | 重试耗尽 | 自动（mock） | 步骤 `attempts = maxAttempts` 后 `failed`，不再重试 | 脚本 |
| N7 | 同一 run 并发二次触发 | 自动 | 第二次被拒绝/幂等（同一 run 单执行），状态不脏 | 脚本 |
| N8 | 恢复时重复执行已完成步骤 | 接口 / 自动 | `resume` **不重算** 已 `succeeded` 步骤（`attempts` 不变） | 脚本 |
| N9 | 未配置模型时的 `agent` 步 | 接口 / 自动 | 该步明确失败/降级，run 有终态、`error` 非空，**不挂起** | 脚本 |
