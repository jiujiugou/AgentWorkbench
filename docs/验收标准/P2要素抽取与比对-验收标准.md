# P2 要素抽取与比对 · 验收标准（可执行版）

> 对应设计：`../设计步骤/P2要素抽取与比对.md`
> 判定原则：每条给出**可复核证据**（接口返回 / 脚本结果 / 截图），不靠感觉。
> 分工：**A 类自动断言（脚本，确定性，不做 LLM 判断）｜B 类人工抽样（人签字）｜负控必须存在**。

## 0. 判定方式说明

| 标记 | 含义 |
| --- | --- |
| **自动** | 由 `scripts/acceptance-p2.ps1` 断言，给 PASS/FAIL/SKIP |
| **半自动** | 脚本给出统计/预筛，人复核确认 |
| **人工** | 必须由人抽样判定并记录证据 |

> **确定性优先**：规则抽取/规则比对路径不依赖模型，断言必须确定性可复现；LLM 增强断言仅在配置模型时执行，否则记 **SKIP**（不阻断放行）。这与 P1「未配 Embedding 降级」一致。

## 1. 功能验收

| 编号 | 标准 | 判定 | 阈值 / 断言 | 证据 |
| --- | --- | --- | --- | --- |
| H1 | 审查能力健康 | **自动** | `/api/review/health` 返回 `capabilities.{extract,compare}` 均为 true | 脚本输出 |
| R0 | 创建并流转 | **自动** | `POST /api/review/runs` 返回 202 + `runId`；轮询终态 `succeeded` | 脚本输出 |
| E1 | 要素抽取（确定性） | **自动** | 对样例合同，要素含 `amount=128000`、`penalty_rate=10%`、`delivery_date=2026-05-01`、`warranty_months=12` 中 **≥3 项值准确** | 脚本输出 |
| E2 | 要素可溯源 | **自动** | 每条 `element` 的 `(chunkId,seq)` 指向该文档真实 `chunks`；有值时 `evidence` 非空 | 脚本输出 |
| C1 | 比对产生清单 | **自动** | 对「缺违约金条款 / 金额大小写不一致」构造样本，`findings` 命中预期规则 **≥1** 且 `severity` 正确 | 脚本输出 |
| C2 | 清单可溯源 | **自动** | 每条 `finding`（非全文级）的 `(chunkId,seq)` 有效或显式为 null | 脚本输出 |
| S1 | 结构化输出合法 | **自动** | `elements`/`findings` 能按 DTO 反序列化；字段 `key/label/value/severity/title` 完整；无解析错误 | 脚本输出 |
| D1 | 删除级联 | **自动** | 删除文档后，其 `review_runs/elements/findings` 全部消失 | 脚本输出 |
| RR1 | 重跑幂等 | **自动** | `POST /runs/{id}/rerun` 后终态 `succeeded`，且要素/清单按 run 重建（行数不翻倍） | 脚本输出 |
| L1 | LLM 增强抽取 | **半自动** | 配置模型后，`llmExtract=true`，`source=llm` 的要素出现 | 抽样记录（未配模型 SKIP） |

## 2. 质量验收

| 编号 | 标准 | 判定 | 阈值 | 证据 |
| --- | --- | --- | --- | --- |
| Q1 | 要素抽取准确率 | **人工** | 金标样本上关键字段 F1（人工抽检；P3 上 harness） | 抽样表 |
| Q2 | 证据可点击回原文并高亮 | **人工** | 要素/清单的「查看原文」跳 `文档详情 ?chunk=seq` 并高亮 | 截图 |
| Q3 | 清单质量 | **人工** | 抽样 **≥80%** 清单项结论合理、严重级恰当、证据对得上 | 抽样表 |
| Q4 | 工作流进度可见 | **人工** | 运行中可见分步进度；结果页展示每步状态 | 截图 |

## 3. 负控（红队）——必须存在，且必须“会失败”

| 编号 | 负控输入 | 判定 | 期望结果 |
| --- | --- | --- | --- |
| N1 | 无关文档（非合同 / 扫描件失败文档） | **自动** | 不产生编造的关键要素（`amount/penalty_rate` 为空或低置信），无「高严重级且无证据」清单 |
| N2 | 未配置模型且 `mode=llm` | **自动** | 创建/执行返回明确 4xx 或 run `failed` 且 `error` 非空，**不挂起** |
| N3 | 非法 `documentId` | **自动** | `POST /runs` 返回 `404` |
| N4 | 未解析/失败文档（`failed`） | **自动** | `POST /runs` 返回 `400`，不进入队列 |
| N5 | LLM 返回非 JSON（结构化解析失败，模拟） | **自动** | 该 LLM 步 `failed`、run `failed`；**不写脏数据**（elements/findings 无非法行） |

## 5. 自动化脚本

```powershell
# 默认：构建 → 清库 → 起服务 → 跑全部验收 → 停服务
powershell -ExecutionPolicy Bypass -File scripts/acceptance-p2.ps1

# 服务已在运行（不自动起停）
powershell -ExecutionPolicy Bypass -File scripts/acceptance-p2.ps1 -NoStart

# 指定地址
powershell -ExecutionPolicy Bypass -File scripts/acceptance-p2.ps1 -BaseUrl http://localhost:8080
```

- 断言：H1/R0/E1/E2/C1/C2/S1/D1/RR1 + N1/N2/N3/N4/N5。
- LLM 相关（L1 等）：未配模型时输出 `SKIP`，不阻断。
- 退出码：**确定性断言全过 0；有失败 1**（可用于 CI 门禁）。
- 输出：每个断言的 PASS/FAIL/SKIP 与明细。

## 7. 放行判定

- **自动**：H1/R0/E1/E2/C1/C2/S1/D1/RR1 + N1/N2/N3/N4/N5 全 PASS（L1 等 LLM 断言允许 SKIP）。
- **人工**：Q2 达标；Q1/Q3 抽样完成；Q4 有截图。
- 二者同时满足 → **P2 通过**。
- 未达标项记入问题清单，作为 P3（评测/权限/审计）输入。

## 8. 与总验收（指南里程碑）的对应

指南 P2 验收：「产出**要素表 + 不一致清单**」。对应本表：

- 要素表 → **E1/E2/S1/Q1**
- 不一致清单 → **C1/C2/S1/Q3**
- 可核对 → **Q2**；可观测 → **Q4**；不编造 → **N1/N5**
