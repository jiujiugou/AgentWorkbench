# 工业报警处置 · 检索效果评测（首轮基线）

- 脚本：`scripts/eval-industrial.py`
- 评测集：`tests/benchmark/industrial/eval-queries.json`（30 正例 + 5 负例）
- 语料：`tests/corpus/industrial/*.pdf`（32 份，由 `scripts/build-industrial-corpus.py` 生成）
- 报告：`tests/benchmark/industrial/report.json`
- 日期：2026-10-08

## 结论（先看这个）

| 指标 | 阈值 | 本次 | 结论 |
| --- | --- | --- | --- |
| Recall@5（RRF 融合） | ≥ 0.90 | 0.9000 | PASS |
| MRR（RRF 融合） | ≥ 0.70 | 0.7639 | PASS |
| **负控误命中率** | ≤ 0.20 | **1.0000** | **FAIL** |

**两个 PASS 是真的，但别拿去吹**：负控 5/5 全部误命中，说明系统对「语料没覆盖的问题」
照样返回 Top5 并自信作答。对工业场景这是安全缺陷，不是指标瑕疵。

## 三路对比（本轮核心产出）

| 检索方式 | Recall@5 | MRR |
| --- | --- | --- |
| 纯 FTS5（BM25 + LIKE 兜底） | 0.4667 | 0.3306 |
| 纯向量（bge-m3） | 0.9000 | 0.7639 |
| **RRF 融合** | 0.9000 | 0.7639 |

读法与口径：

- 三路分数来自 `RetrievalHit` 自带的 `textScore / vectorScore / fusedScore`，无需额外埋点。
- `vectorScore` 是**向量距离**（`HybridRetriever` 用 `<= MaxVectorDistance` 过滤），
  **越小越好**；`textScore` 是 `-bm25`，越大越好；`fusedScore` 是 RRF，越大越好。
  排序方向搞反会让纯向量列直接归零（首轮就踩了这个坑，已修）。
- 候选池取 `candidateK=20`（= `KnowledgeOptions.CandidateK`）再截 Top5，
  因此单路召回是被**低估**的：纯向量真实值可能 ≥ 0.90。

## 结论 1：向量是主力，全文是拖累

中文工业查询（"读上来的数值大得离谱"、"温度读出来是 8500，实际应该是 85 度"）
几乎不含手册里的原词，纯靠字面匹配必然失效；0.47 → 0.90 的差距全部由向量补齐。
**融合后的数字等于纯向量**，说明 RRF 在本语料上没有额外增益 —— 融合的价值要在
「字面命中强但语义弱」的语料上才看得出（例如设备型号、报警码这类精确词）。

所以面试时该说的话不是"我用了混合检索"，而是：
**"我量过：纯全文 0.47，纯向量 0.90，融合 0.90 —— 向量是主力，
融合的收益要在精确词场景才体现，所以我保留了融合而不是砍掉全文路。"**

## 结论 2：负控 5/5 全灭，检索没有相关性下限（未修）

负例（语料明确未覆盖的问题，如"空压机排气温度高报警的可能原因"）**全部返回 5 条命中**，
Top1 分别为 ADDR-006 / ADDR-003 / 点位表 / ADDR-006 / ADDR-001 —— 全是错的。

根因两条：

1. `KnowledgeOptions.MinFusedScore` 默认 **0.0**，配置里也是 0.0。
   该阈值只在 `RagService.StreamAnswerAsync`（`/api/knowledge/ask`）里判断一次，
   而 RRF 分数恒 > 0（本轮最小约 0.016），**拒答分支实际上永远不触发**。
2. `HybridRetriever.FtsSearchAsync` 的 LIKE 兜底对中文短词做 `%词%` 全表模糊匹配，
   几乎任何查询都能捞到东西，但没有相关性下限把噪声挡掉。

**建议修法（未做，属行为变更，需单独评审）**：给检索加相关性下限
（按 `fusedScore` 或向量距离卡阈值，低于阈值返回空），并把 `MinFusedScore` 配成实测值而非 0.0。
改之前先确认不会打翻 P1 的 N2（无源拒答）断言。

## 过程中的两个坑（已修，别再踩）

1. **评测集泄漏**：初版语料把 `fault-cases.json` 的 `query` 原文写进了 PDF（"典型提问：…"），
   而同一句话又是评测正例 → 逐字命中，Recall@5 恒为 **1.0**。
   这是假绿。已改为语料不写提问原文，重跑后降到 0.90 才是真数字。
2. **向量排序方向**：见上文口径，距离当相似度排会让纯向量列变 0。

## 已知限制

- 知识库里仍留着 9 份旧的法律/合同语料（P1/P2 验收要用，不能删），
  它们会给工业检索添噪声，本轮数字是**含噪声**的结果。
- 30 条正例的 query 与语料同源（都出自 `fault-cases.json`），
  属于"改写自同一素材"，不是完全独立的真实用户提问。
  `fault-cases.json` 的 `_trust` 字段已声明：报文 hex 是按规范构造的示例，
  **需在汇川 H5U 软 PLC 上实测后替换**，替换完成才是真实抓包数据。
- 纯向量列依赖 Ollama + bge-m3 在线；若 embedding 未运行，脚本会打 `[WARN]` 且该列不可信。

## 运行

```bash
# 需要先启动后端（默认 http://localhost:8080）与 Ollama（bge-m3）
python scripts/eval-industrial.py                 # 自动补传语料
python scripts/eval-industrial.py --skip-upload   # 语料已就位
```
