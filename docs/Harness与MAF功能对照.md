# Harness 与 MAF 功能对照

一句话：官方 Harness 是**一个预装齐全的 agent 对象**，本项目要的是**一个受控的编排服务**——同一个名字，不同的东西。所以这一格不是"选用"，是**用它的形，换它的芯**。

> 怎么读：一回答为什么是"用形换芯"；二是架构五件逐条；三是 13 项能力矩阵逐条；四说清两级指令那处容易误读的差别；五是放弃理由归类；六是「其余」的查阅接口——不展开，只给去哪查。
> 本文只做解释，不是事实源、不驱动门禁。Agents 底座的逐项对照见 [底座与 MAF 功能对照](底座与MAF功能对照.md)。

## 一、为什么是"用形换芯"

官方定义：*"代理工具是运行时基架，可将语言模型转换为可执行工作的代理……为研究、编码、数据分析和其他长时间运行的工作提供一个采用预设配置且开箱即用的工具套件。"*

**形**（可取）：官方说得很死——*"Harness 由现有的 Agent Framework 构建模块组合而成，而不是定义一个独立的代理运行时"*。这句话就是本项目 `AgentHarnessService` 的官方版本：用现成零件拼一个编排层，不造第二种运行时。

**芯**（必须换）：官方那句话的后半段——*"生成的对象仍然是正常的 Agent Framework 代理：`HarnessAgent` 派生自 `AIAgent`"*。官方的 harness 是**一个 agent 对象**，预装 planning、compaction、auto-approval、OTel；本项目的是一个**编排服务**，判定来自四道闸 + 外部审批人 + 审计五字段。同一个位置，相反的默认值。

所以你从来没"用"过官方 `HarnessAgent`，也没有 Disable 掉它的哪一项——你根本没装它。这是比"装了再逐个关"更彻底的关闭方式。

## 二、架构五件：逐条对照

| 官方件 | 官方作用 | 我们的取用 | 为什么 |
|---|---|---|---|
| 聊天客户端 | 把 agent 接到模型 | **取** | 模型解析层，别无选择 |
| 聊天管道：函数调用 / 消息注入 / 按服务调用历史持久化 / 可选压缩 | 每次模型调用前后的处理 | **只取函数调用** | 工具环挂在 `IChatClient` 层；消息注入不挂；按服务调用持久化明确不开——实测一次 run 结束时工具调用与结果已在历史里，开它收益为零；压缩撞①红线（见 [状态与记忆](core/状态与记忆.md)） |
| 代理和上下文提供程序：会话指令 / 工具 / 记忆 / 待办状态 / 操作模式 | 注入会话范围的状态与能力 | **整层不取** | 上下文提供程序在工具环之外注入，会拆掉守卫与轨迹；待办、模式、记忆注入都是"让 agent 更能干"，与方向相反 |
| 中间件和修饰器：审批处理 / 可观测性 / 可选有界循环 | 横切能力 | **取三个位置的语义** | 审批换成四道闸 fail-closed、可观测换成审计五字段账本、有界循环升格为独立的③终止与预算；实现都在 chat client 层，不在 agent middleware 层 |
| 应用 UX：流式 / 进度 / 收集审批输入 | 人机交互 | **取形态，换实现** | SignalR sink 负责推送与收审批，不依赖官方终端示例 |

## 三、13 项能力矩阵：逐条对照

> 更正：官方矩阵共 **13 行**。此前对话里说过 14 行，是把"函数调用"那一行的权威指南链接文本 `Function tools` 误算成独立一项。下表按官方页面原序。

| # | 官方能力 | 官方默认行为 | 我们的取用 | 为什么 |
|---|---|---|---|---|
| 1 | 函数调用 | 每个请求可配迭代次数上限 | **取形态** | 迭代上限来自③，循环本体是 MEA 的工具环；上限必须显式赋值，不靠框架默认 |
| 2 | 每次服务调用的历史记录持久化 | 每次模型调用后都持久化 | **不开** | 实测 run 结束时工具调用与结果已在历史里；开它只改变 `FunctionInvokingChatClient` 行为，收益为零、风险非零 |
| 3 | 压缩 | 给令牌限制或自定义策略时启用 | **拒绝** | 撞①红线（见 [状态与记忆](core/状态与记忆.md)）；代价是历史全量、无 token 上限 |
| 4 | 待办事项跟踪 | 默认启用 | **不用** | 任务规划不属于受控动作层，扩大副作用面 |
| 5 | 代理模式 | 计划/执行模式默认启用 | **不用** | 同上；模式切换会改变"模型看到什么"，轨迹无法重建 |
| 6 | 文件内存和文件访问 | 会话文件记忆默认启用，共享访问需手动开 | **不用** | 文件读写是新的副作用面，且要另管审批与审计；本项目的外部状态只在业务系统里 |
| 7 | 工具审批 | 永久审批 + 自动审批规则默认启用 | **换掉** | 官方默认自动放行；本项目四道闸 fail-closed，判定来自业务规则与外部审批人，不是 standing rules |
| 8 | OpenTelemetry | 默认启用 | **换掉** | span 回答"发生了什么"，审计五字段回答"谁 / 何时 / 看到什么 / 依据哪条规则 / 变成什么"；不是一回事 |
| 9 | Web 搜索 | 客户端支持时默认添加 | **不用** | 检索走 MCP 工具，调用留痕、可回放、可判分；不能由 harness 暗中做 |
| 10 | 智能体技能 | .NET / Go 默认启用 | **不用** | 技能是"更能干"的能力包，与方向相反 |
| 11 | 后台代理 | 可选并行委派子代理 | **不用** | 多代理委派会把身份链与审批链搅在一起，破坏"谁"的可答性 |
| 12 | Shell 执行 | 由命令行包组合 | **不用** | 与本格无关；本项目的外部动作一律过 `ActionGateway` |
| 13 | 循环 | 评估器/谓词驱动的可选有界重入 | **升格为③** | "跑满了"和"答完了"在账本上不能一样；官方把它当可选能力，本项目把它升成独立的终止与预算部件 |

**13 项的结果**：取形态 1 项、换掉 3 项、升格 1 项、不用 8 项。没有一项是原样启用的。

## 四、两级指令：一处必须说准的差别

C# 页明确写：`HarnessInstructions` 出现在 `ChatOptions.Instructions` **之前**——harness 级操作指南 + agent 级角色设定，两段都下发，这是官方设计。

本项目钉的是"指令只设一次；两级都设会拼接重复（实测 `A\nA`）"。两句不矛盾：

- 官方的**两级内容不同**（harness 的操作指南 vs agent 的角色指令），拼接是预期行为；
- 本项目撞的是**同一句指令被设了两次**（agent 级 + run 级），那才是重复。

所以"两级都设会重复"要限定为"同一内容设两次"，不能读成官方设计有 bug。本项目的取舍是：**不需要 harness 级操作指南**（那是"让 agent 更能干"的指令），只用 agent 级一条。

## 五、放弃理由归成三类

1. **方向相反**（待办 / 模式 / 文件 / 技能 / 后台 / web search / 压缩）：官方目标是"让 agent 更能干"，本项目是"让 agent 更受控"。扩大能力面 = 扩大副作用面。
2. **判定权外包**（auto-approval / OTel / 托管式能力）：它们都能"看起来安全"，但安全的依据不在我们手里——不是业务规则、不是外部审批人、不是可回放的五字段账本。
3. **会拆掉执行控制**（上下文提供程序层、agent middleware 层）：注入发生在工具环之外，守卫与轨迹都失效。这与 Agents 对照文档里的第一类理由同源。
