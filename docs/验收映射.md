# 六句 · 外部观察点

- **适用侧**：公共 ｜ **寿命**：现状 ｜ **最后校准**：2026-11-18

判定权在外部系统，不在这张纸里。这里只回答四件事：**查哪里、什么算过、什么算失败、现在有没有证据。**
外部不肯开口，就没有验过——六句里任何一句都不能用我们的绿灯顶替。

规格来自 `docs/产品目标与范围.md` §3，这里只做提取，不新写、不解释。

## 1. 真实 API 查状态

- **查哪里**：Gitea 上一条真实 issue / PR 的状态与时间戳（对方自己的 API 返回值）
- **算过**：状态码与时间戳是 Gitea 自己的；查不到时系统明确说查不到
- **算失败**：返回的是 mock、假件、或我们自己格式的时间串
- **现在**：无证据。默认 `ErpActionSet` → `FakeErp`，`Gitea:AllowWrites=false`；11-08 抓到的外部事实（PATCH 返 201、DELETE 204 无 body、RFC3339+Z）是探针记录，不是一次完整 run 的验收

## 2. 未审批零外部调用

- **查哪里**：对方系统的记录数 / 访问日志——不是我们自己的调用计数
- **算过**：未点同意时对方记录数不变；拒绝与超时过期都不执行
- **算失败**：审批没点，对方那边多了一条
- **现在**：无证据。M3 写动作默认未开始；pending 领取与恢复的缺口还挂着（S07 拒批后未 Resume）

## 3. 同 request_id 只有一条

- **查哪里**：Gitea 侧按业务键查到的记录条数
- **算过**：只有一条，第二次返回首次结果
- **算失败**：两条以上——11-08 实测 Gitea 完全忽略 `Idempotency-Key`，同 payload 连发三次得三张单
- **现在**：无证据。判定所需的 Gitea 侧读取口缺失（只验过我们自己说"没重放"，那不是对方的话）

## 4. 超时只查证不重放

- **查哪里**：超时之后，对方侧有没有第二次写
- **算过**：记「执行中」、发起状态查询、不重放；查不到转人工
- **算失败**：对方侧出现第二次写
- **现在**：无证据。超时归 Unknown 有单测，但"只查证不重放 + 按业务键查证"的外部闭环没跑过

## 5. 审计五字段

- **查哪里**：任取一笔执行，五字段（意图 / 参数 / 审批人 / 结果 / 外部单号）是否齐全，且"在对方系统里变成什么"能回 Gitea 核对
- **算过**：字段齐全，最后一项与对方记录一致
- **算失败**：缺字段，或"变成什么"对不上
- **现在**：部分。内核把字段交出去有测试；落库往返与外部核对没验。五字段的"做成什么"这项判定权在 Gitea

## 6. 换第二个体系，底座 diff 为空

- **查哪里**：`git diff src/Core/`，以及第二个体系自己的记录
- **算过**：第二体系跑通同一套运行时，底座 diff 为空，且对方一行没改
- **算失败**：底座出现业务名词 / 引用方向变了，或改了对方
- **现在**：无证据。没有第二载体，第六句一直是空的——它是"任何"这个词的唯一证据

---

**为什么这里只有六句**：结构层的判据就是 `dotnet test`，元层的判据就是变异器——它们自己会红，是可执行的东西，不需要一张纸复述。
把它们抄进文档，等于把活的判据做成死的陈列。这张纸只放没有现成执行器的那一层。
