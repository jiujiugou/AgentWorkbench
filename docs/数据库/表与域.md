# 表与域

**这份文件只放判断，不放结构。** 列、类型、索引、外键、行数在[表结构.md](表结构.md)，那个由脚本从库里生成。

## 域 ↔ 表

「域」对应[功能需求.md](../需求/功能需求.md) 的 F1–F6。

| 域 | 表 | 说明 |
|---|---|---|
| F1 身份与访问控制 | `tenants`、`users` | 归属源头 |
| F2 知识资料管理 | `documents`、`document_pages`、`chunks`、`chunks_fts`、`chunks_vec` | 知识的存储与检索通路 |
| **F3 知识问答** | **（无）** | 见下 |
| F4 Agent 执行与可审计 | `agent_runs`、`agent_steps` | 写侧 |
| F5 会话与执行记录 | `conversations`、`messages`、`agent_sessions`、`memory_items` | 读侧的载体 |
| F6 服务端能力 | `providers`、`provider_models`（平台配置）+ **接口属性本身无表** | 见下 |
| — | `workflow_definitions`、`workflow_runs`、`workflow_steps`、`prompt_versions` | 见下 |

## 三条需要写下来的判断

**① F3 是唯一没有自己表的域，这不是遗漏。** 它的产物分别落在 F2（检索证据）和 F5（答案正文）里，只有「引用」没有落点。不写这一句，按域读完会以为 F3 没做。

**② F6 半有半无。** 「接口属性」那一半（可只经 HTTP 完成、断连不丢任务）验收靠调接口，库里查不到；「平台配置」那一半是两张真实的表。混在一起说会让人以为 F6 没有数据结构。

**③ 四张编排表没有需求支撑。** `workflow_*` 三张加 `prompt_versions`，需求文档里没有任何一条 REQ 覆盖它们。按迁移号排的时候看不出来，按域排就变成了看得见的一句话。处置三选一：补需求 / 冻结 / 删除（未定）。
