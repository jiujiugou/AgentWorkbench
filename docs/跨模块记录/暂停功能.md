# 暂停功能（跨模块记录）
> 状态：未实现 ｜ 关联：缺口清单 P5-1 / P5-2、验收 B10 / B11 ｜ 2026-10-11
- 一句话：模型要调危险工具时先挂起等人批准，批了才执行、不批不执行；run 可暂停并恢复（暂停 ≠ 取消，取消是终态不可恢复）。
- 框架已有：MEA（10.10.0）的 `ApprovalRequiredAIFunction` + `ToolApprovalRequestContent` / `ToolApprovalResponseContent` 提供挂起与恢复协议；规则、状态、落库、入口要自己写。
- 责任划分：审批规则 → Safety（现只有全局白名单）；挂起点 → ToolExecution（现只有「拦住不执行」）；待批记录 + 终态 → Observability/Persistence + Shared（现无，需新表/新列 + `pending_approval`）；恢复入口 → AgentHarness（现 `RunAsync` 一问一答）；交互面 → Webapi（对话面走 Conversation / SignalR）；会话历史 → Memory（进程内，重启即丢）。
- 前置：会话持久化（P1-3）→ 工具级权限收敛（P5-2）→ 终态词表（已就位，加取值即可），顺序不能颠倒。
- 红线：未批准绝不允许真正执行；批复必须绑定到具体那一次调用（防伪造）；挂起期间审批耗时不计入 run 墙钟预算；终态不与 `failed` 混。
- 未决：暂停语义（冻结计时还是恢复重计时）、谁能批与如何防伪造、审批粒度（每次调用 / 每次 run 同类一次）、落库形态（新表 or `agent_steps` 加列）。
- 相关：`docs/底座建设清单.md`、`docs/adr/`（若引入 run 状态机则另开 ADR）、`docs/测试标准/Agent-测试与验收标准.md`。
