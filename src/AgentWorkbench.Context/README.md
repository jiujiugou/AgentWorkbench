# 上下文模块（Context）

这个模块只干一件事：**把检索命中的原文片段拼成一次模型调用前置的 user 文本**。纯逻辑、无 IO。

它不做检索（检索在 `Knowledge.Abstractions` 的实现方），不存历史（历史在 `Conversation` / `Memory` /
`Persistence`），不落库、不调模型。

---

## 一、现在已经具备的能力

### 拼什么、怎么拼

- `IContextBuilder.Compose(input, hits)`：没有命中就**原样返回 `input`**；有命中就在前面加一段
  `【知识库检索片段】仅供回答参考，需在结论中标注来源：`，每条一行
  `《文件名》片段#Seq (pX-Y) :: 摘要`，空行之后才是用户原文。
- 每条片段截 120 字符（`Snippet`）。
- 消费者只有一个：`AgentHarness.RunAsync`（`UseKnowledge=true` 且 `Harness:Context:Enabled=true` 时）。
  能力位 `HarnessCapabilities.Context` 跟着开关变。
- 配置节 `Harness:Context`：`Enabled=true`（做不做 RAG 注入）/ `RagTopK=5`（注入几条）。

### 接口

| 接口 | 成员 | 实现 | 消费者 |
| --- | --- | --- | --- |
| `IContextBuilder` | `Compose(input, hits)` | `ContextBuilder` | `AgentHarness.RunAsync` |

## 二、还没处理的问题（接下来要干的活）

分两类：**模块问题**在本模块纯逻辑范围内就能解决；**跨模块问题**必须有人配合才能做，表里写明依赖谁。
凡「必须在权限系统建立之后才能解决」的，统一记在 `docs/跨模块记录/记忆作用域与身份策略.md`
（**本模块当前没有这类问题**，见 §2.2 表末说明）。

### 2.1 模块问题（本模块内可解决）

| 问题 | 不处理的后果 | 现在什么状态 | 做好的标准 |
| --- | --- | --- | --- |
| 截断按字符不按 token | 中文和英文效果不一致，可能截在半句 | 120 字符硬截 | 至少按句边界截，不截在半句（精确 token 见 §2.2） |
| 裁剪 / 压缩的执行逻辑 | 就算给了预算也裁不对 | 没做 | 给定「材料 + 预算」能裁出结果；负控：预算调大必须不裁 |
| 没有裁剪类测试 | 一旦实现裁剪，没有红绿可依 | 只有 `ContextBuilderTests`（拼前缀 / 原样返回） | 裁剪正例 + 负控（预算调大必须不裁） |

### 2.2 跨模块问题（须别处配合）

| 问题 | 依赖谁 | 不处理的后果 | 现在什么状态 | 做好的标准 |
| --- | --- | --- | --- | --- |
| 历史消息裁剪 | 编排层把历史传进来（现在只收 `input` + `hits`） | 长会话把上下文窗口撑爆，请求直接失败或模型「忘了开头」 | 没做；历史由调用方全量传入 | 按 token 预算裁剪，并留下裁剪记录 |
| 历史压缩 / 摘要 | 摘要要调模型（本模块禁 IO）→ 只能由 `Conversation` / `ModelRuntime` 做，本模块收结果 | 长任务没有任何「整理上下文」的手段 | 没做 | 超预算时把旧轮次摘要成一段，保留最近 N 轮原文 |
| 检索片段与历史共用一份预算 | `ModelRuntime`（用量）+ 编排层（分配） | 命中条数一多照样超窗 | `RagTopK` 固定 5，没有 token 计数 | 历史 / 检索 / 输出统一分配预算 |
| 按 token 精确截断 | 需要一个 tokenizer 契约（模型侧） | 估算不准，中英不一致 | 120 字符硬截 | 按 token 截 |
| 拿不到用量 | `ModelRuntime` 暴露只读计量 | 判断不了「超没超」 | 用量计数在 `ModelRuntime`，本模块是纯逻辑 | 由编排层把预算决定下传，或引入只读计量契约 |
| 记忆片段与知识片段一起注入 | `AgentHarness` 召回（`Memory` 出结构化候选）→ 本模块组装 | 记忆只在模型主动调 `recall` 时生效 | 没做（阶段 3） | 注入正例：开召回则文本含记忆；负控：关召回则不含，且本模块仍不依赖 `Memory` |

> **以上六项都不需要在权限系统之后解决。** 它们依赖的是「编排层把材料与预算传进来」和
> 「`ModelRuntime` 暴露只读计量」，与「这是谁」无关。
>
> 两处与身份相邻，但耦合点都不在本模块：
> 1. 「会话历史必须按用户隔离」——本质是 `sessionId` 归属校验；
> 2. 「记忆片段注入」中按 user / global 作用域召回的那一半——耦合点在 `AgentHarness` 与 `Memory`。
>
> 两条均记在 `docs/跨模块记录/记忆作用域与身份策略.md`；本模块的组装逻辑不受影响。

## 三、加一种上下文来源要做什么

- 本模块是纯函数契约：新增来源 = 新增一个 Composer，或在编排层多拼一段再交给它。
- 判断标准：**只要不产生 IO，就可以放这里；一旦要查库 / 调模型，就属于别的模块。**

---

## 四、红线

1. **禁止 IO**。检索、读库、调模型都不在本模块。
2. **无命中必须原样返回**。`Compose` 的语义是「加前缀」，不是「改输入」。
3. **不新建第二个历史存储**。历史只有一个来源，本模块只看传进来的东西。
4. **片段只是参考**。注入的提示里已声明「需在结论中标注来源」，不得把片段当结论。

---

## 五、怎么算验收通过

判定型用例必须正例能绿、负控能红；能由脚本判定的禁止用 AI 判。

目前覆盖到的（`tests/AgentWorkbench.UnitTests/Context/ContextBuilderTests.cs`）：

- 有命中 → 片段被拼到原文之前，来源信息（文件名 / 页码 / 序号）齐全。
- 无命中 → 输出与输入逐字相同。

还没有的：裁剪 / 压缩的判定用例与负控 —— 能力本身没实现，先写负控再写功能。
